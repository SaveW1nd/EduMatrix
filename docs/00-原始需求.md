## 一、 产品概述与架构对照表

### 1.1 产品定位

面向教育机构、学校或企业（ToB）的强管控在线学习管理系统。支持 Web 端（PC/H5），架构上保持 API-First 规范，为后续扩展微信小程序或 App 预留标准接口。

| --- | --- | --- |
| **系统基座 & 权限控制** | **RuoYi-Vue-Plus** | 角色权限（RBAC）、多租户隔离、数据权限控制（老师仅看自己班级）、通用后台 API |

## 二、 用户角色与数据权限（RBAC）

系统必须实现严格的数据隔离与角色权限划分：

* **机构管理员（买单方）：** 拥有最高权限。可管理本机构的教师账号、排课计划、查看机构整体的完播率与学习大屏，无权查看其他机构数据。
* **教师 / 教务（执行方）：** 管理所属班级与学生。可布置作业、批改主观题、查看带班学生的视频观看进度和作业正确率。数据权限限制为"仅可查看/操作自己关联班级的数据"。
* **学生（被监管方）：** 接收学习任务。可观看指定课程视频、提交作业、查看个人错题本及学习档案。

## 三、 核心功能模块详细需求

### 模块 1：组织机构与教师管理

* **组织架构管理：** 支持按机构 -> 校区 -> 年级 -> 班级建立树状结构。
* **教师班级绑定：** 机构管理员将教师账号绑定至具体班级。系统后台通过数据权限掩码（DataScope）过滤数据。
* **学生导入与归档：** 支持通过 Excel 批量导入学生账号并绑定班级，支持学生转班、毕业归档。

### 模块 2：课程与视频学习追踪系统

* **课程结构编排：** 支持创建课程，构建"章 - 节 - 课时"结构。课时类型支持视频点播、图文资料。
* **视频转码与鉴权：** 视频上传至云端 VOD 后自动转码为加密 HLS（`.m3u8`）格式。前端播放时必须向后端请求带有时效性的播放凭证（PlayAuth/Key）。
* **前端播放防护：**
  * **禁用快进：** 播放器强制屏蔽进度条拖拽功能（仅允许向后拖拽重播已看部分）。
  * **跑马灯水印：** 播放器画面随机位置浮动学生"姓名 + 手机号"，防止手机录屏传播。
* **学习进度心跳上报：**
  * 播放器每隔 10 秒向后端发送一次心跳请求（带上当前播放时间戳 `currentTime` 和视频 ID）。
  * 后端校验心跳时间间隔合理性，更新数据库中该学生在该课时的"已看时长"和"完播状态（未开始/学习中/已完成）"。

### 模块 3：作业分发与题库系统

* **题库管理（版本防错乱）：**
  * 支持单选、多选、判断、填空、主观简答题及材料阅读题（一拖多）。
  * **底层约束：** 所有题目使用全局唯一物理 ID（雪花算法）。题库更新内容时触发版本号递增，不改变原题目 ID。
* **作业发布与布置：** 教师选择题库题目生成作业/试卷，指定完成截止时间，并一键分发给指定班级或指定学生。
* **自动判卷与主观题批改：** 客观题由系统实时自动比对答案判分；主观题进入教师批改流水线，教师可打分并填写评语。
* **动态错题本：** 学生做错的题目自动归档至个人错题本，错题本绑定题目物理 ID 与作答时刻的版本号，规避题库更新导致的错题内容错位。

### 模块 4：学习情况数据中心

* **教师端看板：** 直观展示班级视频平均完播率、作业按时提交率、高频错题排行榜。
* **学生个人学习档案：** 记录累计学习时长、各课程进度百分比、作业历史成绩曲线。
* **数据导出：** 支持将班级的学习进度和作业成绩导出为 Excel 报表，方便教务存档。

## 四、 关键技术规范与底层设计原则

* **API-First 接口规范：** 所有 Web 后端接口严格遵循 RESTful API 规范，返回标准 JSON 结构，避免在控制器层编写与视图强绑定的逻辑，确保后续开发微信小程序时可 100% 复用后端接口。
* **异步解耦与缓存：** 视频 10 秒心跳上报属于高频写请求，高并发场景下先写入 Redis 缓存或消息队列，再通过定时任务异步落盘至关系型数据库，防止主数据库锁死。
* **软删除与数据快照：** 涉及课程、题目、作业等核心业务数据，一律禁止物理删除（`DELETE`），统一使用逻辑删除标识（`is_deleted`），确保历史数据追踪链路完整。
