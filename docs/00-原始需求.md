## 一、产品概述

### 1.1 产品定位

面向教育机构、培训机构的**强管控在线学习管理平台**，采用**私域督学**模式：学员归属到具体导师名下，由导师直接负责其学习过程与效果。支持 Web 端（PC 管理端 + 学生 H5），架构上保持 API-First 规范，为后续扩展微信小程序或 App 预留标准接口。

与传统班级制 LMS 的本质区别：**教学组织的最小单元是"导师-学员"关系，而不是"班级"**。学员之间互不可见，每个学员只面对自己的导师、自己的课程与作业。

## 二、组织模型与角色

### 2.1 统一组织树

系统中的每一个人——平台超管、管理员、导师、学员——**全部是同一棵树上的节点**，从平台一路到学员，一棵树到底。**树上没有不绑账号的"空节点"**：每一个节点都对应一个具体的人。

```
平台超管
└─ 机构 A 最高管理员 王建国（= 一个租户，节点名可写作「机构 A」）
   ├─ 管理员 张三
   │  ├─ 导师 李四
   │  │  ├─ 学员 王五
   │  │  └─ 学员 赵六
   │  ├─ 导师 陈七
   │  └─ 学员 孙八        ← 挂在管理员下 = 已归属该管理员、尚未分配导师
   └─ 管理员 周九（节点名「华东片区」，周九即该片区负责人）
      └─ 导师 吴十
         └─ 学员 郑十一
```

**结构规则**：

1. 节点类型分四类：平台超管、管理员、导师、学员——**都是人**。
2. **学员与导师是多对一**：多个学员挂在同一个导师下，一个学员**有且仅有一个导师**（其树上的父节点）。
3. 导师节点下**只能挂学员**；学员是叶子节点，不能有子节点。
4. 管理员节点可以承载下级管理员、导师、学员，**层级不设上限**，机构可自由定义组织形态（校区、片区、学科组、任意分组）。**组织层级由管理员节点的嵌套表达**——要有"华东片区"这一层，就建一个管理员节点、节点名叫「华东片区」、由该片区负责人持有；层级与责任人是同一个东西，不拆成两个节点。
5. 学员创建时默认挂在创建它的管理员节点下，表示"已归属该管理员、尚未分配导师"；分配导师即把该学员节点移到导师节点下。
6. **树不允许成环**：任何节点移动都必须校验目标不是自身或自身的后代。

### 2.2 角色与权限

| 角色 | 职责 |
| --- | --- |
| **平台超管**（运营方） | 开通与管理机构（租户），平台级配置。跨机构 |
| **管理员**（机构方，可多级） | 建下级管理员、建导师、建学员、分配与转交学员、资源下发、全模块管理 |
| **导师**（执行方） | 备课组卷、给名下学员发课程与作业、批改、查看名下学员的学习数据 |
| **学员**（被督学方） | 观看指定课程、提交作业、查看个人错题本与学习档案 |

**数据权限只有一条规则**：

> **你能看到的数据 = 你所在节点的子树。**

全部角色适用同一条规则，不存在第二套过滤逻辑：管理员看到自己那一块（含下级管理员、导师、学员），导师看到自己名下学员，学员只看到自己。学员被移走后，原上级立即失去对其全部数据（含历史）的访问权。

**机构 = 租户**，机构之间硬隔离，跨机构访问一律按"不存在"处理。

## 三、核心功能需求

### 模块 1：组织树与人员管理

- **组织树管理**：节点的增删改查与移动，支持无限层级；移动节点时其整棵子树跟随（导师调岗则学员一起走）。
- **人员建档**：管理员可创建下级管理员、导师、学员。初始密码由创建者指定或系统随机生成，强制首次登录修改；**禁止使用可由账号推导的默认密码**（如手机号后 6 位）。
- **学员分配与转交**：分配导师、转交给其他管理员、导师调岗——统一为同一个动作"移动节点"，并记录异动轨迹。
- **学员导入**：Excel 批量导入学员账号并挂载到指定节点，失败行生成错误报告；同时支持单个添加。
- **学员标签**：给学员打标签（如"高三""数学薄弱"），用于筛选与批量操作；**标签不参与任何权限判断**。
- **退课与毕业归档**：学员状态分在读、已退课（流失）、毕业归档；归档后禁止登录，历史数据保留可查。

### 模块 2：资源授权与权限模板

受管资源为**课程、题目、视频**三类，每类资源有归属节点。

- **逐级下发，不向下继承**：上级拥有不等于下级自动拥有，每一层都必须显式授权。任一节点可用的资源 = 其上级显式授予它的那一份，天然逐级收缩。
- **两条硬约束**：只能授权自己拥有的资源；只能授权给自己子树内的节点。
- **精准到人**：导师最终把课程下发给自己名下的**特定学员**，而不是"一整批"。
- **有效期**：授权可设有效期，且下级的有效期不得超过上级——超出部分自动截断。
- **撤销级联**：撤销某节点的授权时，必须级联撤销该资源在其整棵子树内的全部授权；已产生的学习记录与答卷一律保留，仅失去继续访问权。
- **权限模板**：预置资源清单（如"高三数学包"），新建人员时一键套用以抵消逐级授权的操作成本；**套用时取交集**（模板 ∩ 授权人已有资源），绝不放大权限。

### 模块 3：课程与视频学习追踪

- **课程结构**：课程 → 章/节（两级）→ 课时，课时类型支持视频点播与图文资料。
- **视频转码与鉴权**：视频上传至云端 VOD 后自动转码为加密 HLS（`.m3u8`）；前端播放必须向后端请求带时效的播放凭证。
- **播放防护**：
  - **禁用快进**：进度条只允许拖回已看过的位置，不得向前跳转。
  - **跑马灯水印**：画面随机位置浮动学员姓名与手机号，防手机录屏传播。
- **学习进度心跳**：播放器每 10 秒上报一次当前播放位置；服务端校验间隔合理性后累计"已看时长"，并判定完播状态（未开始/学习中/已完成）。
- **防刷**：服务端必须校验心跳间隔、位置推进与墙钟的一致性、单人同时活跃课时数、单日累计时长上限，异常心跳只留痕不计时。

### 模块 4：作业分发与题库

- **题库**：支持单选、多选、判断、填空、主观简答及材料阅读题（一拖多）。
- **版本防错乱**：题目使用全局唯一物理 ID（雪花算法），内容更新触发版本号递增而**不改变题目 ID**；作业在发布时固化题目版本，此后题库更新不影响已发布作业。
- **作业发布**：导师选题生成作业/试卷，指定截止时间，**分发精确到学员个人**（可从名下全体、按标签、按节点批量选择，但最终落到人）。
- **判卷与批改**：客观题实时自动判分；主观题进入导师批改流水线，可打分与写评语。
- **动态错题本**：做错的题自动归档到学员个人错题本，绑定题目物理 ID 与**做错时刻的版本号**，规避题库更新导致的错题内容错位。

### 模块 5：数据中心

- **导师看板**：名下学员的平均完播率、作业按时提交率、高频错题排行。
- **机构/节点大屏**：谁登录就以谁的节点为根，展示其子树的整体数据、下级节点对比、导师排行。
- **学员学习档案**：累计学习时长、各课程进度、作业历史成绩曲线、错题掌握情况。
- **数据导出**：学习进度与作业成绩可导出 Excel 报表。
- **归属口径**：学员转导师后，**历史数据归原导师**（以自然日为结算单位），转移当日归新导师；新导师查看学员档案时可看到其完整历史，但导师业绩只统计自己名下期间。

## 四、关键技术规范

- **API-First**：所有后端接口遵循 RESTful 规范，返回标准 JSON 结构，控制器层不写与视图强绑定的逻辑，确保后续开发微信小程序时可 100% 复用。
- **异步解耦与缓存**：视频心跳属高频写请求，先写 Redis 缓存，再由定时任务批量落盘至数据库，防止主库锁死。
- **软删除与数据快照**：课程、题目、作业、答卷等核心业务数据禁止物理删除，统一使用逻辑删除标识，确保历史追溯链路完整。
- **归属快照**：涉及归属的统计与答卷数据必须记录发生时刻的归属快照，已结算的历史数据永不重算。

## 五、边界与约束

1. **学员与导师是多对一**：一个学员同一时间只有一个导师。若业务出现"一个学员跟多位导师"（如分科目授课），当前模型无法表达，需引入独立的师生关系表并重新设计数据权限。
2. **学员之间互不可见**：学生端不提供同学名单、群体平均、排行榜等任何展示他人数据的功能。
3. **未分配导师的学员**：不计入任何导师看板，但计入其所在节点的整体统计。
4. **组织形态由机构自定义**：系统不预设"校区/年级/班级"等固定层级，机构可用管理员节点的嵌套自由组织（层级名即节点名，节点持有人即该层级负责人）；跨导师、跨节点的横切属性（年级、科目、能力层级）应使用标签而非节点。
