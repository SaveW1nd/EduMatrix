## 0. 角色与数据权限模型（对齐契约 §2.3 / §2.4 / 第 3 节）

### 0.1 四个角色（全系统穷举，不再有第五个）

| 角色 | role_key | user_type | 绑定节点类型（`org_node.node_type`） | 可执行的关键操作 |
| --- | --- | --- | --- | --- |
| 平台超管 | `super_admin` | 0 | 平台（树根） | 租户开通、平台配置 |
| 管理员 | `org_admin` | 1 | 1 管理员 | 建下级管理员、建教师、建学生、分配学员、资源下发、全模块管理 |
| 教师 / 导师 | `teacher` | 2 | 2 教师 | 备课、组卷、给名下学员发课程与作业、批改、看名下看板 |
| 学生 | `student` | 3 | 3 学生 | 学习、作答、看本人档案 |

> **机构管理员与下级管理员是同一个角色**（同为 `org_admin`、`user_type=1`），差别**仅在其绑定节点在组织树中的位置**——机构管理员挂在机构根节点、下级管理员挂在其子树某处，因而可见范围不同。系统**不存在**独立的"节点管理员""校区管理员"角色，本分册所有接口的"允许角色"一律只出现上述四个 role_key。

### 0.2 数据权限：全系统只有一条规则

> **你能看到的数据 = 你所在节点（`sys_user.node_id`）的子树。**

```sql
-- 统一过滤条件（org_node 别名 n，当前用户所在节点 #{myNodeId}）
n.id = #{myNodeId} OR FIND_IN_SET(#{myNodeId}, n.ancestors) <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
```

- **数据范围由树决定，操作权限由角色决定**。角色上**没有** `dataScope` 字段——同一个 `org_admin` 角色挂在机构根节点即"全机构"，挂在某校区节点即"该校区子树"，无需第二个字段表达。
- 租户隔离（`tenant_id`）与子树权限是**两道独立防线**：跨租户一律 HTTP 404，子树外的写操作返回 403、单条读返回 404。
- 本分册中若某接口写"数据权限：仅本租户"，指的是租户插件的自动过滤（平台级/机构级配置类接口，如租户配置、日志），与子树规则并列而非替代。

## 1. 认证（/api/v1/auth）

### 1.1 获取图形验证码

- **方法+路径**：`GET /api/v1/auth/captcha`
- **权限**：无需认证（白名单）。同一 IP 60 秒内最多 20 次（超限返回 HTTP 429）。

**请求参数**：无

**请求示例**：

```
GET /api/v1/auth/captcha
```

**响应示例**：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "captchaKey": "cap:9f8e7d6c5b4a3f2e1d0c",
    "captchaImage": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA...",
    "expireSeconds": 300
  }
}
```

**响应字段说明**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| captchaKey | string | 验证码唯一标识（Redis key），登录时原样带回 |
| captchaImage | string | Base64 图片（Data URI），前端直接作为 `<img src>` |
| expireSeconds | int | 有效期 300 秒，过期后需重新获取 |

**相关业务错误码**：无（仅可能触发 HTTP 429）

---

### 1.2 登录

- **方法+路径**：`POST /api/v1/auth/login`
- **权限**：无需认证（白名单）。四类角色（super_admin / org_admin / teacher / student）共用本接口，服务端按账号自动识别 `userType`。租户已停用或到期时该租户全员（平台超管除外）登录被拒。

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| username | string | 是 | 用户名，4~30 位 |
| password | string | 是 | 明文密码（HTTPS 传输，服务端 BCrypt 比对），8~20 位 |
| captchaKey | string | 是 | 验证码标识，来自 1.1 接口 |
| captchaCode | string | 是 | 用户输入的验证码，4 位，不区分大小写 |

**请求示例**：

```json
POST /api/v1/auth/login
{
  "username": "t_zhangwei",
  "password": "Zw@20260812",
  "captchaKey": "cap:9f8e7d6c5b4a3f2e1d0c",
  "captchaCode": "8kt6"
}
```

**响应示例**：

```json
{
  "code": 200,
  "msg": "登录成功",
  "data": {
    "tokenType": "Bearer",
    "accessToken": "eyJhbGciOiJIUzI1NiJ9.eyJsb2dpbklkIjoiMTk1MDAwMDAwMDAwMDAwMDEwMiJ9.access",
    "expiresIn": 7200,
    "refreshToken": "eyJhbGciOiJIUzI1NiJ9.eyJsb2dpbklkIjoiMTk1MDAwMDAwMDAwMDAwMDEwMiJ9.refresh",
    "refreshExpiresIn": 604800,
    "userId": "1950000000000000102",
    "userType": 2,
    "needChangePassword": false
  }
}
```

**响应字段说明**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| tokenType | string | 固定 `Bearer` |
| accessToken | string | 访问令牌，有效期 2 小时 |
| expiresIn | int | accessToken 剩余有效秒数（7200） |
| refreshToken | string | 刷新令牌，有效期 7 天，一次性使用 |
| refreshExpiresIn | int | refreshToken 剩余有效秒数（604800） |
| userId | string | 用户 ID |
| userType | int | 0 平台超管 1 管理员 2 教师 3 学生（契约第 5 节枚举；机构管理员与下级管理员同为 1） |
| needChangePassword | boolean | 是否须强制修改密码：账号仍为系统生成/导入默认的初始密码、或被管理员重置密码后为 `true`。为 `true` 时前端强制跳转修改密码页（1.6），未改密前不得进入其他页面（PRD F1-1 / F1-4 验收） |

**相关业务错误码**：

| code | 说明 |
| --- | --- |
| 10003 | 用户名或密码错误 |
| 10004 | 验证码错误或已过期 |
| 10005 | 账号已停用或已锁定（`sys_user.status=1` 账号级封禁，仅超管可置；或连续 5 次密码错误锁定 15 分钟，对齐 PRD 7.3） |
| 10007 | 租户已停用或服务已到期 |
| 10015 | 账号已归档，禁止登录（学生学籍 `org_student.status=2` 毕业归档，见 03-02 §6.9） |
| 10017 | 账号已被停用或其上级已停用（**组织侧停用**，`org_node.status=1`）：①本人所在节点被停用，或②祖先链中有被停用的管理员（分支冻结）。与 `10005` 是两个不同的原因——`10005` 是账号级封禁（超管做的风控），`10017` 是组织侧冻结（机构管理员做的），前端提示语与自助路径不同 |

### 1.3 刷新令牌

- **方法+路径**：`POST /api/v1/auth/refresh`
- **权限**：无需 accessToken（白名单），凭有效 refreshToken 调用。

**请求参数**：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| refreshToken | string | 是 | 登录或上次刷新时下发的刷新令牌 |

**请求示例**：

```json
POST /api/v1/auth/refresh
{
  "refreshToken": "eyJhbGciOiJIUzI1NiJ9.eyJsb2dpbklkIjoiMTk1MDAwMDAwMDAwMDAwMDEwMiJ9.refresh"
}
```

**响应示例**（refreshToken 旋转：旧令牌立即失效，下发新令牌）：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "tokenType": "Bearer",
    "accessToken": "eyJhbGciOiJIUzI1NiJ9.eyJsb2dpbklkIjoiMTk1MDAwMDAwMDAwMDAwMDEwMiJ9.access2",
    "expiresIn": 7200,
    "refreshToken": "eyJhbGciOiJIUzI1NiJ9.eyJsb2dpbklkIjoiMTk1MDAwMDAwMDAwMDAwMDEwMiJ9.refresh2",
    "refreshExpiresIn": 604800
  }
}
```

**相关业务错误码**：

| code | 说明 |
| --- | --- |
| 10006 | refreshToken 无效或已过期（含已被旋转作废、登出作废），需重新登录 |
| 10005 | 账号已停用（停用后禁止续签） |
| 10007 | 租户已停用或服务已到期 |
| 10017 | 所在节点或其上级已停用（组织侧冻结，禁止续签） |

### 1.4 登出

- **方法+路径**：`POST /api/v1/auth/logout`
- **权限**：所有已登录角色（super_admin / org_admin / teacher / student）。

**请求参数**：无（凭请求头 `Authorization: Bearer {accessToken}` 识别会话）

**请求示例**：

```
POST /api/v1/auth/logout
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

**响应示例**（当前会话 accessToken 与 refreshToken 同时作废；对已失效 Token 调用同样返回成功）：

```json
{
  "code": 200,
  "msg": "登出成功",
  "data": null
}
```

**相关业务错误码**：无

### 1.5 获取当前用户信息

- **方法+路径**：`GET /api/v1/auth/me`
- **权限**：所有已登录角色。仅返回当前登录人自身信息（数据范围天然为本人）。响应中的 `nodeId` 是前端与后端共同的**数据权限锚点**——所有列表接口的可见范围即以该节点为根的子树（§0.2）。
- **`roles` / `perms` 的加载链路必须放行平台级行（契约 §2.9）**：本接口经 `sys_user_role → sys_role → sys_role_menu` 取权限，而四个内置角色及其菜单绑定的 `tenant_id = 0`。这两张表的租户插件注入条件必须是 `(tenant_id = ? OR tenant_id = 0)`；若按普通等式过滤，**非超管用户一律返回 `roles: []` / `perms: []`**，前端全部按钮隐藏、后端全部权限校验 403，系统开箱即不可用。这是一个**不报错的故障**——接口返回 200、字段齐全，只是数组为空，很容易被误判为"角色没配好"。

**请求参数**：无

**请求示例**：

```
GET /api/v1/auth/me
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

**响应示例**（以教师张伟为例）：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "userId": "1950000000000000102",
    "username": "t_zhangwei",
    "realName": "张伟",
```

**响应字段说明**：

| 字段 | 类型 | 说明 |
| --- | --- | --- |

| status | int | 0 正常 1 停用 |

**相关业务错误码**：无（Token 失效返回 HTTP 401）

### 1.6 修改密码（本人）

- **方法+路径**：`PUT /api/v1/auth/password`
- **权限**：所有已登录角色（super_admin / org_admin / teacher / student），仅作用于当前登录账号本人。`needChangePassword=true`（初始密码 / 被管理员重置后未改密）的账号，除本接口及 1.4 登出、1.5 获取本人信息外，访问其他业务接口一律返回 403（对齐 PRD F1-1 / F1-4 验收：未改密不可访问其他页面）。

**请求参数**（Body）：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| oldPassword | string | 是 | 原密码（明文，HTTPS 传输，服务端 BCrypt 比对） |
| newPassword | string | 是 | 新密码，8~20 位且同时含字母与数字（PRD 7.3 弱密码策略），不得与原密码相同 |

**请求示例**：

```json
PUT /api/v1/auth/password
{
  "oldPassword": "OldPwd@2026",
  "newPassword": "Zw@20260812"
}
```

**响应示例**（改密成功后：`needChangePassword` 置为 `false`；**除当前会话外**，该账号其余在线会话的 accessToken 与 refreshToken 全部作废，需用新密码重新登录，对齐 PRD 7.3「改密即时失效对应 Token」）：

```json
{
  "code": 200,
  "msg": "密码修改成功",
  "data": null
}
```

**相关业务错误码**：

| code | 说明 |
| --- | --- |
| 10014 | 原密码错误 |

（newPassword 格式不合规或与原密码相同返回 400）

## 2. 用户管理（/api/v1/system/users）

> 用户表为 `sys_user`（管理员/教师/学生统一账号体系）。
>
> **本组的写接口（2.2~2.6）一律仅 `super_admin` 可调，用途限定为平台级账号维护**（超管自身账号、跨租户排障时的账号处置）。**机构侧人员的建、改、删、重置密码、启停用一律走 02-组织机构分册的 `/api/v1/org/**`**。只有 2.1 分页查询保留 `org_admin`，供平台与机构两侧共用一个只读账号视图。
>
> **为什么必须收敛成一条路径**（两处分裂各自会造成什么）：
> - **建人**：本组的创建只写 `sys_user` + `org_node` + `org_node_change_log`，**不写 `org_teacher` / `org_student` 档案**。经这条路径建出的教师，在 `/org/teachers` 列表里查不到、无工号无科目，正是 PRD F1-3 规则 1 明令禁止的孤儿数据（"有节点无档案"）。而 `/org/**` 的建人接口是三写一事务，任一失败整体回滚。
> - **删人**：本组的删除置 `sys_user.deleted_at`（业务键随之释放，同名用户名可再建）；02 分册的删除只置 `sys_user.status=1`（账号保留、用户名仍被占用）。同一个"删除"动作走不同入口，**用户名是否释放的结果不同**，对账时无法解释。
> - **停用**：契约 §2.3 规定 `org_node.status` 是停用的**唯一权威**，`sys_user.status` 仅用于与组织无关的账号级封禁。本组的启停用属于后者，因此收归超管做安全风控；机构侧的停用走 02 分册接口 5（节点停用 / 启用）。
>
> 教师档案、学生档案及批量导入同样见 02-组织机构分册。
>
> **每个非平台账号都对应组织树上的一个节点**：`sys_user.node_id` 指向 `org_node.id`，`org_node.ref_user_id` 反向指向本账号，二者 1:1。因此：
> - 创建账号时必须指定挂载的父节点 `parentNodeId`，服务端在同一事务内创建 `org_node`（**`node_type` 与 `userType` 取值恒等**，不做任何映射：1 管理员、2 教师、3 学生）并回写 `sys_user.node_id`；
> - **`node_id` 一经创建不可经本组接口修改**。变更所在节点 = 移动树节点（分配导师、转交管理员、教师调岗），一律走 02-组织机构分册的节点移动接口，以保证与子树 `ancestors` 重算同事务、同行锁（00-通用约定 §7.4）。

## 3. 角色管理（/api/v1/system/roles）

> 角色表 `sys_role`。系统预置四个角色（super_admin / org_admin / teacher / student，对齐契约第 3 节），这四行 `tenant_id = 0`、**为全平台所有租户共用同一行**；租户可在此基础上新建自定义角色（如"教务主任"）。
>
> **预置角色对 `org_admin` 全只读**（3.4 / 3.5 / 3.6 一律 `400`），只有 `super_admin` 可改、且任何人不可删。契约 §2.9 把这两张表的租户过滤放宽为 `(tenant_id = ? OR tenant_id = 0)`，是为了让租户用户**读得到**自己的权限定义（否则全员零权限、系统开箱不可用）——**放宽的只是读**。写侧必须反向收紧，否则一个租户的管理员改一次预置角色，全平台跟着变。
>
> **角色只定义操作权限（能调哪些接口、看到哪些按钮），不定义数据范围。**
> **数据范围由用户所在节点（`sys_user.node_id`）的子树决定，不在角色上配置**——`sys_role` 按契约第 3 节不设 `data_scope` 字段，本组接口的请求参数、响应体与示例中均不出现 `dataScope`。同一个 `org_admin` 角色挂在机构根节点即"全机构"，挂在某校区节点即"该校区子树"，无需第二个字段表达。
>
> 因此，给某人扩大或收缩可见范围的正确做法是**移动其节点**（02-组织机构分册），而不是改角色。

## 5. 租户管理（/api/v1/system/tenants）

> **平台超管（super_admin）专用**，其余角色（含 org_admin）调用一律返回 403。租户即机构（`sys_tenant`），`tenant_id` 即本表 `id`。本组接口为平台级操作，不做租户注入。
>
> **租户 = 组织树上超管的一个直接子节点**（契约 §2.1）：每个 `sys_tenant` 持有 `root_node_id` 指向该机构在 `org_node` 中的根节点（`node_type=1`，`parent_id=0`，`ancestors="0"`），机构以下所有节点继承同一 `tenant_id`。
>
> **机构根节点就是机构最高管理员本人**——树上每个节点都是一个人（契约 §2.3），`ref_user_id` 恒非空，因此不存在"机构节点 + 挂在它下面的初始管理员节点"这种两层结构，二者是同一行。开通租户因此是**三步同事务**：建租户行（`root_node_id` 暂空）→ 建机构最高管理员的账号与节点 → 回写 `root_node_id`（见 5.3）。

### 5.0 租户与组织树根节点的对应关系

```
org_node 树根 (id=0，平台超管节点)
└── 王建国（机构最高管理员）   node_type=1  id=1951000000000000001  ← sys_tenant.root_node_id
    │                          节点名可写作「启明星教育集团」；该节点 id 即整棵子树的 tenant_id
    │                          ref_user_id → 王建国的 sys_user.id，其 node_id 反向指回本节点
    ├── 李强（北京校区负责人）  node_type=1   节点名「北京校区」
    │   └── 张伟（教师）        node_type=2
    │       └── 李小明（学生）  node_type=3
    └── 赵敏（上海校区负责人）  node_type=1   节点名「上海校区」
```

> 「北京校区」不是一个独立的空节点，而是**李强这个管理员节点的名字**——组织层级与该层级的负责人是同一个东西。

- `sys_tenant.root_node_id` 与 `org_node.id` 一一对应，创建后**不可变更**；删除/停用租户不改动该指向。
- 机构根节点由系统在开通时自动创建，**不可经 02-组织机构分册的节点接口删除或移动**（它是租户边界本身，移动它等同于跨租户搬迁，本期不支持）；其关联账号亦不可删除，只能停用整个租户。

### 5.3 创建租户（开通机构）

- **方法+路径**：`POST /api/v1/system/tenants`
- **权限**：仅 `super_admin`（权限标识 `system:tenant:add`）。
- **同一事务内的三步联动（缺一不可，任一步失败整体回滚）**：

  | 步骤 | 写入 | 说明 |
  | --- | --- | --- |
  | ① 建租户 | `sys_tenant` | 生成 `id`，即该机构全部数据的 `tenant_id`；`root_node_id` 暂为 NULL（解循环依赖，契约 §2.1） |
  | ② 建**机构最高管理员**（账号 + 节点，同一个人） | `sys_user` + `org_node` + `sys_user_role` | 账号：`user_type=1`、绑定预置 `org_admin` 角色。节点：`node_type=1`、`parent_id=0`、`ancestors="0"`、`node_name` 默认取机构名称、`ref_user_id` 指向该账号；节点 `id` 即步骤①的租户 `id`。建成后回填 `sys_user.node_id`，二者互为反向引用。同时记录 `org_node_change_log`（`change_type=1` 建档）×1 |
  | ③ 回写 | `sys_tenant.root_node_id` | 指向步骤②的节点 |

  **该节点既是机构根节点，也是初始管理员本人**——不再另建一层"机构节点"，因为树上不存在不绑账号的节点（契约 §2.3）。其子树 = 整个机构，天然拥有全机构数据范围——**无需也没有任何"数据范围"字段参与**（§0.2）。后续新建的下级管理员挂在更深的位置，可见范围自动收缩。
- 初始管理员密码**由系统随机生成**（12 位，含大小写字母与数字），不由超管指定，仅在本接口响应的 `initialPassword` 字段**一次性返回**（对齐 PRD F1-1 规则 5「初始密码系统生成并强制首次登录修改」及关键交互「保存后弹出初始管理员账号密码（仅展示一次）」）；该管理员首次登录时 `needChangePassword=true`，经 1.6 强制改密后方可使用其他功能。

**请求参数**（Body）：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| name | string | 是 | 机构名称，最长 50 字，全局唯一（同时作为机构根节点的 `node_name`） |
| contactName | string | 是 | 联系人姓名 |
| contactPhone | string | 是 | 联系电话，11 位 |

| adminRealName | string | 是 | 初始机构管理员姓名，最长 30 字（同时作为其节点的 `node_name`） |
| remark | string | 否 | 备注 |

> 无 `rootNodeId` / `parentNodeId` 参数：机构根节点由系统创建并固定挂在平台树根（`parent_id=0`），不由调用方指定。

### 7.2 查询文件详情

- **方法+路径**：`GET /api/v1/system/files/{id}`
- **权限**：
  - 允许角色：`super_admin`、`org_admin`、`teacher`、`student`（权限标识 `system:file:query`）
  - 数据权限：仅可查询本租户文件，跨租户返回 404。
  - **归属校验（与 7.3 下载接口完全一致，不得放宽）**：`import_excel` / `fail_report` / `credential_sheet` 仅导入任务创建人及 `org_admin` 可查；`export_report` 仅导出任务申请人可查；`answer` 仅该作答附件所属答卷的学生本人、作业创建人（叠加子树校验）及 `org_admin` 可查。不通过一律返回 `404`（不暴露存在性）。
  - **本接口只返回元数据，`fileUrl` 恒为 `null`**：取文件一律走 7.3 下载接口换取时效签名地址。若此处直接下发可访问的直链，7.3 的归属校验将被完全绕过——雪花 ID 在同租户内时间相邻、可近邻枚举，等于把学生名单（含手机号、监护人手机号）与成绩报表向全租户敞开。

**请求参数**（路径参数）：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | 是 | 文件 ID |

**请求示例**：

```
GET /api/v1/system/files/1953827104412590090
```

**响应示例**：

```json

  "data": {
    "fileId": "1953827104412590090",
```

### 7.3 下载文件

- **方法+路径**：`GET /api/v1/system/files/{id}/download`
- **权限**：
  - 允许角色：`super_admin`、`org_admin`、`teacher`、`student`（权限标识 `system:file:download`）
  - 数据权限：仅本租户文件，跨租户返回 404（不暴露存在性）。按 `bizType` 附加归属校验：`import_excel` / `fail_report` / `credential_sheet` 仅导入任务创建人及 org_admin 可下载（`credential_sheet` 含明文初始密码，保留 7 天后物理清理）（供 02-组织机构 §7.3（接口 30）导入失败报告下载）；`export_report` 仅导出任务申请人可下载（供 05-数据中心 §4.8 报表下载）；其余 bizType 本租户已登录用户可下载。

**请求参数**（路径参数）：

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string | 是 | 文件 ID（如导入任务的 `failReportFileId`、导出任务的 `fileId`） |

**请求示例**：

```
GET /api/v1/system/files/1953827104412590090/download
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

**响应**（成功时为二进制流 / 重定向，不使用通用 JSON 结构）：

- `storage=1`（本地）：直接返回文件流，响应头示例：

```
Content-Type: application/octet-stream
Content-Disposition: attachment; filename*=UTF-8''%E5%AD%A6%E7%94%9F%E5%90%8D%E5%8D%95.xlsx
Content-Length: 24576
```

- `storage=2`（OSS）：返回 `302` 重定向至带签名的临时地址（有效期 30 分钟，与 05-数据中心 §4.8 `downloadUrl` 口径一致），客户端跟随跳转下载。

**失败响应**（JSON 通用结构）：文件不存在、已逻辑删除（含导出报表超 7 天保留期被清理，PRD F4-4 规则 3）、跨租户、归属校验不通过，均返回 HTTP 404；导出任务侧的「文件已过期清理」提示由 `40008` 承担（4xxxx 段，登记于 00-通用约定 §9.5，归 03-05 分册使用）。

**相关业务错误码**：无（本段 1xxxx 无新增）
