# EduMatrix API 文档 00 —— 通用约定

> 本文档为 EduMatrix 全部 API 接口文档（01~05）的通用约定，所有接口文档均以本文档为前置基准。
> 命名、枚举、错误码段位以 `docs/DESIGN-CONTRACT.md`（设计契约）为唯一权威，本文档为其在 API 层的展开说明。

---

## 1. 基础信息

| 项目 | 约定 |
| --- | --- |
| Base Path | `/api/v1` |
| 传输协议 | 生产环境强制 HTTPS |
| 请求体格式 | `Content-Type: application/json;charset=UTF-8`（文件上传接口除外，使用 `multipart/form-data`） |
| 响应体格式 | `application/json;charset=UTF-8` |
| 字符编码 | UTF-8 |
| 接口风格 | RESTful，API-First，Web / H5 / 后续小程序 100% 复用同一套接口 |

### 1.1 请求方法约定

| 方法 | 语义 | 说明 |
| --- | --- | --- |
| GET | 查询 | 无副作用，可任意重试 |
| POST | 创建 / 动作提交 | 创建资源、登录、上报、提交答卷等 |
| PUT | 修改 / 状态变更 | 全量或指定字段修改，如 `/status`、`/renew` |
| DELETE | 逻辑删除 | **后端统一将 `deleted_at` 由 0 置为当前毫秒时间戳，禁止物理删除**（对齐契约 2.2 / 6.1）。日志、心跳明细等表允许归档清理，属运维行为，不经由 API |

### 1.2 多租户约定

- 机构 = 租户。除 `sys_menu` 等平台级数据外，所有业务接口由 MyBatis-Plus 租户插件自动注入 `tenant_id` 过滤条件，客户端**无需也不允许**在业务参数中传递租户 ID（平台超管的租户管理接口除外）。
- **平台级行的读取例外**：`sys_role` / `sys_role_menu` 的注入条件为 `(tenant_id = ? OR tenant_id = 0)`，因内置角色与其菜单绑定的 `tenant_id = 0` 是全租户共用定义；按等式过滤会让 `/auth/me` 返回空 `roles`/`perms`，进而所有权限校验 403。完整表清单与逐表定案见契约 §2.9。
- **跨租户访问一律返回 HTTP 404**（不暴露资源存在性，对齐契约 2.1）。客户端收到 404 时按"资源不存在"处理即可。

## 2. 认证方式

### 2.1 Token 机制

采用 Sa-Token（JWT 风格）双 Token 机制：

| Token | 有效期 | 用途 |
| --- | --- | --- |
| `accessToken` | **2 小时** | 业务接口访问凭证，随每次请求携带 |
| `refreshToken` | **7 天** | 仅用于调用 `POST /api/v1/auth/refresh` 换取新的 accessToken，**不得**用于访问业务接口 |

携带方式（请求头）：

```
Authorization: Bearer {accessToken}
```

### 2.2 Token 生命周期规则

1. 登录成功（`POST /api/v1/auth/login`）同时下发 `accessToken` 与 `refreshToken`。
2. `accessToken` 过期后业务接口返回 HTTP 401，客户端应调用 `POST /api/v1/auth/refresh` 换取新 Token。
3. **refreshToken 旋转**：每次刷新成功都会下发**新的** refreshToken，旧 refreshToken 立即失效（一次性使用，防重放）。
4. `refreshToken` 过期或失效时，刷新接口返回业务错误码 `10006`，客户端应清除本地 Token 并引导用户重新登录。
5. 登出（`POST /api/v1/auth/logout`）后，该用户当前会话的 accessToken 与 refreshToken 同时作废。
6. 账号被停用、租户被停用或租户到期时，已下发 Token 在服务端校验环节被拦截（返回 401 或对应业务错误码）。

### 2.3 认证白名单（无需 Token）

| 接口 | 说明 |
| --- | --- |
| `POST /api/v1/auth/login` | 登录 |
| `GET /api/v1/auth/captcha` | 获取图形验证码 |
| `POST /api/v1/auth/refresh` | 刷新令牌（凭 refreshToken） |
| `GET /api/v1/vod/decrypt-key` | HLS 解密密钥分发（03-课程与视频接口 29 获取解密密钥）。**调用方是 hls.js 播放器内核，它不会携带任何自定义请求头**，身份完全来自 URL 上的 `MtsHlsUriToken`（8.1 发放、绑 studentId+lessonId、TTL ≤ 300s）。**免登录不等于免鉴权**——本接口必须跑与 8.1 逐条相同的 `org_resource_grant` 校验链，它才是加密视频真正的鉴权闸口 |

其余全部接口必须携带有效 `accessToken`。

### 2.4 权限模型（对齐契约第 3 节）

| 角色 | role_key | user_type | 绑定节点类型 | 可执行的关键操作 |
| --- | --- | --- | --- | --- |
| 平台超管 | `super_admin` | 0 | 平台（树根） | 租户开通、平台配置 |
| 管理员 | `org_admin` | 1 | 管理员节点（机构根节点即机构最高管理员） | 建下级管理员、建教师、建学生、分配学员、资源下发、全模块管理 |
| 教师 / 导师 | `teacher` | 2 | 教师节点 | 备课、组卷、给名下学员发课程与作业、批改、看名下看板 |
| 学生 | `student` | 3 | 学生节点 | 学习、作答、看本人档案 |

> 机构管理员与下级管理员**角色相同**（同为 `org_admin`），差别仅在其绑定节点在树中的位置。

**数据权限：全系统只有一条规则（对齐契约 §2.4）**

> **你能看到的数据 = 你所在节点的子树。**

```sql
-- 统一过滤条件（org_node 别名 n，当前用户所在节点 #{myNodeId}）
n.id = #{myNodeId} OR FIND_IN_SET(#{myNodeId}, n.ancestors) <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
```

| 角色 | 实际可见范围 |
| --- | --- |
| 平台超管 | 全平台（跨租户） |
| 管理员（任意层级） | 其子树全部：下级管理员、教师、学生 |
| 教师 | 其子树 = 名下学员（教师的直接子节点即其学员） |
| 学生 | 仅自身（学生是叶子，无子节点） |

- 不存在第二套数据权限逻辑。标签、角色、资源授权**均不得扩大可见范围**。
- 学员被移出某节点后，原上级**立即失去**对其全部数据（含历史明细）的访问权。
- **数据范围由树决定，操作权限由角色决定**：父节点决定子节点"能看到哪些数据"，不决定"能执行哪些操作"。

**资源可用范围（独立于数据权限，对齐契约 §2.5）**：课程/题目/视频的可用性由 `org_resource_grant` **逐级显式授权**决定，**不向下继承**。判定只需一条命中（`target_node_id = 我的节点`），不回溯祖先链。

功能权限（能不能调该接口）由角色-菜单按钮权限标识（`perms`，如 `system:user:list`）控制；数据权限（能看到哪些行）在 SQL 层自动过滤。

**越界响应三分法（全系统统一，对齐契约 §2.4，各分册不得另立规则）**：

| 场景 | 返回 | 理由 |
| --- | --- | --- |
| 访问**路径上的资源**（`GET/PUT/DELETE /xxx/{id}`）而该资源不在我的子树内 | **404** | 不暴露存在性，与跨租户一致 |
| 无该功能的操作权限（角色/菜单权限不足） | **403** | 与数据无关，是功能级拒绝 |
| **请求体/查询参数中显式指定的目标**越界（`targetParentId`、`targetNodeIds`、`studentIds`、`nodeId` 等） | **`10107`**（业务码，HTTP 200） | 用户主动选了越界对象，需明确提示"请重新选择"，而非静默 404 |

> 判别口径：**"我要操作的东西"越界 → 404；"我选的目标"越界 → 10107；"我没资格做这件事" → 403。**

## 3. 通用响应结构

所有接口统一返回以下结构（对齐契约 6.1）：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| code | int | 状态码。`200` 成功；`400/401/403/404/500` 框架层错误；`1xxxx~4xxxx` 业务错误（见第 9 节错误码总表） |
| msg | string | 提示信息，可直接用于前端 Toast 展示 |
| data | object / array / null | 业务数据。无返回数据时为 `null`；分页时固定为 `{"total": ..., "list": [...]}`，允许附加**可选**的 `summary` 对象承载与筛选条件相关的聚合信息（如批改进度，见 03-04 §5.1），除 total/list/summary 外不得再有其他同级字段 |

### 3.1 成功示例

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "id": "1953827104412590081",
    "createTime": "2026-08-12 10:30:00"
  }
}
```

### 3.2 失败示例

```json
{
  "code": 10003,
  "msg": "用户名或密码错误",
  "data": null
}
```

### 3.3 HTTP 状态码与响应体 code 的关系

- 框架层错误（未登录 401、无权限 403、参数校验 400、资源不存在/跨租户 404、服务异常 500 等）：HTTP 状态码与响应体 `code` **一致**。
- 业务错误（`1xxxx` ~ `4xxxx`）：HTTP 状态码统一返回 **200**，以响应体 `code` 判定业务结果。

## 4. 分页约定

### 4.1 分页请求参数（Query 传递）

| 参数 | 类型 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- | --- |
| pageNum | int | 否 | 1 | 页码，从 1 开始 |
| pageSize | int | 否 | 10 | 每页条数，**最大 100**，超出按 100 处理 |

### 4.2 分页响应结构

分页接口的 `data` 固定为：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "total": 138,
    "list": [
      { "id": "1953827104412590081" },
      { "id": "1953827104412590082" }
    ]
  }
}
```

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| total | long | 符合条件的总记录数 |
| list | array | 当前页数据列表，无数据时为 `[]`（total 为 0，不返回 null） |

### 4.3 通用查询习惯

- 时间范围查询统一使用 `beginTime` / `endTime`（含边界，格式见第 6 节）。
- 字符串条件默认模糊匹配（如 `username`、`realName`），枚举/ID 条件精确匹配。
- 排序由服务端固定（一般按 `create_time DESC` 或 `sort ASC`），本期不开放自定义排序参数。

## 5. ID 字符串化

- 主键统一为**雪花算法 bigint**（Java 侧生成，非自增）。
- JavaScript `Number` 安全整数上限为 2^53-1，雪花 ID（19 位）会溢出丢精度。因此：
  - **所有响应中的 bigint ID 一律序列化为字符串**，如 `"id": "1953827104412590081"`；
  - **所有请求中的 ID 参数一律以字符串传递**（路径参数、Query、Body 均同）；
  - ID 数组同理：`"menuIds": ["1949000000000000001", "1949000000000000002"]`。
- 前端严禁对 ID 做数值运算或 `parseInt`。

## 6. 时间与时区

| 项目 | 约定 |
| --- | --- |
| 时区 | 统一东八区（`Asia/Shanghai`，UTC+8），服务器、数据库、接口三层一致 |
| 日期时间格式 | `yyyy-MM-dd HH:mm:ss`，如 `2026-08-12 10:30:00`（请求与响应一致） |
| 纯日期格式 | `yyyy-MM-dd`，如 `2026-08-12`（如 `statDate`、`entryDate`） |

## 7. 幂等与重试约定

### 7.1 按方法的幂等性

| 方法 | 幂等性 | 说明 |
| --- | --- | --- |
| GET | 天然幂等 | 可任意重试 |
| PUT | 幂等 | 重复提交同一修改结果一致，可安全重试 |
| DELETE | 幂等 | 对已逻辑删除的资源重复 DELETE 返回 `code=200`（不报错） |
| POST | **非幂等** | 需按 7.2 防重 |

### 7.2 POST 创建类接口防重

- 客户端应做按钮防抖 / 提交中置灰。
- 服务端支持可选请求头 `X-Request-Id`（客户端生成 UUID）：同一用户携带相同 `X-Request-Id` 的 POST 请求在 **5 分钟**内重复到达时，服务端直接返回首次处理结果（Redis key：`idem:{userId}:{requestId}`），不重复执行。
- 对创建类接口（创建用户、创建作业、上传文件等）建议一律携带 `X-Request-Id`。

### 7.3 业务层天然防重（无需 X-Request-Id）

| 场景 | 防重机制 |
| --- | --- |
| 心跳上报 `POST /api/v1/vod/heartbeat` | 服务端间隔合理性校验：间隔 ≥8s 有效、单次计入 min(实际间隔,15)s；间隔 <8s 或参数非法的心跳丢弃并返回 `20002`（对齐契约 6.4 / PRD F2-7），重复/伪造上报不会多计时长 |
| 答卷提交 | `hw_answer_sheet` 唯一约束 `UK(homework_id, student_id)`，重复提交返回 `30003` |
| 资源授权 | `org_resource_grant` 唯一约束 `UK(resource_type, resource_id, target_node_id)`，重复授权返回 `10303`（批量授权整批回滚） |
| 学生 Excel 导入 | 以导入任务（`org_import_task`）为单位异步执行，重复上传生成新任务，不叠加写入 |

### 7.4 文件与导出的安全基线（全局强制）

| 项 | 要求 |
| --- | --- |
| **对象存储桶权限** | 一律**私有**。任何文件访问都必须经服务端换取**时效签名 URL**（有效期 ≤30 分钟），禁止下发长期有效的公开直链。文件域名与业务域名分离 |
| **归属校验的唯一入口** | 文件的 bizType 归属校验只在下载接口（03-01 §7.3）实现一次；**任何其他接口不得返回可直接访问的文件地址**，否则该校验被绕过 |
| **上传类型校验** | 扩展名 + 请求 `Content-Type` + **文件头魔数**三重校验，以魔数为准且必须与扩展名一致；服务端强制重命名为 `{fileId}.{规范扩展名}`；下载统一 `Content-Disposition: attachment` + `X-Content-Type-Options: nosniff`。SVG 不在白名单内 |
| **Excel 写出防公式注入** | 生成任何 `.xlsx`（失败报告、成绩报表、进度报表、账号密码表）时，字符串单元格若以 `=` `+` `-` `@` `Tab` `CR` 开头，**必须前置单引号或显式设为文本格式**。<br>不做此处理时：导入的"姓名"列填入 `=cmd 加管道符的公式`，会被原样写回失败报告，管理员打开并启用编辑即在其终端执行；且该值一旦入库，之后每一份含姓名的导出报表都会携带它，受害面从单人扩散到全部导出者 |
| **Excel 导入字符白名单** | 姓名、学号、节点名等文本字段拒绝以 `= + - @` 开头的值，并限制为中英文、数字与有限标点 |
| **敏感文件保留期** | 导入源文件、失败报告、导出报表一律保留 **7 天**后由定时任务物理清理（与 03-05 §4.6 导出口径一致） |

### 7.5 组织树结构操作的并发约束（对齐契约 §2.3 / 铁律 1）

节点移动（`org_node.parent_id` 变更，含分配导师、转交管理员、教师调岗等所有"改父"语义的接口）不是普通的字段更新，服务端必须满足以下约束：

| 约束 | 说明 |
| --- | --- |
| **同一事务** | 「更新 `parent_id`」与「递归重算整棵子树（含被移动节点自身）的 `ancestors`」必须在**同一个数据库事务**内完成。任一步失败整体回滚，禁止分两次提交——否则会留下 `ancestors` 与 `parent_id` 不一致的脏树，且 `FIND_IN_SET` 子树查询会静默返回错误的数据范围（等同数据权限失效）。 | <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
| **行锁防并发** | 事务内须先对**被移动节点及其目标父节点**加行锁（`SELECT ... FOR UPDATE`），再做成环校验与写入。并发移动同一子树内的不同节点若不加锁，两个事务各自基于旧 `ancestors` 重算，会产生环或断链，造成树结构损坏且不可自愈。 |
| **校验在锁内** | 成环校验（`targetParentId != movingNodeId AND FIND_IN_SET(movingNodeId, targetParent.ancestors) = 0`）与父子类型合法性校验必须在持锁后执行，避免"校验通过—落库前树已变化"的 TOCTOU 窗口。校验失败返回 `10103` / `10104`。 | <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
| **非幂等重试** | 移动接口对客户端**不可自动重试**：超时后节点可能已移动成功，盲目重试会把节点再移到另一位置。客户端应改为重新拉取节点详情确认当前 `parentId`。 |

> 移动接口一律记录 `org_node_change_log`（异动轨迹），该写入同样在上述事务内。

### 7.6 客户端重试策略建议

- 仅对**幂等请求**（GET/PUT/DELETE）在网络超时、HTTP 500 时自动重试：指数退避 1s → 2s → 4s，最多 3 次。
- HTTP 429（触发限流）：读取响应头 `Retry-After`（秒）后再重试，不做即时重试。
- 业务错误码（`1xxxx~4xxxx`）属于确定性失败，**禁止自动重试**，应提示用户。

## 8. 限流约定

| 场景 | 限制 | 超限响应 |
| --- | --- | --- |
| 登录 `POST /auth/login` | 同一 IP 60 秒内最多 10 次 | HTTP 429 |
| 验证码 `GET /auth/captcha` | 同一 IP 60 秒内最多 20 次 | HTTP 429 |
| 同一账号连续密码错误 | 连续 5 次错误锁定 15 分钟（对齐 PRD 7.3 安全条款） | `10005`（msg 提示锁定剩余时间） |
| 心跳上报 | 单学生单课时理论频率 1 次/10s，间隔 <8s 的异常高频上报丢弃 | `20002` |

## 9. 错误码总表

> 段位划分对齐契约 6.3。**新增错误码必须先在本表登记再在分册文档中使用**；本表与各分册模块错误码表**逐码一致**，同一 code 全局仅允许一个语义。各段位内未列出的号段为预留（1xxxx 基础段预留 10010、10018~10099，组织机构段预留 10309~10399，2xxxx 预留 20007、20011~20012、20021~20099，3xxxx 预留 30018~30099，4xxxx 预留 40009~40099）。

### 9.1 HTTP / 框架层
