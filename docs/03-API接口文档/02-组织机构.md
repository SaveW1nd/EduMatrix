## 2. 模块通用说明

### 2.1 涉及数据表

| 表名 | 用途 |
| --- | --- |
| `org_node` | 统一组织树（平台超管 / 管理员 / 教师 / 学生，每个节点都是一个人） |
| `org_teacher` | 教师档案（与节点 1:1） |
| `org_student` | 学生档案（与节点 1:1，含学籍状态、退课、归档字段） |
| `org_node_change_log` | 节点异动轨迹（分配导师 / 转交管理员 / 教师调岗 / 退课 / 归档 / 恢复） |
| `org_resource_grant` | 资源逐级下发授权（课程 / 题目 / 视频 → 目标节点） |
| `org_perm_template` / `org_perm_template_item` | 权限模板与模板资源明细 |
| `org_tag` / `org_student_tag` | 标签定义与学生-标签关联 |
| `org_import_task` | Excel 导入任务 |
| `sys_user`（基座） | 管理员 / 教师 / 学生的统一登录账号，含 `node_id` 指向其所在节点 |
| `sys_file`（基座） | 导入源文件与失败报告文件 |

### 2.2 统一组织树与结构约束（对齐契约 §2.3）

系统中的每一个人**都是同一棵树上的节点**，从平台根一路到学生，一棵树到底。**`node_type` 与 `sys_user.user_type` 取值完全一致**（契约 §5）。

| node_type | 节点类型 | 可承载的子节点 | 说明 |
| --- | --- | --- | --- |
| 0 | 平台超管 | 仅管理员 | 全树唯一一行（`id=0`），平台根 |
| 1 | 管理员 | 管理员、教师、学生 | 可无限嵌套；**组织层级由管理员节点的嵌套表达** |
| 2 | 教师 | **仅学生** | 导师节点；其直接子节点即"名下学员" |
| 3 | 学生 | **不可有子节点** | 叶子 |

> **每个节点都是一个人**：不存在"校区/年级/部门"这类不绑账号的空节点，`ref_user_id` **全部非空**。需要表达组织层级时建一个管理员节点即可——把 `nodeName` 命名为"华东校区"、`refUserId` 指向该片区负责人，这个节点既是组织层级也是责任人。因此**本模块没有独立的"新建节点"接口**，建节点 = 建人，一律走接口 8（新建下级管理员）/ 12（新建教师）/ 17（创建学生），以保证 `sys_user` 账号与档案表同事务落地。

**服务端强制校验的结构约束（违反即拒绝）**：

1. 教师节点下只能挂学生 → 违反返回 `10105`；学生节点不可有任何子节点 → 违反返回 `10106`；其余非法组合返回 `10104`。
2. **树不允许成环**：移动节点时目标父节点不得是自身或自身的任何后代，判定 `toParentId != movingNodeId AND FIND_IN_SET(movingNodeId, targetParent.ancestors) = 0` → 违反返回 `10103`。 <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
3. `org_node.ancestors` 冗余祖级路径（逗号串，含根哨兵 `0`，不含本节点，如 `0,1960000000000000001,1960000000000000002`），子树查询用 `FIND_IN_SET(#{nodeId}, ancestors)` 单条件命中。 <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
4. **移动节点后必须递归重算整棵子树的 `ancestors`**（含被移动节点自身），与移动本身在同一事务内完成。
5. 树深度**上限 50 级**（`ancestors` 为 `VARCHAR(1000)`，20 字符/级），建/移节点时服务层校验，超限返回 `400`；同一父节点下 `node_name` 唯一（重复返回 `10102`）。

**节点 ID 与业务 ID 的对应关系（各接口 `{id}` 语义）**：

| 对象 | 路径 `{id}` 取值 | 说明 |
| --- | --- | --- |
| 节点（接口 1~5、41） | `org_node.id` | — |
| 管理员（接口 8~10） | `org_node.id`（管理员节点 ID） | 管理员无独立档案表，节点 + `sys_user` 即全部 |
| 教师（接口 13~15） | `org_teacher.id`（教师档案 ID） | 响应中同时返回 `nodeId` / `userId` |
| 学生（接口 18~26） | `org_student.id`（学生档案 ID） | 响应中同时返回 `nodeId` / `userId` |

### 2.3 权限总览（角色 + 数据权限）

**操作权限由角色决定，数据范围由树决定**，两者互不替代（契约 §2.4 / 第 3 节）。

| 角色 | role_key | user_type | 在本模块的能力 |
| --- | --- | --- | --- |
| 平台超管 | `super_admin` | 0 | 只读巡检（可跨租户查询组织树与节点详情），**不参与租户内组织写操作与资源授权** |
| 管理员 | `org_admin` | 1 | 本模块几乎全部接口：改名/移动/停用节点、建下级管理员与教师与学生（建节点即建人）、删人、分配与转交学员、退课归档、标签、导入、资源授权、权限模板 |
| 教师 / 导师 | `teacher` | 2 | 名下学员的查询与维护（16 学生分页列表 / 18 修改学生 / 26 学生异动轨迹 / 36 按标签批量选人）、名下学员列表（15）、学生退课申请（23）、打/去标签（34/35）、对**名下学员**下发自己已拥有的资源（37~41）、使用可见模板（42~44 只读、50 套用，目标限名下学员）；**不可**建教师/管理员、不可移动教师节点、不可删除任何人、**不可**调用 22 转交管理员与 45~49 模板写接口 |
| 学生 | `student` | 3 | 仅可查询本人的异动轨迹（26） |

**数据权限：全系统只有一条规则（契约 §2.4，铁律 2）**

> **你能看到、能操作的数据 = 你所在节点的子树。**

```sql
-- 统一过滤条件（org_node 别名 n，当前用户所在节点 #{myNodeId}）
n.id = #{myNodeId} OR FIND_IN_SET(#{myNodeId}, n.ancestors) <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
```

本模块所有接口的"数据权限"一栏统一按此规则表述，具体含义为：

- **读接口**：结果集自动追加上述子树条件，不在子树内的行不返回；按 ID 精确查询不在子树内的对象返回 `404`（不暴露存在性）。
- **写接口**（按契约 §2.4 越界响应三分法，全系统统一）：
  - **路径 `{id}` 上的操作对象**越界 → `404`（不暴露存在性，与读接口一致）
  - **请求体/查询参数中显式指定的目标**（`toParentId`、`targetNodeIds`、`studentIds`、`nodeId` 等）越界 → `10107`（用户主动选了越界对象，需提示重新选择）
  - 功能权限不足（角色/菜单）→ `403`
- **跨租户**：一律返回 `404`（契约 §2.1）。
- 学员被移出某节点后，原上级**立即失去**对其全部数据（含历史明细）的访问权。
- 标签、角色、资源授权**均不得扩大可见范围**。

### 2.4 资源逐级下发与权限模板要点（对齐契约 §2.5，铁律 3）

1. **只能授权自己拥有的资源**：授权人是资源的 `owner_node_id`，或该资源已显式授权给授权人所在节点且在有效期内。否则 `10301`。
2. **只能授权给自己子树内的节点**：禁止横向授权与向上授权。否则 `10302`。
3. **不向下继承，每一层都必须显式授权**。上级拥有 ≠ 下级自动拥有；机构管理员 → 下级管理员 → 教师 → 学生，每一级都要显式授权，天然逐级收缩。
4. **判定不回溯祖先链**：某节点能否使用某资源，只看 `org_resource_grant` 是否存在 `target_node_id = 该节点 AND resource_id = X AND 在有效期内` 的一行。
5. **撤销必须级联子树**：撤销对某节点的资源授权时，**级联撤销该资源在目标节点整个子树内的全部授权**；已产生的学习记录（`vod_watch_progress`、`hw_answer_sheet`、`hw_wrong_book`）**一律保留不删**，仅失去继续访问权（详见接口 39）。**撤销课程授权不影响已分发的作业**（契约 §2.5 规则 10：作业是已下达的任务，不是资源）——学员仍可作答、教师仍可批改、成绩仍计入统计。
6. **模板取交集，绝不放大权限**：套用模板时，实际授权 = 模板资源清单 **∩ 授权人当前拥有的资源**；被跳过的部分在响应 `skippedResources` 中逐条列出；交集为空时返回 `10306`（详见接口 50）。

### 2.5 标签的定位（重要边界，不得误用）

> **`org_tag` / `org_student_tag` 仅用于筛选与批量操作，不参与任何权限判断。**

- 标签**不扩大也不缩小**任何人的数据可见范围——可见范围永远只由 2.3 的子树规则决定。
- 标签**不构成资源可用性依据**——资源可用性永远只由 `org_resource_grant` 的显式授权决定。
- 按标签选人（接口 36）的结果**已先经过子树过滤**：同一个标签，不同管理员查到的学员集合不同，各自只看到自己子树内的部分。
- 按标签批量授权 / 批量分发时，标签只承担"选出这批人"的作用，`grant_source=3`（按标签批量）仅是来源标记，逐条授权仍走 2.4 的全部校验。

## 3. 组织树管理

### 3.1 组织树查询

- **接口名**：组织树查询
- **方法与路径**：`GET /api/v1/org/nodes/tree`
- **权限**：`org_admin`、`teacher`、`super_admin`
- **数据权限**：以当前用户所在节点为默认树根，只返回**其子树**；传入 `rootId` 时该节点必须在子树内，否则返回 `10107`。教师调用时树根即其教师节点，返回的子树就是名下学员列表。
- **说明**：**默认懒加载**——不传 `parentId` 时只返回调用者所在节点的**直接子节点**；前端展开某节点时再带 `parentId` 拉下一层（命中 `idx_tenant_parent_sort`，单层毫秒级）。
  传 `deep=true` 可一次性取整棵子树，此时**必须同时传 `maxDepth` 或 `nodeTypes`**，且服务端硬上限 2000 个节点，超出返回 `400` 要求收窄条件。
  **超管调用时禁止以平台根为起点**：必须显式指定某个租户的根节点，否则会一次性返回全平台所有租户的节点（100 机构约 110 万行）。
  设计原因：机构根管理员的子树 = 全机构（单租户约 1.1 万节点），一次性返回的响应体约 5~8 MB，而这是管理端登录后的第一个请求。`nodeTypes` 用于筛选展示层级，例如只画到教师层（`nodeTypes=1,2`，即管理员+教师、不含学生）用于选择授权目标。筛选时若某节点被排除，其子节点一并不返回（保持树的连通性）。

**请求参数（Query）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| rootId | string | 否 | 树根节点 ID，默认当前用户所在节点 |
| nodeTypes | string | 否 | 节点类型过滤，逗号分隔，取值 `1` 管理员 `2` 教师 `3` 学生（`0` 平台超管仅超管自身可见）；不传返回全部类型 |
| includeDisabled | boolean | 否 | 是否包含 `status=1` 已停用节点，默认 `false` |
| maxDepth | int | 否 | 相对树根的最大返回深度，`0` 或不传表示不限 |
| keyword | string | 否 | 节点名称模糊匹配；命中节点及其**全部祖先链**一并返回，未命中分支不返回 |

**请求示例**

```
GET /api/v1/org/nodes/tree?nodeTypes=1,2&includeDisabled=false
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

### 3.4 移动节点

- **接口名**：移动节点
- **方法与路径**：`PUT /api/v1/org/nodes/{id}/move`
- **权限**：仅 `org_admin`
- **数据权限**：**被移动节点与目标父节点都必须在当前用户子树内**，且被移动节点不得是当前用户自己所在节点、不得是租户根节点（`parent_id=0`），任一不满足返回 `10107`。这条约束保证了"不能把自己或上级搬走"，也保证了跨子树搬运（把别人的节点搬到自己这边）被拒绝。
- **说明**：本接口是**唯一**改变树形结构的入口，学员分配导师（接口 20）、转交管理员（接口 22）、教师带学员整体调岗都是本接口逻辑的语义化封装。

  **校验顺序（任一失败即整体拒绝，不落任何数据）**：

  | 序 | 校验项 | 失败错误码 |
  | --- | --- | --- |
  | 1 | 被移动节点、目标父节点存在且未逻辑删除 | `10101` |
  | 2 | 被移动节点 ∈ 我的子树，且不是我自己、不是租户根节点 | `10107` |
  | 3 | 目标父节点 ∈ 我的子树（**跨子树搬运在此被拒**） | `10107` |
  | 4 | 防成环：`toParentId != id` 且 `FIND_IN_SET(id, targetParent.ancestors) = 0` | `10103` | <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
  | 5 | 目标父节点为教师节点（`nodeType=2`）时，被移动节点必须是学生 | `10105` |
  | 6 | 目标父节点为学生节点（`nodeType=3`）时一律拒绝 | `10106` |
  | 7 | 其余非法父子类型组合（如把管理员挂到教师下） | `10104` |
  | 8 | 目标父节点 `status=0`（未停用） | `10109` |
  | 9 | 目标父节点下无同名节点 | `10102` |
  | 10 | 被移动学生节点学籍状态为 0 在读 | `10203` |
  | 11 | 目标父节点不等于当前父节点 | `10205` |

  **事务内执行**：更新 `org_node.parent_id` 与自身 `ancestors` → **递归重算整棵子树（含自身）的 `ancestors`** → 原父节点 `child_count - 1`、新父节点 `child_count + 1` → 沿新旧两条祖先链维护 `student_count` → 写入 `org_node_change_log`。

  **事务提交后立即执行**：递归删除被移动子树的 `node:anc:*` Redis 键（契约 §2.3）。这是 §2.4「学员被移走后原上级立即失去对其全部数据的访问权」这句承诺的**唯一落地机制**——鉴权与数据权限选路都从该缓存取祖先链，不删就等于原上级在缓存 TTL 内继续持有旧的可见范围。**`ancestors` 绝不可写进 JWT**：它随移动而变，写进去就固化成发证时刻的快照，任何移动都要等 Token 过期才生效。

  **异动类型自动推断**（`org_node_change_log.change_type`，契约第 5 节枚举）：

  | 被移动节点 | 目标父节点 | change_type |
  | --- | --- | --- |
  | 学生（3） | 教师（2） | `2` 分配导师 |
  | 学生（3） | 管理员（1） | `3` 转交管理员 |
  | 教师（2） | 管理员（1） | `4` 教师调岗（其名下学员子树整体跟随） |
  | 管理员（1） | 管理员（1） | `8` 节点移动（管理员节点自身改父，即整个分支换上级） |

  **移动的即时副作用**：原上级立即失去对被移动子树全部数据（含历史明细）的访问权；被移动节点**已获得的资源授权（`org_resource_grant`）随节点保留，不自动撤销**——若新上级并不拥有这些资源，属于跨管辖授权。本接口按契约 §2.5 规则 9 **必须**在响应中回传该清单（`outOfScopeGrants`）。**支持 `revokeOutOfScopeGrants=true` 一并回收**（模块 11 已落地）：置 `true` 时，被移动子树内**已跨出管辖范围**的授权在**同一事务内级联撤销**，`outOfScopeGrants` 为**已回收**的清单；默认 `false` 时授权一律保留，清单为**仍保留**的那一份，可另走**接口 39（撤销资源授权）** 手动处理，未回收的同时进入一致性巡检待办。<br>**回收必须级联**：清单是按「授权链断没断」逐层算的，只撤清单里那些行会在语义放宽时留下悬挂授权，故走与接口 39 **同一条**级联撤销。归属与结算口径（当日归新导师、已结算行永不重算）见 03-05 数据中心分册。

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string(Path) | 是 | 被移动节点 ID |
| toParentId | string(Body) | 是 | 目标父节点 ID |
| revokeOutOfScopeGrants | boolean(Body) | 否 | 默认 `false`。语义是「移动后被移动子树持有的、由原上级授予且现已跨出其管辖范围的资源授权是否一并回收」（契约 §2.5 规则 9）。**是否一并回收**（模块 11 已落地）：`true` 时同事务内级联撤销这些授权，`false`（默认）时一律保留、仅在响应中列出。 |
| reason | string(Body) | 否 | 异动原因，写入 `org_node_change_log.reason`，最长 500 字符 |

### 3.5 节点停用 / 启用

- **接口名**：节点停用 / 启用
- **方法与路径**：`PUT /api/v1/org/nodes/{id}/status`
- **权限**：仅 `org_admin`
- **数据权限**：目标节点必须在当前用户**子树**内，且不得是自己所在节点，否则返回 `10107`。
- **说明**：停用是**可逆的软冻结**，不删除任何数据。
  - `status=1`（停用）后：该节点不可再作为新建下级的父节点、移动目标、授权目标（相关接口返回 `10109`）；此后登录返回 `10017`。
  - **在线 Token 的失效走"冻结集"，不逐个踢人**（契约 §2.3）：停用时 `SADD frozen:{tenantId} {nodeId}`（**先写 Redis、再提交事务**），鉴权拦截器每请求比对调用者的祖先链与该集合，命中即拒。**分支冻结因此对子树内已登录的 1.1 万人立即生效**——若只作废被停用者本人的 Token，子树成员手里的 `accessToken` 还有最长 2 小时有效期，而分部关停/欠费停服/合规冻结都不接受这个延迟。启用时**先提交事务、再 `SREM`**，两个方向都朝"宁可多拦一瞬"偏。
  - **只写 `org_node.status` 一行，绝不同步写 `sys_user.status`**（契约 §2.3）：后者是与组织无关的账号级封禁、仅超管可写（03-01 §2.6）。曾经的"停用时同步置 `sys_user.status=1`"会造成**停用可逆、启用不可逆**——启用只改回 `org_node.status`，账号侧的 1 无人复位，而机构管理员没有任何接口能改它，用户永久登不进去、只能提工单改库。
  - **停用效果按节点类型自动区分，无 `cascade` 参数**：停用**管理员节点**时其整棵子树禁止登录（分支冻结）；停用**教师节点**时仅本人，名下学员照常学习；学生节点仅本人。
  - **实现走登录时查祖先链，不做级联写库**：停用只改本节点 1 行。登录校验分两段（契约 §2.3）——①本人所在节点 `status=1` 即拒登（教师/学生的"仅本人"停用由此生效）；②拆 `ancestors` 主键 IN 查询，命中 `node_type=1 且 status=1` 的祖先即拒登（管理员的分支冻结由此生效）。两段任一命中均返回 `10017`。恢复同样只改 1 行、子树立即同步；级联写库方案要为一个 1.1 万人的分支写 2.2 万行，中途失败留下半停用状态，且恢复时无法区分"被级联停的"与"本来就单独停的"。
  - `status=0`（启用）：只改本节点 1 行，其子树的登录能力立即恢复；子树内被**单独**停用的节点仍保持停用（互不干扰）。**停用与启用写的是同一字段的两个方向，因此天然对称可逆**——这正是不去碰 `sys_user.status` 的理由。
  - 停用**不影响**已产生的学习记录与统计，也**不撤销**已有的资源授权。

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string(Path) | 是 | 节点 ID |
| status | int(Body) | 是 | 目标状态：0 正常 1 停用 |
| remark | string(Body) | 否 | 操作说明，最长 500 字符 |

**请求示例**

```json
PUT /api/v1/org/nodes/1960000000000000011/status
{
  "status": 1,
  "remark": "赵敏离职交接期，团队暂时冻结"
}
```

**响应示例**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "nodeId": "1960000000000000011",
    "status": 1,
      "affectedNodeCount": 43,
    "affectedUserCount": 43,
    "updateTime": "2026-08-12 14:35:00"
  }
}
```

**相关业务错误码**：`10101` 节点不存在或已删除；`10107` 目标节点不在您的管辖范围内；`10012` 不允许对当前登录账号执行该操作（停用自己所在节点或自己的账号）。

### 3.6 重置人员密码

- **接口名**：重置人员密码
- **方法与路径**：`PUT /api/v1/org/nodes/{id}/password/reset`
- **权限**：`org_admin`；`teacher`（仅限其**名下学员**，即该节点是自己的直接子节点）
- **数据权限**：目标节点必须在当前用户**子树**内，否则返回 `404`（不暴露存在性）；**不得对自己执行**（返回 `10012`，改密自己走 03-01 §1.6）。
- **说明**：学员或教师忘记密码时由其上级重置。**按节点 ID 而非按人员类型分三个接口**——每个节点都是一个人（契约 §2.3），管理员 / 教师 / 学生的重置逻辑完全一致，没有分三份的理由。
  - 事务内：写 `sys_user.password`（BCrypt）→ 置 `pwd_reset_flag=1`（下次登录强制改密）→ **作废该用户全部在线 Token** → 写 `sys_oper_log`。
  - 新密码：请求体传 `newPassword` 时用指定值（8~20 位、含字母与数字）；**留空则服务端随机生成 ≥12 位强口令**。明文仅在本次响应返回一次，不落库、不可再查。**严禁以手机号后 6 位等可由账号推导的值作兜底**——`username` 即手机号，同源意味着拿到名单即可登录任意账号。
  - 目标节点或其账号已停用时照常可重置（重置不解除停用）。

> **为什么这个接口必须存在于 `/org/**`**：机构侧人员的全部生命周期操作都在本分册，而"重置密码"此前只有 `/api/v1/system/users/{id}/password/reset` 一条路径。该路径已收敛为**平台超管专用**（03-01 §2 导语），机构管理员若没有本接口，就无法给忘记密码的学员重置——收敛入口不等于砍掉能力。

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string(Path) | 是 | 目标人员的**节点 ID**（`org_node.id`，管理员 / 教师 / 学生任一类型） |
| newPassword | string(Body) | 否 | 新密码，8~20 位且**同时含字母与数字**；留空则服务端随机生成 ≥12 位强口令 |

**请求示例**

```json
}
```

**响应示例**

### 4.2 新建下级管理员

- **接口名**：新建下级管理员
- **方法与路径**：`POST /api/v1/org/admins`
- **权限**：仅 `org_admin`
- **数据权限**：`parentNodeId` 必须在当前用户**子树**内（可以是自己所在节点），否则返回 `10107`。
- **说明**：单事务内完成：
  1. 创建 `sys_user`：`user_type=1`，`username` 默认取手机号，初始密码 BCrypt 存储、`pwd_reset_flag=1`（首次登录强制改密）：**请求体传入 `initPassword` 时用管理员指定的值**（8~20 位、含字母与数字）；**留空则由服务端随机生成 ≥12 位强口令**，明文仅在本次响应的 `initPassword` 中返回一次、不落库、不可再查。**严禁以手机号后 6 位等可由账号推导的值作为兜底**——`username` 即手机号，两者同源意味着任何拿到学生名单的人都能直接登录。绑定 `org_admin` 角色；
  2. 创建 `org_node`：`node_type=1`，`parent_id=parentNodeId`，`ancestors` 由父节点推导，`ref_user_id` 指向新账号，`node_name` 默认取 `realName`；
  3. 回填 `sys_user.node_id` 为新节点 ID；
  4. 父节点 `child_count + 1`；
  5. 若传入 `templateId`，套用权限模板批量授权（见下）。
- **套用权限模板（可选）**：`templateId` 有值时，对新节点按契约 §2.5 执行**取交集**：`实际授权 = 模板资源清单 ∩ 当前操作人（授权人）拥有的资源`；被跳过的资源在响应 `templateApply.skippedResources` 中逐条列出。授权行写入 `org_resource_grant`，`grant_source=5`（按模板），`source_ref_id=templateId`。
  **交集为空时不阻断建号**：账号与节点仍创建成功，`templateApply.grantedCount=0` 且跳过清单完整返回（与接口 50 独立调用时返回 `10306` 的行为不同——建号是主操作，授权是附带操作，不因附带操作失败而回滚）。
- **父子类型校验**：`parentNodeId` 须为 `node_type = 1`；父节点为教师返回 `10105`，为学生返回 `10106`。

- **数据权限**：目标管理员节点必须在当前用户**子树**内且不得是自己，否则返回 `10107` / `10012`。

  - 已产生的操作日志、学习与统计数据一律保留。

| --- | --- | --- | --- |

### 5.4 删除教师

- **接口名**：删除教师
- **方法与路径**：`DELETE /api/v1/org/teachers/{id}`
- **权限**：仅 `org_admin`
- **数据权限**：目标教师节点必须在当前用户**子树**内且不得是自己，否则返回 `10107` / `10012`。
- **说明**：逻辑删除。

  - 该教师历史批改记录、`hw_answer_sheet.teacher_node_id` 快照、`stat_teacher_daily` 业绩数据**一律保留**（契约 §2.6 历史归原导师）。

## 6. 学生管理

> 一个学生 = 一个 `sys_user`（`user_type=3`，角色 `student`）+ 一个 `org_node`（`node_type=3`，**叶子，不可有子节点**）+ 一条 `org_student` 档案。
> **学生挂在哪个节点下，就归谁管**：挂在管理员节点下 = 已归属该管理员、尚未分配导师；挂在教师节点下 = 该导师的名下学员。

- **权限**：`org_admin`；`teacher`（建的学生**直接挂本人节点**，即刻成为其名下学员）
- **数据权限**：`parentNodeId` 必须在当前用户**子树**内（可以是自己所在节点），否则返回 `10107`。
- **说明**：`parentNodeId` **不传时默认挂在创建者本人所在节点下**（契约 §2.3："学生由管理员创建时，默认挂在创建它的管理员节点下 → 已归属该管理员、尚未分配导师"）。传入教师节点则等同于建档即分配导师。

  单事务内完成：
  1. 创建 `sys_user`：`user_type=3`，`username` 默认取手机号，初始密码 BCrypt 存储、`pwd_reset_flag=1`（首次登录强制改密）：**请求体传入 `initPassword` 时用管理员指定的值**（8~20 位、含字母与数字）；**留空则由服务端随机生成 ≥12 位强口令**，明文仅在本次响应的 `initPassword` 中返回一次、不落库、不可再查。**严禁以手机号后 6 位等可由账号推导的值作为兜底**——`username` 即手机号，两者同源意味着任何拿到学生名单的人都能直接登录。绑定 `student` 角色；
  2. 创建 `org_node`：`node_type=3`（叶子），`parent_id=parentNodeId`，`ref_user_id` 指向新账号；
  3. 创建 `org_student` 档案：`status=0` 在读；
  4. 回填 `sys_user.node_id`；父节点 `child_count + 1`；沿祖先链 `student_count + 1`；父节点为教师节点时 `org_teacher.student_count + 1`；
  5. 写入 `org_node_change_log`：`change_type=1`（建档），`from_parent_id=null`，`to_parent_id=parentNodeId`；
  6. 有 `tagIds` 则写入 `org_student_tag`；
  7. 有 `templateId` 则按契约 §2.5 **取交集**套用权限模板（规则与接口 8 一致，`grant_source=5`，交集为空不阻断建档）。
- **上限校验**：创建后本租户在读学生总数（`org_student.status=0`）不得超过 `sys_tenant.max_student_count`，超出返回 `10207`。
- **父子类型校验**：`parentNodeId` 可为 `node_type ∈ {1, 2, 3}` 的任一节点；父节点为学生节点返回 `10106`。

  退课后：该学员退出全部在途统计分母（`stat_teacher_daily` / `stat_node_daily` 的 `student_count`），不再接收新的资源授权与作业分发；**已有的资源授权不自动撤销**，如需收回请通过接口 39 显式撤销；历史学习记录、答卷、错题本一律保留。退课学员**仍可登录**（区别于归档），仅无新内容下发；如需一并禁止登录请改用毕业归档（接口 24）。

  误操作可通过接口 25 恢复为在读——该接口同时受理 `status=1` 退课与 `status=2` 归档的恢复（见 6.10）。

### 6.9 批量毕业归档

- **接口名**：批量毕业归档
- **方法与路径**：`POST /api/v1/org/students/archive`
- **权限**：仅 `org_admin`
- **数据权限**：`studentIds` 内每个学生节点、或 `nodeId` 指定的节点，都必须在当前用户**子树**内，否则返回 `10107`。
- **说明**：`studentIds` 与 `nodeId` **二选一**（同时传或都不传返回 `400`）：
  - `studentIds`：按名单归档；
  - `nodeId`：按**子树**整批归档，归档该节点整棵子树内全部 `status=0` 在读学员（节点本身不变、不删除）。

  **原子操作**：名单中任一学员状态不为 `0` 在读则整体失败并返回 `10208`（`nodeId` 模式下自动只取在读学员，因此不会触发该码）。逐生执行：`org_student.status` 0 → 2（毕业归档），写入 `archive_time` → 沿祖先链 `student_count - 1`、原导师 `org_teacher.student_count - 1` → 写入 `org_node_change_log`：`change_type=5`（毕业归档），节点**不移动**。

  **归档后禁止登录**：学籍 `status=2` 后登录接口（03-01）返回 `10015` 账号已归档，禁止登录。归档不物理删除任何数据：历史答卷、错题本、学习档案完整保留，管理员 / 教师端按子树权限仍可查询。归档学员退出全部在途统计分母，不再接收新的资源授权与作业分发；**已有的资源授权不自动撤销**，如需收回请通过接口 39 显式撤销。误归档可通过接口 25 恢复。

  **`archiveReason` 决定是否启动脱敏倒计时**（契约 §7.2 第 3 条）：
  - `1` **正常毕业归档**（默认）：仅改学籍状态，联系方式原样保留——机构仍需联系校友。
  - `2` **因监护人删除请求归档**：写入 `archive_reason=2`，此后由定时任务在 **30 日**后执行**不可逆脱敏**（见下）。
    选 30 日而非立即，是给"误提删除请求"和"机构内部走完审批"留出撤回窗口；这 30 日内可经接口 25 恢复，脱敏一旦执行则不可恢复。

  **脱敏定时任务（XXL-Job，每日一次）**：扫描 `archive_reason=2 AND archive_time <= NOW()-30天 AND anonymized_at IS NULL` 的学员，逐个把 `org_student.guardian_phone`、`sys_user.phone` 覆写为掩码（`138****5678`），`guardian_name`、`sys_user.real_name` 覆写为姓氏 + `*`，回写 `anonymized_at`，并记 `sys_oper_log`。
  - **保留掩码位而不是置 NULL**：置 NULL 会让"这个人到底提没提过删除请求"变得不可区分，也无法与历史对账。
  - **`sys_login_log` / `sys_oper_log` 不参与本次清理**（契约 §7.2 第 5 条：《网络安全法》第 21 条要求日志留存 ≥ 6 个月）。
  - 学习记录与答卷本身是机构的教学档案，按约定保留期留存——与个人身份标识解绑后不再构成个人信息。

**请求参数（Body，application/json）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| archiveReason | int | 否 | 归档原因：`1` 正常毕业归档（默认） `2` 因监护人删除请求归档。传 `2` 时启动 30 日脱敏倒计时，**该操作不可逆**，前端须二次确认 |
| studentIds | string[] | 二选一 | 学生档案 ID 数组，单次最多 500 个 |
| nodeId | string | 二选一 | 节点 ID，归档其**整棵子树**内全部在读学员 |
| remark | string | 否 | 归档说明，写入每条轨迹记录 `reason`，最长 500 字符 |

**请求示例（按子树整批归档）**

```json
POST /api/v1/org/students/archive
{
  "nodeId": "1960000000000000020",
  "remark": "2026 届高三学员统一结课归档"
}
```

**请求示例（按名单归档）**

```json

  "remark": "提前结课"
}
```

**相关业务错误码**：`10101` 节点不存在或已删除；`10107` 目标节点不在您的管辖范围内；`10208` 退课/归档名单包含状态不符的学员。归档后学生登录由登录接口（03-01）返回 `10015` 账号已归档，禁止登录。

### 6.10 归档恢复

- **接口名**：归档恢复
- **方法与路径**：`POST /api/v1/org/students/{id}/unarchive`
- **权限**：仅 `org_admin`
- **数据权限**：目标学生节点与 `toParentNodeId` 都必须在当前用户**子树**内，否则返回 `10107`。
- **说明**：把已归档（`status=2`）或已退课（`status=1`）的学员恢复为 `0` 在读。仅 `status ∈ {1, 2}` 可恢复，对在读学员调用返回 `10204`。

  **已脱敏的学员不可恢复**：`anonymized_at` 非空时返回 `10209`。脱敏是**不可逆**的——`guardian_phone` 与 `sys_user.phone` 已被掩码覆写，原值不存在于任何地方，恢复出来的会是一个联系不上的账号，且违背了当初对监护人"已删除"的承诺。因删除请求归档的学员（`archive_reason=2`）在 30 日倒计时内**可以**恢复，这正是该窗口存在的意义。

  事务内：`org_student.status` → 0，清空 `archive_time` / `archive_reason` / `quit_time` / `quit_reason` → 若传入 `toParentNodeId` 且与当前父节点不同，则同步移动节点（走接口 4 的完整校验：类型、子树、停用、重名）→ 沿祖先链 `student_count + 1`、目标为教师节点时 `org_teacher.student_count + 1` → 写入 `org_node_change_log`：`change_type=6`（归档恢复）。

  `toParentNodeId` **可不传**：不传即原地恢复，学员回到归档前所在的节点下（原节点已被删除或停用时返回 `10101` / `10109`，此时必须显式指定新的挂载节点）。

  恢复后学员即可正常登录（登录接口不再返回 `10015`），重新计入统计分母；**归档期间未被撤销的资源授权继续有效**，无需重新授权。
- **上限校验**：恢复后本租户在读学生总数不得超过 `sys_tenant.max_student_count`，超出返回 `10207`。

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string(Path) | 是 | 学生档案 ID |
| toParentNodeId | string(Body) | 否 | 恢复后的挂载父节点 ID（管理员或教师节点）；留空表示原地恢复 |
| remark | string(Body) | 否 | 恢复原因，写入轨迹记录 `reason`，最长 500 字符 |

```json
POST /api/v1/org/students/1963000000000000030/unarchive
{
  "toParentNodeId": "1960000000000000021",
  "remark": "学员续费复课，转由李强老师带教"
}
```

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "studentId": "1963000000000000030",
    "nodeId": "1960000000000000030",
```

### 6.12 归属变更影响面预检

- **接口名**：归属变更影响面预检
- **方法与路径**：`POST /api/v1/org/students/transfer-precheck`
- **权限**：仅 `org_admin`
- **数据权限**：`studentIds` 内每个学生节点与 `toNodeId` 都必须在当前用户**子树**内，任一越界整体拒绝并返回 `10107`（与接口 20 / 21 / 22 同一判定，预检与执行不得有两套口径）。
- **说明**：**只读预检，不改任何数据**。接口 20（分配导师）/ 21（批量分配导师）/ 22（转交给其他管理员）执行后，学员原有的资源授权按契约 §2.5 规则 6 **合法保留**，但**新上级的祖先链上无人持有这些资源**——新导师 / 新管理员看不到这门课，也无法再下发。本接口把这个影响面在**执行前**摊开给操作者。

  **一个接口覆盖三个动作**：接口 20 是接口 21 在 `n = 1` 时的情形；接口 22 只是目标节点类型不同。动作类型由 `toNodeId` 的 `node_type` 推断（`2` → 分配导师，`1` → 转交管理员），与接口 4（移动节点）的 `changeType` 推断同源，不另立一套分支。

  **按资源聚合，不按人聚合**：批量上限 500 人，逐人弹窗不可用；前端若自行调接口 41（节点已获授权资源列表）做差集，500 人要调 501 次。本接口一次返回按**资源**归并的差集——每个资源涉及多少人、当前操作者能否授予。

  **三个处置选项，默认「保持现状」**（契约 §2.5 规则 6 把跨管辖定为**合法状态**；且本系统的教师是**督学导师不是授课老师**，督学动作——看进度、完播率、催作业——全按学生维度查，**不需要课程授权**）：强制二选一等于逼操作者在「给导师一堆用不上的授权」和「把学员的课停掉」之间挑一个，默认必须是第三个选项：**什么都不做**。

  **操作者无权授予的资源不返回 `10301`**，而是以 `grantableByMe = false` 标记。`10301`（只能授权自己拥有的资源）是**执行接口 38 时**的拒绝码；在只读预检里抛它会让整个预检失败，而操作者恰恰需要看到「这门课我授不了，得找共同上级」——接口 22 的完整流程本就是**三步**（转交 → 授权给新管理员 → 分配导师并授权给该导师），第二步必须由共同上级执行。

  **披露形态参照接口 39（撤销资源授权）的 `cascadeDetail`**：样本最多返回前 50 个，完整数量另给字段。「把影响面摊开给操作者」这个模式分册里已经确立，不另造一套。

**请求参数（Body，application/json）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| studentIds | string[] | 是 | 学生档案 ID 数组，不可为空，单次最多 500 个；预检接口 20 时传 1 个 |
| toNodeId | string | 是 | 目标节点 ID。`node_type = 2` 教师节点 → 预检接口 20 / 21；`node_type = 1` 管理员节点 → 预检接口 22 |

**为什么是 `POST` 而不是 `GET`**：500 个 ID 放不进 query string。与接口 36（按标签批量选人）同为读语义，方法选择只取决于入参体积。

| --- | --- | --- |

> **实现排期：本接口的签名在模块 07 敲定，实现落在模块 11。** 三处依赖全部在模块 11 及其前置：
> ① `outOfScopeGrants` 的判定在模块 06 只做了一半（`org/node/mapper/NodeGrantScopeMapper` 交接给模块 11，「资源 `owner_node_id` 与有效授权链」那一半不在模块 06 / 07 的涉及表内）；
> ② `resourceName` 在 `crs_course` / `qb_question` / `vod_video`，模块 08 / 09 / 10 才建表——在此之前**恒为 `null`**（接口 4 的响应字段说明已记同一件事）；
> ③ `grantableByMe` 需要「授权人是否拥有该资源」的完整判定，同样是模块 11 的授权引擎。
> 现在定签名而不是等编码时再定，是因为它让接口总数 160 → 161，需同步四处计数（本分册目录、`README.md`、`00-通用约定` §10、`04-实施计划.md` §A 核对行），**F-2 那次 159 → 160 就是漏了最后一处**。

### 7.2 学生批量导入

- **接口名**：学生批量导入
- **方法与路径**：`POST /api/v1/org/students/import`
- **权限**：仅 `org_admin`
- **数据权限**：`targetNodeId` 必须在当前用户**子树**内（可以是自己所在节点），否则**同步**返回 `10107`，任务不创建。
- **说明**：**异步处理**。接口只做文件级与参数级校验（格式、大小、行数、目标节点、并发任务、租户学生数上限），通过后：上传文件落 `sys_file` → 创建 `org_import_task`（`biz_type=1` 学生导入，`status=0` 处理中）→ 立即返回 `taskId`，由后台任务逐行解析入库，进度通过接口 29 轮询。
  - **目标节点由 `targetNodeId` 统一指定**，本次导入的全部学员均挂在该节点下；留空默认取当前用户所在节点。`targetNodeId` 可为管理员或教师节点：指向教师节点即建档时直接分配导师；指向管理员节点即"已归属、待分配"。
  - 每行成功逻辑与接口 17（创建学生）完全一致：建 `sys_user` → 建 `org_node`（`node_type=3`）→ 建 `org_student`（`status=0`）→ 回填 `node_id` → 维护 `child_count` / `student_count` → 写入 `org_node_change_log`（`change_type=1` 建档）→ 写入标签关联。
  - 传入 `templateId` 时，对**每个新建学生节点**按契约 §2.5 取交集套用权限模板（`grant_source=5`）；交集为空不阻断导入，跳过情况计入失败报告的备注列而非失败行。
  - **行级失败不中断任务**：手机号已被注册、同文件手机号重复（仅保留首行）、学号重复、标签名不存在、字段格式非法等，失败行写入失败报告 Excel（原行内容 + 追加"失败原因"列），生成 `fail_report_file_id`。
  - **并发限制**：同一租户同一时刻仅允许一个 `status=0` 的学生导入任务，重复发起返回 `10401`。
- **文件限制**：仅 `.xlsx`；大小 ≤ 5MB；数据行数 ≤ 2000（超出返回 `10402`）。

**请求参数（Body，multipart/form-data）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| file | file | 是 | 按模板填写的 xlsx 文件 |
| targetNodeId | string | 否 | 目标挂载节点 ID；留空默认取当前用户所在节点 |
| templateId | string | 否 | 权限模板 ID，对每个新建学生节点套用（取交集） |

**请求示例**

```
------WebKitFormBoundaryEduMatrix
Content-Disposition: form-data; name="templateId"

1965000000000000001
------WebKitFormBoundaryEduMatrix--
```

**响应示例**

```json

  "msg": "操作成功",
  "data": {
```

**相关业务错误码**：`10002` 导入文件格式错误；`10101` 节点不存在或已删除（`targetNodeId` 无效）；`10106` 学生节点不可有子节点（`targetNodeId` 指向学生节点）；`10107` 目标节点不在您的管辖范围内；`10109` 节点已停用，不可执行该操作；`10207` 学生数量超出机构可容纳上限（按文件数据行数预校验）；`10305` 权限模板不存在或已停用；`10401` 存在处理中的学生导入任务；`10402` 导入文件行数超出上限（2000 行）。手机号占用、学号重复、标签不存在等均为**行级失败**进错误报告，不返回业务错误码。

## 8. 标签管理

> **标签边界（务必遵守）**：`org_tag` / `org_student_tag` **仅用于筛选与批量操作，不参与任何权限判断**（契约 §4 表清单、铁律 2）。

## 9. 资源授权（逐级下发）

> **本节对齐契约 §2.5 与铁律 3。**
>
> **受管资源**共三类（`resource_type`）：`1` 课程（`crs_course`）、`2` 题目（`qb_question`）、`3` 视频（`vod_video`）。每个资源有 `owner_node_id`（归属节点，创建时写入创建者所在节点）。授权关系落在 `org_resource_grant`，唯一约束 `UK(resource_type, resource_id, target_node_id)`。
>
> **四条不可违反的规则**：
>
> 1. **只能授权自己拥有的资源**——授权人是该资源的 `owner_node_id`，或该资源已显式授权给授权人所在节点。否则 `10301`。
> 2. **只能授权给自己子树内的节点**——禁止横向授权（授给平级）与向上授权（授给上级）。否则 `10302`。
> 3. **不向下继承，每一层都必须显式授权**——机构管理员拿到 100 门课，其下级管理员必须被**显式授权**才能拿到其中 30 门；下级管理员 → 教师、教师 → 学生同理，精准到人。任一节点实际可用的资源 = 其父级显式授予它的那一份，天然逐级收缩，不存在跨级穿透。
> 4. **判定不回溯祖先链**——"某节点能否使用某资源"只看一条命中：`target_node_id = 该节点 AND resource_id = X AND deleted_at = 0`。这比继承模型更快，且不存在祖先链断裂导致的判定歧义。
>
> **撤销必须级联到子树**（接口 39），否则会出现"父级已无权、子级仍持有"的悬挂授权，逐级收缩被破坏。
>
> ---
>
> ### ⚠ 授权**没有有效期**（需求方 2026-08-21 定案）
>
> 需求方原话：「课程权限我不希望有时间，我觉得不需要有时间，这还不如直接收回权限」「全部都是永久有效可以吗？包括所有的接口」。
>
> **失效手段只有两个**：显式撤销（接口 39，级联整棵子树）与**学籍状态**（播放凭证校验链第一步「学生在读」）。时间不再是其中之一。
>
> 连带后果，**逐条列出，都不是缺陷**：
>
> | 位置 | 现在的行为 |
> | --- | --- |
> | 接口 40 修改授权有效期 | **已删除**，接口总数 161 → 160。§9.4 保留为墓碑小节，§9.5 / §9.6 的编号不变 |
> | 接口 38 的 `validStart` / `validEnd` 请求参数 | **已删除**；响应的 `validStart` / `validEnd` / `validEndTruncated` / `effectiveValidEnd` 四个字段一并删除（它们是**截断动作的产物**，动作没了字段就是噪音） |
> | 接口 37 / 41 / 51 的 `validStart` / `validEnd` | **字段保留、恒为 `null`**（响应结构不变） |
> | 接口 41 的 `expired` 与 `includeExpired` | **均已删除**（F-107）：`expired` 恒 `false`、`includeExpired` 恒无差别，而字段注释还写着「仅 `includeExpired = true` 时可能为 `true`」——**注释描述了一个不存在的行为**。留一个「调了没反应」的开关，与上一轮被否决的「接口 40 空壳」是同一个形状 |
> | 接口 51 的 `type=expiring` | 取值保留，**恒回空清单**——没有到期日就没有「临期」 |
> | 契约 §2.5 规则 7（「不晚于授权人自身对该资源的 `valid_end`」） | **失去适用对象** |
> | `org_resource_grant.valid_start` / `valid_end` 两列 | **保留但永远不写**——从生产已有的表上删列要做迁移、有风险，收益为零。**留列删码** |
>
> **`org:grant:edit`（菜单「修改授权有效期」）已随之删除**（需求方 2026-08-21 定案「没人用的权限 直接删掉」，F-104）：`V202608210100__drop_grant_edit_perm.sql` 删掉菜单行与 `org_admin` / `teacher` **两条**绑定 —— 那条权限**原本绑给两个角色**，教师也能改有效期。父菜单「资源下发中心」还有授权、撤销两个子项，不会留下空目录。

### 9.2 授权资源给节点

- **接口名**：授权资源给节点
- **方法与路径**：`POST /api/v1/org/grants`
- **权限**：`org_admin`；`teacher`（目标节点只能是其名下学员节点）
- **数据权限**：`targetNodeIds` 内**每一个目标节点都必须在当前用户子树内**，任一越界整体拒绝并返回 `10302`（横向授权与向上授权在此被拦截）。
- **说明**：一次调用可把 **N 个同类资源** 授权给 **M 个目标节点**（笛卡尔积，最多 `N × M = 5000` 条），写入 `org_resource_grant`。

  **校验顺序（任一失败即整体回滚，不做部分成功）**：

  | 序 | 校验项 | 失败错误码 |
  | --- | --- | --- |
  | 1 | `resourceIds` 内每个资源都在"我可授权的资源列表"（接口 37）内 | `10301` |
  | 2 | `targetNodeIds` 内每个节点存在且未删除 | `10101` |
  | 3 | `targetNodeIds` 内每个节点都在我的**子树**内 | `10302` |
  | 4 | 目标节点未停用 | `10109` |
  | 5 | **`resourceType ∈ {2,3}`（题目 / 视频）时，目标节点不得是学生节点（`node_type=3`）** | `10308` |
  | 7 | 不存在重复授权（`UK(resource_type, resource_id, target_node_id)`） | `10303` |

  **为什么第 5 条必须有**（契约 §2.5 规则 11）：学生侧**没有题目/视频的直接使用入口**——作答走 `hw_homework_target` + 固化版本，播放走课程授权，错题本走 `question_version` 快照，三条路径都与题目/视频授权解耦。授给学生的行**永远不会被任何鉴权路径读到**。

  不拦的后果是量级问题：一个"高三数学包"（20 课程 + 500 题目 + 80 视频）套给 300 名新生，每人写 600 行，其中 **580 行是题目/视频授权**——18 万行里 17.4 万行是永不被读的垃圾。更糟的是契约 §2.5 规则 6 会把这类行计入悬挂授权巡检，而 `grant_dangling_count` 的告警线是 **> 0**，这条"每发生一次就是一次静默数据错误"的指标会被垃圾行永久淹没。

  **重复授权的两种处理**：默认 `ignoreDuplicate=false`，命中已有授权即整批回滚返回 `10303`；置 `ignoreDuplicate=true` 时跳过已存在的组合、只写入新组合，跳过明细在响应 `duplicated` 中列出——批量补授场景建议使用后者。

  **授权来源标记**：`grantSource` 记录本次授权的操作方式（契约第 5 节 `grant_source`：1 手动选择 2 按节点批量 3 按标签批量 4 按名下全体 5 按权限模板），`sourceRefId` 为对应的来源对象 ID（按节点批量填节点 ID、按标签批量填标签 ID、按模板填模板 ID，手动选择留空）。**来源标记只是审计信息，不是授权依据**——尤其 `grantSource=3` 按标签批量，标签只负责选出目标节点，授权本身仍逐条走上表全部校验（契约铁律 2）。

**请求参数（Body，application/json）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |

### 9.3 撤销资源授权（级联子树）

- **接口名**：撤销资源授权（级联子树）
- **方法与路径**：`DELETE /api/v1/org/grants`
- **权限**：`org_admin`；`teacher`（仅可撤销自己授给名下学员的授权）
- **数据权限**：`targetNodeIds` 内**每一个目标节点都必须在当前用户子树内**，任一越界整体拒绝并返回 `10302`。
- **说明**：本接口为 `DELETE` **携带 JSON 请求体**（批量撤销无法用路径参数表达），执行逻辑删除（`org_resource_grant` 逻辑删除）。

  **必须级联撤销子树（契约 §2.5 规则 5，铁律 3）**：

  > 撤销对某节点的资源授权时，**必须级联撤销该资源在目标节点整个子树内的全部授权**。

  也就是说，撤销 `targetNodeId = N` 上的资源 X，服务端实际删除的是**所有满足 `resource_id = X` 且 `target_node_id ∈ {N} ∪ N 的子树` 的授权行**。理由：逐级收缩模型下，N 已经无权使用 X，其下级的授权必然是由 N 或 N 的上级授出的；若只删 N 这一行，就会出现"父级已无权、子级仍持有"的**悬挂授权**，逐级收缩被破坏，且无人再能管理这些悬挂行。

  级联是**强制行为，不提供关闭开关**；响应中通过 `cascadeDetail` 完整披露被连带撤销的节点，供操作者确认影响面。契约 §2.5 规则 6 另有定时巡检任务扫描悬挂授权作为兜底防线。

  **学习记录一律保留不删**：`vod_watch_progress`（学习进度）、`hw_answer_sheet`（答卷）、`hw_wrong_book`（错题本）以及 `stat_student_daily` 等统计数据**全部保留**，学员仅**失去继续访问权**——已看过的课程不再能打开、已做过的作业不再能进入，但历史成绩、进度、错题记录在管理端与学员档案中依然完整可查。这条规则保证撤销授权是一个**权限动作，不是数据销毁动作**。

  **幂等**：对不存在或已撤销的授权组合重复调用返回 `code=200`，`revokedCount` 计 0（对齐《00-通用约定》§7.1 DELETE 幂等）。

**请求参数（Body，application/json）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| resourceType | int | 是 | 资源类型：1 课程 2 题目 3 视频 |
| resourceIds | string[] | 是 | 资源 ID 数组，不可为空，单次最多 500 个 |
| targetNodeIds | string[] | 是 | 目标节点 ID 数组，不可为空，单次最多 500 个；**每个节点的整棵子树都会被级联撤销** |
| reason | string | 否 | 撤销原因，写入 `org_resource_grant.remark` 归档，最长 500 字符 |

| missingNodeId | string | `type=dangling` 时为**授权链上已失去该资源的那个上级节点**；`type=crossScope` 时为**移动后新祖先链上无人持有该资源的那个上级节点**（即"该补授给谁"）；`type=expiring` 时为 `null`（该类型恒空，此分支实际不会出现） |

**相关业务错误码**：无（仅通用 400/401/403）。

## 10. 权限模板

> **模板的存在意义**：逐级显式授权的代价是运维负担（新招一名教师要逐个勾选几百个资源），模板用于抵消这一成本（契约 §2.5）。
>
> **三条边界，必须写进实现**：
>
> 1. **模板只管资源，不含功能权限**——模板内容仅为课程 / 题目 / 视频清单，**不包含角色、菜单、按钮等操作权限**。操作权限由角色决定（契约第 3 节），与模板无关。
> 2. **模板不绕过收缩规则**——套用时 `实际授权 = 模板资源清单 ∩ 授权人当前拥有的资源`，模板中授权人已无权的部分**自动跳过并在响应中列出**，**绝不放大权限**。
> 3. **模板按子树可见，套用时自动收缩**——上级建的模板下级可见可用，但应用时因取交集而自动收缩：同一个"高三数学包"，机构管理员用能授出 20 门课，只拿到 5 门的下级管理员用就只授出 5 门。
>
> 表：`org_perm_template`（模板头，`status`：**0 启用 1 停用**，与 `sys_user` / `sys_tenant` / `org_node` 方向一致）、`org_perm_template_item`（资源明细，`UK(template_id, resource_type, resource_id)`）。

### 10.1 权限模板分页列表

- **接口名**：权限模板分页列表
- **方法与路径**：`GET /api/v1/org/perm-templates`
- **权限**：`org_admin`、`teacher`
- **数据权限**：模板可见范围是**铁律 2 的唯一显式例外**（契约 §2.5）——覆盖整条根到叶路径 ∪ 子树，即下列三者之并。该例外安全的原因：模板只是资源清单，套用时取交集（模板 ∩ 授权人已有资源），**永远不可能授出授权人本就没有的资源**（`owner` 指模板归属节点 `org_perm_template.owner_node_id`）：

  ```sql
  owner_node_id = #{myNodeId}                        -- 我自己建的
  OR FIND_IN_SET(#{myNodeId}, owner.ancestors)       -- 我子树内的下级建的（标准子树规则） <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
  OR FIND_IN_SET(owner_node_id, my.ancestors)        -- 我的祖先建的（上级建的模板下级可见可用） <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
  ```

### 10.3 模板明细项分页列表

- **接口名**：模板明细项分页列表
- **方法与路径**：`GET /api/v1/org/perm-templates/{id}/items`
- **权限**：`org_admin`、`teacher`
- **数据权限**：模板必须在 10.1 定义的可见范围（祖先链 + 子树）内，否则返回 `404`。
- **说明**：分页返回 `org_perm_template_item` 明细。每一行附带 `grantableByMe`，标明**当前用户**是否拥有该资源——`false` 的行就是套用时会被跳过、并出现在 `skippedResources` 中的那些资源。前端可据此在勾选界面直接置灰提示。

  **祖先节点建的模板：明细按可见性脱敏（安全约束，必须实现）**

  | 模板归属 | 返回内容 |
  | --- | --- |
  | **我自己建的**（`owner_node_id` = 我的节点） | 明细**全量**返回 |
  | **我子树内节点建的** | 明细**全量**返回 |
  | **我的祖先节点建的** | **仅返回 `grantableByMe = true` 的条目**；其余条目不出现在 `list` 中，只在 `hidden` 中给出数量 |

  **为什么必须脱敏**：契约 FR-2 规则 2 要求下级看不到上级未授予自己的资源，请求未授予资源的详情一律按"不存在"处理、**不暴露存在性**。而 `org_perm_template_item` 就是一张 `(resource_type, resource_id, resource_name)` 清单——下级管理员打开机构统一建的"高三数学包"，若明细全量返回，他**当场就能枚举出上级拥有但从未授予他的全部资源 ID 与名称**，包括课程名这类业务敏感信息。

  契约此前用"模板套用取交集、不会放大权限"来论证祖先可见这条例外是安全的，**但取交集只覆盖了使用权，没有覆盖存在性**：套不出来 ≠ 看不见。存在性由本条脱敏保证，二者缺一不可（契约 §2.5 已补上这一维度）。

  **`grantableByMe` 查询参数在祖先模板上的行为**：传 `false` 时返回空列表（那些条目本就不可见），`hidden.count` 仍如实给出数量——让下级知道"这个模板里还有 480 项我用不了"，但不告诉他那 480 项是什么。

### 10.4 新建权限模板

### 10.5 修改权限模板

- **接口名**：修改权限模板
- **方法与路径**：`PUT /api/v1/org/perm-templates/{id}`
- **权限**：仅 `org_admin`
- **数据权限**：**只能修改 `owner_node_id` 等于自己所在节点、或在自己子树内的模板**；祖先建的模板对自己**只读**（可见可用但不可改），越权修改返回 **`403`**——模板是**路径 `{id}` 上的资源**且按设计对我可见（契约 §2.5 祖先可见例外），既不是"我选的目标越界"（10107 的语义）也不是"不存在"（404 的语义），而是"我没资格改这个东西"——正是 403 的定义。且 10107 的 msg 是"目标节点不在您的管辖范围内"，而用户改的是模板、根本没选任何节点，提示文不对题。

### 10.9 套用模板到节点

- **接口名**：套用模板到节点
- **方法与路径**：`POST /api/v1/org/perm-templates/{id}/apply`
- **权限**：`org_admin`；`teacher`（目标节点只能是其名下学员节点）
- **数据权限**：模板必须在 10.1 的可见范围（祖先链 + 子树）内，否则返回 `404` / `10305`；`targetNodeIds` 内**每一个目标节点都必须在当前用户子树内**，任一越界整体拒绝并返回 `10302`。
- **说明**：把模板清单一次性授权给一批已存在的节点（新建人员时的套用见接口 8 / 12 / 17）。

  **取交集逻辑（契约 §2.5，铁律 3，必须严格实现）**：

  ```
  实际授权 = 模板资源清单 ∩ 授权人（当前登录用户所在节点）当前拥有的资源
  ```

  其中"当前拥有"的判定与接口 37 完全一致：`owner_node_id = 我的节点`（自有），或存在指向我的节点、且在有效期内的 `org_resource_grant`（受授权）。

  **模板中授权人已无权的部分自动跳过，绝不放大权限**，跳过明细在响应 `skippedResources` 中逐条列出（含 `skipReason`）。**但套用祖先节点建的模板时，`skippedResources` 恒为空、只回 `skippedCount` 数量**——被跳过的就是我不拥有的资源，逐条列出等于绕过接口 44 的脱敏再枚举一遍（契约 §2.5 存在性维度）。**套用行为本身不受影响**：服务端仍按完整模板清单取交集，脱敏只作用于响应。这保证了同一个模板在不同层级产生不同的授权结果——机构管理员套用能授出 20 门课，只拿到 5 门的下级管理员套用就只授出 5 门，模板永远不会让任何人拿到超出其上级授予范围的资源。

  **全部跳过时返回 `10306`**：交集为空（模板清单中没有任何一项是授权人当前拥有的）时，不写入任何授权行，返回 `10306` 模板中无任何可授出的资源。这与接口 8 / 12 / 17 建人员时套模板的行为不同——那里建号是主操作、授权是附带操作，交集为空不阻断建号；本接口授权就是主操作，交集为空即无事可做，须明确报错。

  **落库细节**：交集内的每个 `(resource, targetNode)` 组合写入一行 `org_resource_grant`，`grant_source=5`（按权限模板），`source_ref_id={id}`。已存在的授权组合按 `ignoreDuplicate` 处理（默认 `true`，套用模板场景以幂等补授为主）。校验顺序与接口 38 一致：目标节点存在（`10101`）→ 在子树内（`10302`）→ 未停用（`10109`）→ 模板启用（`10305`）→ **按目标节点类型过滤受管资源** → **总量不超上限（`400`）** → 取交集非空（`10306`）。

  **按目标节点类型过滤（契约 §2.5 规则 11）**：目标为**学生节点**（`node_type=3`）时，模板中的**题目与视频条目一律跳过**，只授出课程；被跳过的计入 `skippedCount`，`skipReason` 为"该资源类型不可授权给学生节点"。**与接口 38 的差别是：这里跳过而非报错**——模板是给各类节点共用的清单，套给学生时自动收敛为课程部分才是预期行为，整批拒绝反而让"新生一键套包"这个主场景不可用。若过滤后交集为空，仍返回 `10306`。

  **总量硬上限：交集后的授权行数 ≤ 5000**（与接口 38 的 `N × M ≤ 5000` 同一口径）。**这条不能省**：模板明细上限 2000 项、目标节点上限 500 个，笛卡尔积可达 **100 万行**，若放进一个同步事务，锁持有时间与 binlog 体积都会把主库拖垮，而调用方只是点了一次"套用模板"。

  校验用**交集后**的实际行数而非模板原始明细数——同一个模板在不同层级授出的行数本就不同，用原始数会误拒。超出时返回 `400` 并在 msg 中给出实际行数与上限，提示分批套用（按 `targetNodeIds` 拆批，模板侧无需改动）。

  预估公式：`预计行数 = 交集资源数 × targetNodeIds.length`，服务端在写入前先算出该值，超限即整体拒绝、不落任何行。

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| id | string(Path) | 是 | 权限模板 ID（须 `status=0` 启用） |
| targetNodeIds | string[] | 是 | 目标节点 ID 数组，不可为空，单次最多 500 个，且必须都在当前用户子树内。另受总量约束：**交集资源数 × 本数组长度 ≤ 5000**，超出返回 `400` |

| ignoreDuplicate | boolean | 否 | 已存在的授权组合是否跳过而非报错，默认 `true` |
