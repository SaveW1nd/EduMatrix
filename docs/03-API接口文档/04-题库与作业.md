## 0. 模块级通用说明

### 0.1 角色、数据权限与题目可见性（对齐契约 §2.3 / §2.4 / §2.5）

**两条彼此独立的判定必须同时满足**：

1. **数据权限（看到哪些人的数据）——全系统唯一一条规则（契约 §2.4）**：你能看到的数据 = 你所在节点的子树。
   ```sql
   -- org_node 别名 n，当前用户所在节点 #{myNodeId}
   n.id = #{myNodeId} OR FIND_IN_SET(#{myNodeId}, n.ancestors) <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
   ```
   作业分发目标、答卷、错题本等**与人相关**的数据一律按此过滤（答卷学生必须在我的子树内）。
2. **题目可见性（能用哪些题）——逐级显式授权，无继承（契约 §2.5）**：

   > **可见 = 我的节点就是该题目的 `owner_node_id`，或该题目已被显式授权给我的节点（`org_resource_grant` 命中且当前时间在有效期内）。**

   ```sql
   -- 题目可见性判定（resource_type=2）
   q.owner_node_id = #{myNodeId}
   OR EXISTS (
       SELECT 1 FROM org_resource_grant g
        WHERE g.resource_type = 2
          AND g.resource_id   = q.id
          AND g.target_node_id = #{myNodeId}          -- 精确等于我的节点
          AND g.deleted_at = 0
          AND (g.valid_start IS NULL OR g.valid_start <= NOW())
          AND (g.valid_end   IS NULL OR g.valid_end   >= NOW())
   )
   ```

   - **题库不再是"租户级共享资源"**：同一租户内的题目默认互不可见，必须显式下发。
   - **不回溯祖先链、无继承**：只看 `target_node_id = 我的节点` 这一条命中，**绝不**用 `FIND_IN_SET` 匹配我的任一祖先节点。上级拥有 ≠ 我自动拥有。 <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
   - **不向下展开**：我拥有某题目不代表我的下级可用；下级须经 03-02 的资源授权接口被显式授权。
   - 材料题以**父题**为授权粒度：授权父题即连带其全部子题（子题不单独授权，随父题判定）。
   - 授权过期或被撤销后立即不可见（**但已分发的作业不受影响**：契约 §2.5 规则 10，作业是已下达的任务而非资源，学员仍可作答、教师仍可批改、成绩仍计入统计）；已产生的 `hw_answer_sheet`、`hw_wrong_book` 一律保留不删（契约 §2.5 规则 5）。

| 角色（role_key） | 题库 | 作业管理 / 批改 | 学生作答 / 错题本 |
| --- | --- | --- | --- |
| `org_admin`（管理员，机构级与下级同一角色） | 可见 = `owner_node_id` 为本节点的题目 ∪ 显式授权给本节点的题目；**写操作（改/停用/删除）仅限自有题目** | 仅本人创建的作业可管；**发布目标必须在本人子树内**；批改限本人创建的作业且答卷学生在本人子树内 | 子树内学员错题本**只读**（接口 31） |
| `teacher`（教师 / 导师） | 同上（判定完全一致，不因角色放宽） | 同上；教师的子树 = 名下学员，故发布目标天然限于名下学员 | 名下学员（子树内）错题本**只读**（接口 31，PRD F3-8 规则 6） |
| `student`（学生） | 无权访问 `/api/v1/question/**` | 无 | 仅本人答卷与本人错题本（`student_id`=当前用户） |

- **可见 ≠ 可写**：修改/停用/删除题目要求 `owner_node_id` = 我的节点；仅被授权者为只读可用（可选进作业、可发布），写操作返回 403。
- 所有查询自动注入 `tenant_id` 过滤；跨租户访问一律返回 404（不暴露存在性）。
- 数据权限拒绝按契约 §2.4 三分法：路径 `{id}` 上的对象（他人作业、他人答卷、子树外学员）不在可见范围 → **404**（不暴露存在性）；请求体/参数中显式指定的目标（如 `nodeId`）越界 → **10107**；功能权限不足 → **403**。
- **例外：作业发布的 `studentIds` 越界另用 `30011`**（见 §3.5 与登记册 §9.4），不用 10107。理由是 30011 同时还要承载"目标为空"这一相邻语义，两者在前端是同一处提示（"请重新选择分发对象"），拆成两个码只会让前端多写一个分支而提示文案相同。
- 学生端任何题目下发接口（20/21）**一律不包含** `correctAnswer` 与 `analysis` 字段。
- **题目归属字段**：`qb_question.owner_node_id` 由服务端在创建时强制写入创建者所在节点（`sys_user.node_id`），请求体不接受该参数；材料题的父题与子题写入同一 `owner_node_id`。响应中统一以 `ownerNodeId` / `ownerNodeName` 暴露。

### 1.2 新增题库分类

- **接口名**：新增题库分类
- **方法与路径**：`POST /api/v1/question/categories`
- **权限**：**仅 `org_admin`**，且**仅机构根节点**（F-114 定案一，见下）；数据权限：写入当前租户
- **⚠ F-72 定案（模块 10 落地）**：本条「仅 `org_admin`」此前**从未真正生效** —— 契约 §10 附表 A 与
  `V202608140000__init_menu_and_role_menu.sql` **一致地**把 `question:category:add / edit / remove`
  绑给了 `teacher`，于是只写 `@SaCheckPermission` 的话教师会照样通过。
  已由 `V202608200000__revoke_teacher_question_category_perms.sql` 删掉那三行绑定并订正契约附表 A；
  **不在代码里加角色门**（角色门会是全库唯一一处不同构的判定）。教师**仍可读**分类树（接口 1）。
- **为什么写操作只给 `org_admin`**：`qb_category` 是**全租户共享的目录结构**，不带 `owner_node_id`、不进 `org_resource_grant`，因此它落在"数据范围由树决定"这条规则的**管辖之外**——树能限制谁看到哪些题目，限制不了谁改分类树。若开放给 `teacher`，任一教师改一个分类名或删掉一个空分类，全机构所有人的题库目录立刻跟着变，且没有任何子树边界拦得住。教师需要新分类时走管理员申请，或把题目挂到已有分类下。
- **⚠ F-114 定案一（需方 2026-08-21）：本接口再加一道闸 —— 【仅机构根节点】（`org_node.id = tenant_id`，契约 §2.1）**，非机构根的 `org_admin` 返回 `403`。与那 18 个受管资源写接口<b>共用同一个判定</b>（`common/subtree/OrgRootGuard`），不新写一份。
  **需方的理由，原样登记**：F-114 那 18 个接口之后，分校管理员对题库**已经完全只读**（建不了题、改不了题、删不了题、停不了用）。那么他新建一个分类**放不进任何题**，改一个分类名**改的是别人题目的归类**——这是一个**残缺的权限**：只覆盖了一个完整动作的一半，剩下的只有副作用。**这类半个权限，要么补全要么去掉。**
  **一处事实修正**：删除分类**本来就有引用保护**（`30004`，分类下有子分类或题目一律拒绝），所以**只有空分类删得掉**，删不掉别人正在用的分类。真正没有保护、也确实会影响全机构的是**新建**与**改名**。收窄删除是为了三个写口一致，不是因为它会伤到别人的题。
  **读接口（接口 1）一个都不动**：分校管理员仍要按分类挑题给名下学员组卷。

- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| parentId | body | string | 是 | 父分类 ID，根节点传 "0" |
| categoryName | body | string | 是 | 分类名称，1~50 字符，同级不可重名 |
| sort | body | int | 否 | 排序号，默认 0，升序 |
| remark | body | string | 否 | 备注，最长 500 字符 |

- **请求示例**：

```json
POST /api/v1/question/categories
{
  "parentId": "1953820000000000001",
  "categoryName": "函数",
  "sort": 3,
  "remark": "高一函数专题"
}
```

- **响应示例**：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "id": "1953820000000000004"
  }
}
```

- **相关业务错误码**：无（同级重名、名称超长等返回 400 参数校验失败）。

### 1.3 修改题库分类

- **接口名**：修改题库分类
- **方法与路径**：`PUT /api/v1/question/categories/{id}`
- **权限**：**仅 `org_admin`**（理由同新增：分类树全租户共享，教师改名会影响全机构），且**仅机构根节点**（F-114 定案一，理由见 §1.2）——非机构根的 `org_admin` 返回 `403`；数据权限：仅本租户分类
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| id | path | string | 是 | 分类 ID |
| categoryName | body | string | 否 | 新名称，同级不可重名 |
| parentId | body | string | 否 | 新父节点 ID（移动分类）；不可移动到自身或其子孙节点（否则 400） |
| sort | body | int | 否 | 排序号 |
| remark | body | string | 否 | 备注 |

- **请求示例**：

```json
PUT /api/v1/question/categories/1953820000000000004
{
  "categoryName": "函数与导数",
```

## 3. 作业定义与发布（hw_homework / hw_homework_question / hw_homework_target）

### 3.1 创建作业（草稿）

- **接口名**：创建作业（草稿）
- **方法与路径**：`POST /api/v1/homework/homeworks`
- **权限**：`org_admin`、`teacher`；数据权限：写入当前租户，`create_by`=当前用户
- **版本固化规则（核心，布置时固化）**：
  - 草稿选题落库时写入的 `hw_homework_question.question_version` 仅为**暂存值**（取当时 `current_version`，供草稿预览）；**真正的版本固化发生在发布动作（3.6）事务内**——逐题重读 `qb_question.current_version` 覆盖写入完成固化（契约"布置时固化版本" / PRD F3-3 规则 3），此后题库改版不影响本作业的渲染与判卷。草稿期间题目改版，发布时自动取最新版本。
  - **选题范围（0.1 题目可见性）**：只能选入**对我可见**的题目——`owner_node_id` = 我的节点，或已显式授权给我的节点且在有效期内（`org_resource_grant`，`resource_type=2`）；**不回溯祖先链、无继承**。不可见的 `questionId` 一律按"不存在"处理返回 404（不暴露存在性）。
  - 选题必须为 `status=1`（启用）的题目，否则 30008；材料题只传**父题** `questionId`，`score` 为整道材料题总分；**子题分值可逐子题调整**（PRD F3-1 验收标准）：传 `childScores` 指定各子题分值（合计须等于 `score`，否则 400），缺省时服务端按各子题当前版本 `score_default` 占比拆分（保留 1 位小数，误差补至最后一个子题）。父题与全部子题分别写入 `hw_homework_question`（各自固化版本；父题不计分，子题行分值合计 = 父题行 `score`，不重复计入 `total_score`）。
  - `total_score` = 普通题与材料题父题行分值之和；`question_count` **按可作答题目计数：普通题各计 1，材料题按子题计数、父题不计**（对齐 PRD F3-3 规则 2）。
  - 创建后 `status=0`（草稿），草稿对学生不可见。
- **请求参数**：

| questions[].score | body | number | 是 | 该题分值，>0，保留 1 位小数（材料题为整题总分） |
| questions[].sort | body | int | 是 | 题序，从 1 起 |
| questions[].childScores | body | array | 否 | 仅材料题可传：逐子题分值 `{questionId, score}` 数组，须覆盖全部子题且合计等于该题 `score`；缺省按子题 `score_default` 占比拆分 |

### 3.6 发布作业

- **接口名**：发布作业
- **方法与路径**：`POST /api/v1/homework/homeworks/{id}/publish`
- **权限**：`org_admin`、`teacher`（均仅限本人创建的作业）
- **发布目标（全量精确到学生）**：**纯学生列表 `studentIds[]`**，附 `grantSource`（分发来源）与 `sourceRefId`。服务端不做任何二次展开，`hw_homework_target` 每生一行。
- **子树校验（唯一数据权限规则，契约 §2.4）**：`studentIds` 中的**每一个学生节点都必须在发布者子树内**——
  ```sql
  -- studentId → org_student.node_id → org_node（别名 n），逐一校验
  n.id = #{myNodeId} OR FIND_IN_SET(#{myNodeId}, n.ancestors) <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
  ```
  存在任一不满足者**整批拒绝**（不做静默过滤），返回 30011 并在 `data.invalidStudentIds` 中列出越界学员。教师的子树 = 名下学员，故教师只能发给自己名下的学生；管理员可发给其子树内任意学生（含下级管理员/教师名下的学生）。
  - 学生学籍状态必须为 `0 在读`（`org_student.status`）；名单含已退课/已归档学员返回 10203（03-02 分册登记）。
  - **前端按节点/标签/名下全体批量勾选时，须先在客户端展开为学生 ID 列表再提交**；`grantSource` 与 `sourceRefId` 仅记录"这批学生是怎么选出来的"，**不参与权限判定，也不产生任何自动展开语义**（避免服务端二次展开导致越权）。
- **发布逻辑（服务端事务内完成）**：
  1. 校验作业状态为 0(草稿) 或 3(已撤回)，否则 30010；校验 `studentIds` 非空且去重后每个学生均在发布者子树内，否则 30011；复核所有选题当前 `status=1`（启用）且对发布者可见（0.1 题目可见性），存在停用/草稿题返回 30008、存在不可见题返回 404。
  2. **版本固化（布置时固化，契约 / PRD F3-3 规则 3）**：逐题重读 `qb_question.current_version`，覆盖写入 `hw_homework_question.question_version`（材料题父题与子题各自固化）。草稿期暂存的版本值以本步为准刷新；**撤回后重新发布同样重新固化**（PRD B2/B8）。
  3. 写入 `hw_homework_target`：每个学生一行，字段 `homework_id` + `student_id` + `grant_source` + `source_ref_id`，按 `UK(homework_id, student_id)` 去重。
  4. 目标集合即 `studentIds` 去重后的结果，**服务端不做任何二次展开**。
  5. **为每个目标学生生成一条 `hw_answer_sheet`，`status=0`（未开始）**，**`teacher_node_id` 写入该生当前导师节点快照**（取代原 `class_id`）——即该生 `org_node.parent_id`，仅当父节点 `node_type=2`（教师）时写入，父节点为管理员节点时写 `null`（该生尚未分配导师）。建卷时写入的是初值，**最终固化发生在学生提交答卷时**（见 4.4 第 4 步，对齐契约 §2.6 "答卷归属以作答时刻快照为锚点"）。**重新发布（撤回后再发布）时按 PRD B41 处理已有答卷**（`UK(homework_id,student_id)`，重新发布视为新一轮任务、统计仅计最新一轮）：
     - 未提交答卷（状态 0/1）：复用原记录、保留已暂存答案，学生继续作答；
     - **已提交/已批改/逾期未交答卷（状态 2/3/4）：标记作废重考**——原 `hw_answer_detail` 明细逻辑删除（`deleted_at` 写入毫秒时间戳）保留审计，答卷复位为 `status=0`、清空 `objective_score`/`subjective_score`/`total_score`/`submit_time`/`is_late`/`grade_teacher_id`/`grade_time`，并**按当前树结构刷新 `teacher_node_id` 快照**（学生若已换导师，重考归新导师），学生须重新作答（前端在发布确认弹窗向教师明确提示影响人数）；
     - 新增命中学生补建答卷；本轮不再命中的学生，其答卷不删除、不作废，仅不参与本轮统计。
  6. 更新 `hw_homework`：`status=1`、`publish_time=now`、`deadline`、`allow_late_submit`。
  - 截止处理：`deadline` 到期后定时任务将作业置 `status=2`（已截止）；若 `allow_late_submit=0`，同时将该作业下状态 0/1 的答卷置为 4（逾期未交），**并在置 4 的同一事务内固化其 `teacher_node_id`**（契约 §2.6，见 4.4 第 4 步逾期未交分支）；若 `allow_late_submit=1`，答卷保持可补交，补交提交时标记 `is_late=1` 并在提交时固化。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| id | path | string | 是 | 作业 ID |
| studentIds | body | array&lt;string&gt; | 是 | **目标学生 ID 列表**（`org_student.id`），至少 1 个，最多 2000 个；服务端去重；每个学生必须在发布者子树内且学籍为 0 在读 |

### 3.7 撤回作业

- **请求参数**：

### 4.4 提交答卷（触发自动判卷）

- **接口名**：提交答卷
- **方法与路径**：`POST /api/v1/homework/sheets/{sheetId}/submit`
- **权限**：`student`；数据权限：仅本人答卷
- **自动判卷规则（客观题即时执行，`auto_graded=1`）**：

| 题型 | 规则 | is_correct |
| --- | --- | --- |
| 单选(1)/判断(3) | 与固化版本 `correct_answer` 完全一致得满分，否则 0 分 | 1 / 0 |
| 多选(2) | 全对得满分（is_correct=1）；漏选（所选均正确但不全）得该题分值 ×50%，四舍五入保留 1 位小数（is_correct=2）；含任一错选 0 分（is_correct=0） | 1 / 2 / 0 |
| 填空(4) | 逐空比对：去除首尾空格、英文忽略大小写，命中该空同义答案集（`accepts`）任一项即该空得分；每空分值 = 题目分值 ÷ 空数（保留 1 位小数，除不尽差额补至最后一空）。全对 is_correct=1，部分对 is_correct=2，全错 is_correct=0 | 1 / 2 / 0 |
| 简答(5)（含材料题子题） | 不自动判卷，`is_correct=NULL`、`score=NULL`，进入教师批改流水线，`auto_graded=0` | NULL |
| 材料题(6) | 父题不判卷；各子题按其题型分别适用上述规则 | — |

- **提交处理流程（事务内）**：
  1. 校验：答卷状态 2/3 返回 30003（**重复提交**）；状态 4 或（已过 `deadline` 且 `allowLateSubmit=0`）返回 30002；作业已撤回返回 30013。
  2. 若 body 带 `answers`，先按 4.3 语义落库（最终批量暂存），再判卷。
  3. 客观题逐题判分，写 `hw_answer_detail`（`is_correct`、`score`、`auto_graded=1`、`grade_time`）；未作答的客观题记 0 分（is_correct=0）。
  4. 汇总 `objective_score`；主观题置待批改（`is_correct=NULL`）。**答卷状态 → 2（已提交待批改）**，记录 `submit_time`；已过 deadline 补交则 `is_late=1`。若作业不含任何主观题，直接置状态 3（已批改），`total_score=objective_score`。
     - **导师归属快照固化（契约 §2.6）**：本步同时按提交时刻的树结构刷新并**最终固化** `hw_answer_sheet.teacher_node_id`——取该生 `org_node.parent_id`，父节点 `node_type=2`（教师）时写入该教师节点 ID，否则写 `null`（尚未分配导师）。**固化后永不回改**，学员后续换导师不影响已提交答卷的归属。
     - **同步写入 `hw_answer_detail` 的三个冗余列**：本次提交涉及的全部明细行一并写入 `student_id`、`teacher_node_id`、`submit_date`（= `submit_time` 的日期部分）。**三者必须取自本步刚固化的答卷头值，不得各自重算**——重算会让错题榜（03-05 §2.3(4)）与作业分析对同一份作答得出两个归属。这三列是错题榜的执行前提（明细表稳态 3600 万行，不冗余就只能 IN 上万个 sheet_id 全表扫），落库细节见 02-数据库设计 §4.3.8。
       - **逾期未交分支**：从未提交的答卷在定时任务将其置 `status=4`（逾期未交）时，**同样按该时刻的树结构固化 `teacher_node_id`**，此后永不回改——保证每张答卷都有确定的归属时点（提交时 或 截止置 4 时），不存在归属悬空的答卷。
       - 状态 0/1 的未提交答卷在固化发生前，`teacher_node_id` 仍为随发布/重新发布刷新的初值，不作为结算依据。
  5. **错题本联动**：客观题 `is_correct` ∈ {0, 2}（未获满分即视为做错）即写入/更新 `hw_wrong_book`——不存在则新增（`question_version` 绑定**本次作答所用的固化版本**，`first_wrong_time`、`source_homework_id`、`source_answer_detail_id`）；已存在（`UK(student_id,question_id)`）则 `wrong_count+1`、更新 `last_wrong_time` 与来源指向，且若曾标记已掌握则重置 `master_status=0`。材料题以**子题**粒度记录错题。

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| sheetId | path | string | 是 | 答卷 ID |
| answers | body | array | 否 | 提交前最终批量暂存，元素同 4.3；不传则按已暂存内容判卷 |

### 6.3 标记错题掌握状态

- **接口名**：标记错题掌握状态
- **方法与路径**：`PUT /api/v1/homework/wrong-book/{id}/master`
- **权限**：`student`；数据权限：仅本人错题
- **说明**：标记已掌握（`master_status=1`，记录 `master_time`）或撤销标记恢复未掌握（`master_status=0`，清空 `master_time`）。接口幂等：重复设置同一状态直接返回成功。已掌握的错题再次做错时由系统自动重置为未掌握（见 4.4）。错题记录不提供删除接口，仅通过掌握状态管理（软删除原则）。
- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| id | path | string | 是 | 错题记录 ID |
| masterStatus | body | int | 是 | 0未掌握 1已掌握 |

- **请求示例**：

```json
PUT /api/v1/homework/wrong-book/1954300000000000001/master
{
  "masterStatus": 1
}
```

- **响应示例**：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "id": "1954300000000000001",
    "masterStatus": 1,
    "masterTime": "2026-08-13 20:15:00"
  }
}
```

- **相关业务错误码**：无。

### 6.4 学生错题本查询（教师/管理员）

- **接口名**：学生错题本查询（教师/管理员只读）
- **方法与路径**：`GET /api/v1/homework/students/{studentId}/wrong-book`
- **权限**：`teacher` / `org_admin`（**只读**）——要求 **该学员在我的子树内**（契约 §2.4 唯一数据权限规则）：
  ```sql
  -- 目标学生节点 sn；当前用户所在节点 #{myNodeId}
  sn.id = #{myNodeId} OR FIND_IN_SET(#{myNodeId}, sn.ancestors) <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
  ```
  不满足返回 403；学生不存在或跨租户返回 404。教师的子树 = 名下学员，因此教师只能查看名下学员；管理员可查看其子树内任意学员。**学员被移出我的子树后立即失去访问权（含历史错题明细）**。学生本人查询走 6.1，本接口不对 `student` 开放。
- **说明**：教师查看**名下学员**（子树内学生）的错题本（对齐 PRD 3.2 权限矩阵、F3-8 规则 6、页面 B12）。响应结构、筛选参数与渲染规则与 6.1 完全一致（按错题绑定版本渲染 `stemPreview`）；错题明细可进一步经 6.2 查看（教师/管理员只读）。本接口只读，不提供掌握状态修改能力（6.3 仍仅限学生本人）。

- **请求参数**：

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| studentId | path | string | 是 | 学生 ID（`org_student.id`） |
| pageNum | query | int | 否 | 页码，默认 1 |
| pageSize | query | int | 否 | 每页条数，默认 10，最大 100 |
| categoryId | query | string | 否 | 题库分类（科目/知识点）ID，含子孙分类 |
| questionType | query | int | 否 | 题型：1单选 2多选 3判断 4填空 5简答 |
| masterStatus | query | int | 否 | 掌握状态：0未掌握 1已掌握；不传查全部 |

- **请求示例**：

```
GET /api/v1/homework/students/1954200998877665544/wrong-book?pageNum=1&pageSize=10&masterStatus=0
```

- **响应示例**：结构与 6.1 完全一致（`data.total` + `data.list[]`，字段同 6.1 响应示例），此处不重复展开。

- **相关业务错误码**：无（学生不存在或跨租户返回 404；学员不在本人子树内返回 403）。

## 附：本文档关键一致性说明

1. **版本链路闭环**：题库编辑 → `qb_question_version` 新增（version+1，历史不可变）→ 作业**发布时（布置时）**固化 `hw_homework_question.question_version`（草稿期仅暂存，见 3.1/3.6；重判专项任务 3.8 可迁移单题固化版本）→ 答卷明细快照 `hw_answer_detail.question_version` → 错题本绑定 `hw_wrong_book.question_version`（首次做错时刻版本）。四处版本字段同源，渲染与判卷一律以固化/绑定版本为准，与题库当前版本无关。
2. **答卷状态机**：0未开始 --(进入作答 4.2)--> 1作答中 --(提交 4.4)--> 2已提交待批改 --(全部主观题批完 5.3 / 无主观题自动)--> 3已批改；0/1 --(截止且不允许补交，定时任务)--> 4逾期未交（置 4 时固化 `teacher_node_id`）；2/3/4 --(撤回后重新发布 3.6，作废重考，PRD B8)--> 0未开始（原作答明细逻辑删除留档，统计仅计最新一轮）；3 状态答卷可在首次批改完成（`grade_time`）后 7 天内经 5.3 修正打分（状态保持 3）。
3. **作业状态机**：0草稿 --(发布 3.6)--> 1已发布 --(deadline 到期，定时任务)--> 2已截止；1已发布 --(撤回 3.7)--> 3已撤回 --(重新发布 3.6)--> 1已发布。
4. 所有写接口（1.2/1.3/1.4/2.2/2.3/2.7/2.8/3.1/3.2/3.3/3.6/3.7/3.8/5.3）由后端记录 `sys_oper_log` 操作日志，本文档不再逐一标注。
