# 03 - 课程与视频 API（course + vod）

> 本文档覆盖路由前缀 `/api/v1/course/**`（课程、章节、课时、图文资料）与 `/api/v1/vod/**`（上传凭证、媒资、转码回调、播放凭证、心跳上报、进度查询）。
>
> **课程与视频的授权（下发给某个节点/学员）不在本分册**：课程（`resource_type=1`）与视频（`resource_type=3`）统一走 `/api/v1/org/**` 的资源授权接口（表 `org_resource_grant`），由 03-02《组织机构》分册定义。本分册只定义资源本身的管理与消费，以及"我是否被授权"的判定口径。
>
> 通用约定（认证方式、响应结构、分页、时间格式、错误码总表）见 `00-通用约定.md`；本文档所有表名、字段名、枚举值、路由前缀均以 `DESIGN-CONTRACT.md` 为唯一权威。

## 0. 模块级通用说明

### 0.1 认证与多租户

- 除第 26 号「云端转码回调」外，所有接口均需请求头 `Authorization: Bearer {accessToken}`（Sa-Token JWT）。
- 所有业务数据按 `tenant_id` 自动隔离（MyBatis-Plus 租户插件注入）；**跨租户访问一律返回 HTTP 404**，不暴露资源存在性（契约 2.1）。
- 所有雪花 ID（bigint）在 JSON 中一律序列化为**字符串**；时间格式统一 `yyyy-MM-dd HH:mm:ss`（东八区）。
- `DELETE` 方法一律为逻辑删除（后端逻辑删除（`deleted_at` 写入毫秒时间戳），契约 6.1）；`vod_heartbeat_log` 等日志明细表除外（契约 2.2）。
- 分页接口统一请求参数 `pageNum`（默认 1）、`pageSize`（默认 10，最大 100），响应统一 `data: {"total": 100, "list": [...]}`。

### 0.2 角色、数据权限与资源可见性（对齐契约 §2.3 / §2.4 / §2.5）

**两条彼此独立的判定必须同时满足**：

1. **数据权限（看到哪些行）——全系统唯一一条规则（契约 §2.4）**：你能看到的数据 = 你所在节点的子树。
   ```sql
   -- org_node 别名 n，当前用户所在节点 #{myNodeId}
   n.id = #{myNodeId} OR FIND_IN_SET(#{myNodeId}, n.ancestors) <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
   ```
2. **资源可见性（能用哪些课程/视频）——逐级显式授权，无继承（契约 §2.5）**：

   > **可见 = 我的节点就是该资源的 `owner_node_id`，或该资源已被显式授权给我的节点（`org_resource_grant` 命中且当前时间在有效期内）。**

   ```sql
   -- 课程可见性判定（resource_type=1；视频同理取 3）
   c.owner_node_id = #{myNodeId}
   OR EXISTS (
       SELECT 1 FROM org_resource_grant g
        WHERE g.resource_type = 1
          AND g.resource_id   = c.id
          AND g.target_node_id = #{myNodeId}          -- 精确等于我的节点
          AND g.deleted_at = 0
          AND (g.valid_start IS NULL OR g.valid_start <= NOW())
          AND (g.valid_end   IS NULL OR g.valid_end   >= NOW())
   )
   ```

   - **不回溯祖先链、无继承**：判定只看 `target_node_id = 我的节点` 这一条命中，**绝不**用 `FIND_IN_SET` 去匹配我的任一祖先节点。上级拥有 ≠ 我自动拥有；父级授权给了我的下级也不等于授权给了我。 <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
   - **不做向下展开**：我拥有某课程，不代表我的子节点自动可用；子节点必须被显式授权（由 03-02 的授权接口逐级下发）。
   - 授权过期（`valid_end` 已过）等同未授权：列表不返回，单条访问返回 20013（学生端消费场景）。
   - 授权被撤销时按契约 §2.5 规则 5 **级联撤销目标节点整棵子树**上的同一资源授权；已产生的 `vod_watch_progress` 一律保留，仅失去继续访问权。

| 角色 | role_key | 数据范围（子树） | 本模块资源范围与权限概览 |
| --- | --- | --- | --- |
| 管理员（机构/下级，同一角色） | `org_admin` | 其节点子树全部 | 管理端全部接口；课程/媒资范围 = 本节点 `owner_node_id` 的 + 被显式授权给本节点的 |
| 教师 / 导师 | `teacher` | 其子树 = 名下学员 | 管理端接口：可管理 `owner_node_id` 为本人教师节点的课程、章节、课时、资料、媒资；对"被授权给本人节点"的课程为**只读可用**（可预览、可再下发给名下学员，下发走 03-02），不可编辑或删除 |
| 学生 | `student` | 仅自身 | 学生端与播放接口：仅可访问**显式授权给本学生节点**且在有效期内、且课程已上架的课程；进度数据仅本人 |

- **只读可用 vs 可编辑**：编辑/删除/上下架类写操作要求 `owner_node_id = 我的节点`（仅被授权者不可写，返回 403）；查询与消费类操作按上文资源可见性判定。
- 平台超管（`super_admin`）不参与本模块业务操作。
- 各接口「权限」栏在此基础上给出具体说明。

### 0.2.1 课程与视频的归属字段

- `crs_course.owner_node_id`、`vod_video.owner_node_id`：**创建时写入创建者所在节点**（`sys_user.node_id`），此后不随创建人调岗自动变更；节点被移动时资源随节点走（归属仍是该节点）。
- 响应中统一以 `ownerNodeId` / `ownerNodeName` 暴露；`ownerNodeId` 为 bigint 字符串。
- **归属唯一真相源**：课程/媒资的归属只有 `owner_node_id` 一个字段。原 `crs_course.teacher_id` 与 API 中的 `teacherId` / `teacherName` **已彻底移除**（避免归属存在两个真相源）——展示「这是谁的课」一律用 `ownerNodeId` / `ownerNodeName`；需要作者署名时用通用字段 `createBy` / `createByName`（`sys_user`）。

### 0.4 API 字段与契约表字段映射说明

- API 中 `videoId` 对应 `crs_lesson.video_id`（→ `vod_video.id`）。
- API 中 `materialId` 对应 `crs_lesson.content_id`（→ `crs_material.id`，契约字段名为 `content_id`，API 层为语义清晰使用 materialId，开发实现时按此映射，不新增表字段）。
- API 中 `coverUrl` 为服务端根据 `cover_file_id` 关联 `sys_file.file_url` 计算的展示字段，非表字段。

## 1. 课程管理（管理端）

### 1.1 课程分页列表

- **方法+路径**：`GET /api/v1/course/courses`
- **权限**：`org_admin`、`teacher`
- **数据权限（0.2 资源可见性）**：返回 **`owner_node_id` = 我的节点** 的课程 ∪ **已显式授权给我的节点且在有效期内**（`org_resource_grant`，`resource_type=1`）的课程。**不回溯祖先链、无继承**——上级节点拥有的课程若未显式授权给我，本接口不返回。响应逐行以 `grantType` 标识来源（1 自有 2 被授权）。

**请求参数（Query）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| pageNum | integer | 否 | 页码，默认 1 |
| pageSize | integer | 否 | 每页条数，默认 10，最大 100 |
| courseName | string | 否 | 课程名称，模糊匹配 |
| subject | string | 否 | 科目，精确匹配 |
| status | integer | 否 | 课程状态：0 草稿 1 已上架 2 已下架 |
| grantType | integer | 否 | 来源筛选：1 仅自有（`owner_node_id`=我的节点）2 仅被授权；不传返回两者并集 |
| ownerNodeId | string | 否 | 按归属节点精确筛选（须在本人子树内，否则 403） |

**请求示例**

```
GET /api/v1/course/courses?pageNum=1&pageSize=10&courseName=数学&status=1
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

**响应示例**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "total": 1,
    "list": [
      {
        "id": "1954101234567890001",
        "courseName": "高一数学（必修一）",
        "coverFileId": "1949600000000000021",
        "coverUrl": "https://cdn.edumatrix.cn/cover/math1.jpg",
        "subject": "数学",
        "ownerNodeId": "1952000000000000301",
        "ownerNodeName": "王建国（导师）",
        "grantType": 1,
        "status": 1,
        "lessonCount": 24,
        "totalDuration": 43200,
        "grantedNodeCount": 3,
```

**响应字段说明**：`grantType` 1 自有（`owner_node_id` = 我的节点）/ 2 被授权（`org_resource_grant` 命中）；`grantedNodeCount` 为该课程当前有效授权的目标节点数（仅 `grantType=1` 的行返回真实值，被授权行返回 `null`——**下级不得窥探同级/上级的授权面**）。

### 1.3 创建课程

- **方法+路径**：`POST /api/v1/course/courses`
- **权限**：`org_admin`、`teacher`
- **说明**：
  - 新建课程初始 `status=0`（草稿）；`lesson_count`、`total_duration` 为冗余字段，由课时变更时自动重算，创建时置 0。
  - **`owner_node_id` 由服务端强制写入创建者所在节点（`sys_user.node_id`），请求体不接受该参数**（传入即忽略）。创建后课程仅对该节点可见；要让下级使用，须经 03-02 的资源授权接口显式下发（无继承）。
  - **不接受 `teacherId` 参数**：课程归属唯一由 `owner_node_id` 表示；创建人以通用字段 `create_by` 记录。

**请求参数（Body，application/json）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| courseName | string | 是 | 课程名称，1~100 字符 |
| coverFileId | string | 否 | 封面文件 ID（`sys_file.id`，先经文件上传接口获得） |
| subject | string | 否 | 科目，最长 50 字符 |
| description | string | 否 | 课程简介，最长 2000 字符 |
| remark | string | 否 | 备注，最长 500 字符 |

**请求示例**

```json
{
  "courseName": "高一数学（必修一）",
  "coverFileId": "1949600000000000021",
  "subject": "数学",
  "description": "覆盖人教A版必修一全部章节，含例题精讲与同步练习。",
  "remark": "秋季学期主线课程"
}
```

**响应示例**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "id": "1954101234567890001"
  }
}
```

**相关业务错误码**：无（仅通用 400/401/403）。

### 1.4 修改课程

- **方法+路径**：`PUT /api/v1/course/courses/{id}`
- **权限**：`org_admin`、`teacher`；**写操作要求 `owner_node_id` = 我的节点**（仅被授权而非拥有者时返回 403）
- **说明**：仅修改课程基本信息，不涉及状态流转（上下架走 1.6）。已上架课程允许修改基本信息，实时生效。`ownerNodeId` **不可通过本接口变更**（归属转移属组织操作，走 03-02）。

**请求参数**

| 参数 | 类型 | 必填 | 说明 |

### 2.5 章节拖拽排序

### 7.1 获取视频上传凭证

- **方法+路径**：`POST /api/v1/vod/videos/upload-token`
- **权限**：`org_admin`、`teacher`
- **流程说明（客户端直传，视频流量不过应用服务器）**：
  1. 服务端预创建 `vod_video` 记录（`status=0` 上传中，`upload_user_id=当前用户`），并向云厂商申请一次性上传凭证。
  2. **provider 差异**：
     - `provider=1`（腾讯云）：返回 `credential.signature`（客户端上传签名）。前端使用腾讯云 `TcVod` Web SDK 携带该签名直传；云端 `FileId` 在上传完成回调（7.2）中写回 `vod_file_id`。
     - `provider=2`（阿里云）：返回 `credential.uploadAuth` + `credential.uploadAddress` + `credential.cloudVideoId`（阿里云 VideoId）。前端使用阿里云 `AliyunUpload` SDK 直传；`cloudVideoId` 在发放凭证时即已写入 `vod_file_id`。
  3. 上传完成后云端自动触发加密 HLS 转码任务（`.m3u8`），状态经回调流转：0 上传中 → 1 转码中 → 2 正常 / 3 转码失败。
  4. 凭证有效期 3600s；过期未完成上传可重新调用本接口（传入 `videoId` 续签，不新建媒资记录）。续签允许的媒资状态为 `status∈{0,3}`：`0` 上传中（凭证过期重传）与 `3` 转码失败（**重传源文件**，对齐 PRD F2-3 规则 3；重传成功走回调重新流转 0→1→2/3）。

**请求参数（Body）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| videoName | string | 是 | 媒资名称，1~200 字符 |

| videoId | string | 否 | 续签/重传场景传入已有媒资 ID（`status∈{0,3}` 时有效） |

### 7.2 云端转码回调

- **方法+路径**：`POST /api/v1/vod/callback/{provider}`
- **权限**：**免登录**（云厂商服务端调用，无 Authorization 头），以**回调签名校验**代替身份认证；接口仅在网关层对云厂商回调出口 IP 段放行。
- **签名校验（防伪造/防重放）**：
  - `tencent`：按腾讯云 VOD 事件通知签名规范校验——使用控制台配置的回调密钥，对「时间戳 + 原始请求体」计算 HMAC-SHA256，与请求头中云端携带的签名比对；时间戳与服务器时间偏差超过 300s 拒绝（防重放）。
  - `aliyun`：按阿里云 VOD 事件通知校验规范——校验回调请求携带的加密 Token / 公钥签名；同样执行 300s 时间窗校验。
  - 校验失败返回 `code=20017`，**不处理任何业务**，并记录告警日志；云端会按其重试策略重发。
- **事件处理（适配层将两家云的报文归一为内部事件后处理）**：

| 内部事件 | 腾讯云事件 | 阿里云事件 | 处理动作 |
| --- | --- | --- | --- |
| 上传完成 | NewFileUpload | UploadComplete | 按凭证关联找到 `vod_video`，写入 `vod_file_id`（腾讯 FileId），`status` 0→1（转码中） |
| 转码成功 | ProcedureStateChanged(FINISH) | StreamTranscodeComplete | `status` 1→2（正常），写入 `hls_url`（加密 m3u8 地址）、`duration`（秒）、`cover_url`、`size_bytes`；同步刷新引用该视频课时的 `duration` 冗余及课程 `total_duration` |
| 转码失败 | ProcedureStateChanged(FAIL) | TranscodeComplete(fail) | `status` 1→3（转码失败），失败原因写入 `remark` |

- **幂等**：以 `vod_file_id + 事件类型` 幂等去重，重复回调直接返回成功。

**请求参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| provider | string(Path) | 是 | 云厂商标识：`tencent`（对应 vod_video.provider=1）/ `aliyun`（对应 2） |
| （Body） | object | 是 | 云厂商原始回调报文，两家结构不同，由适配层解析 |

**请求示例（腾讯云·转码完成，报文节选）**

```json
{
  "EventType": "ProcedureStateChanged",
  "ProcedureStateChangeEvent": {
    "TaskId": "1400000000-procedurev2-9d2f...",
    "Status": "FINISH",
    "FileId": "387702299774545813",
    "MediaProcessResultSet": [
      {
        "Type": "Transcode",
        "TranscodeTask": {
          "Status": "SUCCESS",
          "Output": {
            "Url": "https://1305000001.vod-qcloud.com/vod/387702299774545813/adp.10.m3u8",
            "Duration": 2143.5,
            "Size": 734003200
          }
        }
      }
    ]
  }
}
```

**响应示例（校验与处理成功）**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": null
}
```

**失败响应示例（签名校验失败）**

```json
{
  "code": 20017,
  "msg": "回调签名校验失败",
  "data": null
}
```

**相关业务错误码**：20015（回调报文中的云端文件 ID 找不到对应媒资记录）、20017。

## 8. 播放与防刷（重点）

> 设计目标（对齐原始需求模块 2）：加密 HLS + 时效播放凭证防盗链；**禁用向前拖拽**（仅允许回看已看部分）；**跑马灯水印**（姓名 + 手机号）防录屏传播；**心跳上报 + 服务端防刷校验**保证「已看时长」真实可信；高频写走 Redis 缓冲异步落盘（原始需求第四节）。

### 8.1 获取播放凭证

- **方法+路径**：`POST /api/v1/vod/play-auth`
- **权限**：`student`（本人播放）；`org_admin` / `teacher` 管理端预览时同样调用本接口（跳过第 2 步的学生授权校验，改按 0.2 资源可见性校验该课程自有或被授权；预览产生的心跳不计入任何学生进度，服务端按 user_type 直接丢弃）
- **服务端校验链（按序执行，任一失败即终止；本链路其余环节口径不变）**：
  1. 课时校验：`lessonId` 对应课时存在、未删除、`status=1` 可见、`lesson_type=1` 视频，否则返回 20014；
  2. **授权校验（学生）**：**该学生节点被授权该课程且在有效期内**——`org_resource_grant` 存在 `resource_type=1 AND resource_id=课程ID AND target_node_id=本学生节点ID AND deleted_at=0`，且当前时间 ∈ [`valid_start`, `valid_end`]（`valid_end` 为 NULL 视为永久），且课程 `status=1` 已上架；**判定不回溯祖先链**（授权给其导师/管理员节点不算数），任一不满足返回 20013；
  3. 视频校验：关联 `vod_video` 存在且 `status=2` 正常——`status∈{0,1}` 返回 20003（转码未完成），`status∈{3,9}` 返回 20015。
- **响应内容与生成规则**：

| 字段 | 生成规则 |
| --- | --- |
| authToken | 32 位随机凭证（UUID 去横线），绑定 studentId + lessonId，Redis 存储，TTL 300s；心跳请求头 `X-Play-Token` 携带 |
| playUrl | 加密 HLS（`.m3u8`）播放地址，附带云厂商时效防盗链签名（腾讯云：Key 防盗链 `t`/`sign` 参数；阿里云：URL 鉴权 `auth_key` 参数），签名有效期与 authExpire 一致 |
| authExpire | 凭证有效秒数，固定 300 |
| maxPosition | 允许拖拽上限（秒）= 本人历史最远触达位置（`vod_watch_progress.max_position` 与 Redis 缓冲取较大值）；仅随正常播放推进，`watchStatus=2`（已完成）后**同样**按真实 max_position 限制拖拽，不解除禁快进（对齐 PRD F2-5 规则 2 与 02-数据库设计 §4.2.7 max_position 说明） |
| watermark.text | 跑马灯水印文本 = 学生「真实姓名 + 手机号」（用于录屏溯源，例：`李子墨 13812345678`），取自 `sys_user.real_name` / `sys_user.phone`。手机号是否脱敏读取租户配置「水印脱敏」（A16 系统设置，配置键 `watermark_phone_mask`）：**默认不脱敏**（完整手机号，强化威慑）；租户开启脱敏后中间四位打星（例：`李子墨 138****5678`）。对齐 PRD F2-6 规则 1 |
| watermark.interval | 水印随机位置刷新间隔（秒），服务端每次在 **8~15** 间随机下发（对齐 PRD F2-6 规则 2），前端每 interval 秒将水印移动到画面随机位置（随机落点覆盖九宫格全部区域），避免固定规律被遮挡工具识别 |
| watchedDuration / watchStatus | 本人当前进度快照（合并 Redis），供播放器续播定位与 UI 展示 |

- **审计**：每次成功发放，同步写 `vod_play_auth_log`（`viewer_user_id` = 当前账号、`viewer_type` = 其 `user_type`、`lesson_id`、`video_id`、`auth_token`、`expire_time`、`client_ip`）。**`student_id` 仅 `viewer_type=3` 时写入**，管理端预览留 NULL——教师与管理员没有 `org_student` 档案行。管理端预览**同样必须落审计**：能看到全机构课程的人批量取证，正是最需要留痕的场景。
- **续签**：凭证 300s 过期后，播放器在心跳收到 20001 时**无感重调**本接口换取新 authToken 与新 playUrl，不打断播放。

**请求参数（Body）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| lessonId | string | 是 | 课时 ID（视频类型） |

**请求示例**

```json
{
  "lessonId": "1954103000000000002"
}
```

**响应示例**

```json
{
  "code": 200,
  "msg": "操作成功",
```

### 8.2 播放心跳上报

- **方法+路径**：`POST /api/v1/vod/heartbeat`
- **权限**：`student`（仅累计本人进度）
- **签名**：本接口为全系统最高频接口，请求体与响应体签名与契约 6.4 **完全一致**，任何字段不得增删改名。
- **上报频率**：播放器每 10s 上报一次（原始需求）；暂停时停止上报，恢复播放后继续。
- **请求头**：除 `Authorization` 外，须携带 `X-Play-Token: {authToken}`（8.1 发放，300s 有效）。

**请求参数（Body，契约 6.4 固定签名）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| lessonId | string | 是 | 课时 ID |
| videoId | string | 是 | 媒资 ID（`vod_video.id`），须与课时当前关联一致 |
| currentTime | number | 是 | 当前播放位置（秒，允许一位小数） |
| duration | number | 是 | 播放器读取的视频总时长（秒） |
| playRate | number | 是 | 当前倍速（0.5~3.0） |

**请求示例**

```json
{
  "lessonId": "1954103000000000002",
  "videoId": "1954200000000000002",
  "currentTime": 123.4,
  "duration": 600,
  "playRate": 1.0
}
```

**响应示例（有效心跳，契约 6.4 固定签名）**

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "watchedDuration": 130,
    "watchStatus": 1,
    "maxPosition": 135
  }
}
```

#### 8.2.1 服务端八条校验规则（防刷核心，必须全部实现）

| # | 规则 | 判定与处理 |
| --- | --- | --- |
| 1 | **凭证有效** | `X-Play-Token` 必须存在、未过期（TTL 300s）、且 Redis 中绑定的 studentId/lessonId 与本次请求一致；不通过返回 **20001**，客户端无感调 8.1 续签后重试本次心跳 |
| 2 | **间隔校验** | 取与上一次**有效**心跳的服务端接收时间差 Δt（首次心跳以凭证发放时间为锚点）：Δt < 8s 判为异常（脚本高频刷时长），走规则 5；Δt ≥ 8s 有效，本次**单次计入 `min(Δt, 15)` 秒**——8~15s 为正常窗口全额计入，超过 15s 的部分视为暂停/切后台，不计入（防止挂机刷时长） |
| 3 | **拖拽校验** | `currentTime` 不得超过 `maxPosition + 15`（15s 为单周期最大合法推进量）；超出视为绕过前端「禁用快进」的非法拖拽或报文篡改，走规则 5。校验通过后更新 `maxPosition = max(maxPosition, currentTime)` |
| 4 | **倍速不加速累计** | `playRate > 1` 时**不加速累计**：`watchedDuration` 增量只按规则 2 的服务端墙钟间隔计算，与 playRate 无关——2 倍速看 10s 仍只计 10s（防倍速刷完播）；playRate 仅落 `vod_heartbeat_log` 供行为分析 |
| 5 | **异常心跳丢弃** | 凡未通过规则 2/3，或参数明显非法（`currentTime<0`、`currentTime>duration+2`（合法区间 [0, duration+2]，对齐 PRD F2-7 规则 6）、`duration` 与媒资 `vod_video.duration` 偏差 >5%、`playRate` 超出 0.5~3.0 等），一律**丢弃不计入**，明细仍写 `vod_heartbeat_log` 备查（interval_sec 记实际值），返回 **code=20002** |

| 6 | **推进一致性**（挂机/纯脚本防护） | 有效心跳的位置推进量必须与墙钟一致：`Δ currentTime` 须落在 `[0.5, 1.5] × Δt × playRate` 区间。长期零推进（连续 5 次 `Δ currentTime ≈ 0` 而 `Δt` 正常）判定为**挂机或纯脚本上报**——只记 `vod_heartbeat_log` 留痕、**不计入 `watchedDuration`**，并累加风控分。<br>不设此条时，脚本无需下载任何视频分片、仅按 10s 节奏发包即可 1:1 墙钟速度刷满时长，挂机成本≈0 |
| 7 | **并发课时数上限** | 单学生**同一时刻活跃课时数 ≤ 2**（活跃 = 60s 内有有效心跳）。超出的课时心跳直接丢弃并计风控分。<br>原有的并发防护只作用在"同一课时"（Redis key 含 lessonId），**跨课时并行完全不受限**——20 个课时并行的脚本一晚可刷完整门课程，这是防刷模型此前最大的缺口 |
| 8 | **时长封顶** | 单学生**单日** `watchedDuration` 累计上限 10 小时、**单课时**累计上限 `duration × 3`。超出部分只记录不计入完播判定，并触发风控标记供机构核查 |

> 规则 6~8 的阈值（`[0.5,1.5]` 区间、活跃课时数 2、单日 10h、单课时 3 倍）为平台级默认值，不属于租户配置键；调整需修订本文档与 PRD F2-7。

**异常心跳响应示例**

```json
{
  "code": 20002,
  "msg": "心跳间隔异常，本次已丢弃",
  "data": null
}
```

#### 8.2.2 Redis 缓冲 + 批量落盘（对齐契约 6.4 与原始需求第四节）

1. 有效心跳**只写 Redis，不直接写库**：`key = vod:hb:{studentId}:{lessonId}`（Hash：watchedDuration / maxPosition / watchStatus / lastHeartbeatTime / videoId / courseId，TTL 24h），并将 key 加入脏集合 `vod:hb:dirty`。
2. **XXL-Job 每 60s** 扫描脏集合，批量 UPSERT `vod_watch_progress`（UK student_id + lesson_id），心跳明细批量插入 `vod_heartbeat_log`（按月分区，允许归档清理）；落盘成功后移出脏集合。极端情况下（实例宕机）最多丢失 60s 内的增量，可接受。
3. **完播判定在第 2 步 XXL-Job 落盘时执行**（唯一判定时机，对齐 PRD F2-9 规则 1 / F2-7 规则 7 与 02-数据库设计 §4.2.7）：逐条比较 `watchedDuration ≥ duration × complete_rate_threshold`（租户级配置，默认 90%，契约第 5 节）→ 回填 `watch_status = 2`、记 `complete_time`，并同步刷新 Redis 缓冲中的 `watchStatus`；状态单向流转（0→1→2），不回退。心跳响应中的 `watchStatus` 回传 Redis 缓冲当前值，因此从达到阈值到状态翻转最长有 60s（一个落盘周期）延迟，前端不得据此做完播弹窗以外的强依赖。`maxPosition` 始终只由 8.2.1 规则 3 按 `max(maxPosition, currentTime)` 推进，**完播后不解除拖拽限制**（对齐 PRD F2-5 规则 2 与 02-数据库设计 3.2.9）。
4. 所有进度查询接口（6.1、6.2、8.3、8.4）读取时合并 Redis 缓冲与 DB，取较大值，保证准实时。

#### 8.2.3 客户端降级策略

- 收到 **20002**：**静默降级**——不弹窗、不打断播放、不回退进度条，丢弃本次结果，按原 10s 周期继续上报；连续 3 次及以上 20002 时前端仅上报监控埋点。
- 收到 **20001**：无感调用 8.1 续签凭证后继续上报，播放不中断。
- 网络失败：本次心跳直接丢弃，不做本地补偿重发（防止补发报文被规则 2 判异常），下个周期正常上报。

**相关业务错误码**：20001、20002、20014（课时被删除或隐藏后仍在上报）。

## 附：本模块状态机速查

**课程 `crs_course.status`**：0 草稿 →（上架）→ 1 已上架 ↔（下架/再上架）↔ 2 已下架；仅 0/2 可删除。

**媒资 `vod_video.status`**：0 上传中 →（上传完成回调）→ 1 转码中 →（转码回调）→ 2 正常 / 3 转码失败；3 →（接口 33 重新转码 / 接口 25 重传源文件）→ 1；2 ↔ 9 禁用/启用经接口 34 人工操作；仅 2 可挂课时、可发放播放凭证。

**完播 `vod_watch_progress.watch_status`**：视频课时 0 未开始 →（首个有效心跳）→ 1 学习中 →（落盘时判定 watched_duration ≥ duration × 90%，阈值租户可配 `complete_rate_threshold`）→ 2 已完成；**图文课时首次成功访问直接 0 → 2（不经过 1，见 §6.3）**。单向流转不回退。
