> 本文档覆盖数据中心模块全部接口：导师看板、单次作业分析、机构/节点大屏、学员学习档案、报表导出任务。
> 通用约定（认证方式、响应结构、分页、通用错误码）见《00-通用约定.md》，本文不再重复。

## 2. 指标口径（权威计算公式）

本节为数据中心全部指标的唯一计算口径，前后端与报表实现必须与此一致。指标与契约 §4 `stat_` 表字段的对应关系一并标注。

### 2.1 数据生成链路

- `stat_student_daily`（学生日学习汇总，**唯一原始事实表**）由 XXL-Job 定时任务**每日凌晨 00:30 结算前一日（T-1）数据**；结算时同步写入两个归属快照字段 `teacher_node_id`（结算时刻父节点若为教师节点则写入其 ID，否则为 NULL）与 `node_id`（结算时刻所在节点 ID）。
- `stat_teacher_daily` / `stat_node_daily` 由 `stat_student_daily` 按上述两个快照字段**二次上卷**生成，**不存在第二份原始数据**（契约 §4 统计架构）。其中 **`stat_node_daily` 每行的值 = 该节点整棵子树内全部学员的汇总**（契约 §4），读某节点大屏只需 **1 行命中**，无需扫描子树全部节点。
- **已结算的 `stat_student_daily` 行永不重算**（契约 §2.6）。同一 `stat_date` 的重跑仅对**尚未结算过**的日期生效；对已有行的重跑为幂等空操作，不因学员事后转导师而回填改写。
- **当日（T 日）指标**（如"今日活跃"、看板区间末点）不读 `stat_` 表，由服务端**实时聚合**：Redis 心跳缓冲（`vod:hb:{studentId}:{lessonId}`）已落盘部分 + `vod_watch_progress.last_heartbeat_time` + 当日 `hw_answer_sheet.submit_time`，归属**按当前树结构判定**。
- 高频错题、单次作业分析、学员档案中的明细类指标不预聚合，实时查询 `hw_`、`vod_` 明细表并做短时缓存（Redis 5 分钟）。

#### 2.1.1 统计表铁律：存分子分母，不只存比率（契约 §4）

> 比率不可跨天平均：**`AVG(日比率) ≠ 区间真实比率`**。跨日期区间的指标**按列语义分两类取值，不可一律 `Σ分子 ÷ Σ分母`**（见下表）：**累计状态型**（`finished_lesson_count` / `should_lesson_count`）取**区间末日一行**相除，严禁跨天求和；**当日流量型**（`*_submit_count`、`watch_seconds`）才用 `Σ分子 ÷ Σ分母`。各日汇总表冗余的 `avg_complete_rate` / `ontime_submit_rate` 列**仅供"单日"直读**（趋势折线的每个点），**禁止用于区间聚合**。

三张日汇总表为此提供的分子分母列：

| 表 | 完播率分子 / 分母 | 提交率分子 / 分母 | 其他 |
| --- | --- | --- | --- |
| `stat_student_daily` | `finished_lesson_count` / `should_lesson_count` | `ontime_submit_count` / `should_submit_count` | `late_submit_count`、`is_active`(0否1是)、`watch_seconds` |
| `stat_teacher_daily` | `finished_lesson_count` / `should_lesson_count` | `ontime_submit_count` / `should_submit_count` | `student_count`、`active_student_count`、两个派生 rate 列 |
| `stat_node_daily` | `finished_lesson_count` / `should_lesson_count` | `ontime_submit_count` / `should_submit_count` | `student_count`、`active_student_count`、两个派生 rate 列 |

**两类指标的区间聚合方式必须区分**（两者都不违反铁律——铁律禁止的是 `AVG(日比率)`）：

| 指标类型 | 分子分母语义 | 区间值取法 | 本模块指标 |
| --- | --- | --- | --- |
| **累计状态型** | 分子分母均为**截至该统计日的累计快照**（非当日增量） | **取区间末日一行**的 `分子 ÷ 分母`；跨日求和会把同一门课时重复计数，**禁止 Σ** | 完播率（`finished_lesson_count` / `should_lesson_count`） |
| **当日流量型** | 分子分母均为**当日新增量** | `Σ分子 ÷ Σ分母`（区间内逐日求和后相除） | 按时提交率（`ontime_submit_count` / `should_submit_count`）、学习时长（`watch_seconds`） |

- 活跃学员数为**去重计数型**：`is_active` / `active_student_count` 可按天求和得到"活跃人日"，但**不能**求和得到"区间活跃人数"（需按 `student_id` 跨日去重）。
- 本模块所有返回比率的接口，**必须同时返回该比率的分子与分母**（如 `shouldSubmitCount` / `ontimeSubmitCount`、`shouldLessonCount` / `finishedLessonCount`），使前端与对账方可独立复核，且不必反推口径。

### 2.2 统计范围的两种定义（分母的来源）

所有"平均值/比率"类指标的分母只有以下两种取法，接口文档中逐一标注采用哪一种：

| 范围类型 | 定义 | SQL 判定 |
| --- | --- | --- |
| **名下学员**（导师维度） | 某教师节点的**直接子节点**中 `node_type = 3` 且 `org_student.status = 0`（在读）的学员 | `n.parent_id = #{teacherNodeId} AND n.node_type = 3` |
| **节点子树内学员**（组织维度） | 某节点自身及其全部后代中 `node_type = 3` 且 `org_student.status = 0` 的学员 | `n.node_type = 3 AND (n.id = #{nodeId} OR FIND_IN_SET(#{nodeId}, n.ancestors))` | <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>

- 已退课（`org_student.status = 1`）与已毕业归档（`status = 2`）的学员**不进入任何分母**；其历史日汇总行保留不追改（契约 §2.6"已结算行永不重算"）。
- 两种范围均以契约 §2.4 的唯一数据权限规则为前提：**调用者只能把统计范围限定在自己所在节点的子树之内**，任何显式传入的 `nodeId` / `teacherNodeId` 都必须先通过子树校验（详见 2.5）。

### 2.3 各指标计算公式

#### （1）单课时完播判定（基础口径）

- 依据 `vod_watch_progress`：`watched_duration`（墙钟有效累计观看秒数，复看计入）、`watch_status`（0未开始 1学习中 2已完成）。
- 完播判定：`watched_duration >= crs_lesson.duration × 90%` 时置 `watch_status = 2`（阈值 90% 为租户级配置项，配置键 `complete_rate_threshold`，合法范围 60~100）。判定时机为 XXL-Job 落盘时（唯一判定时机，契约 §5）。
- **统计范围仅限视频课时**（`crs_lesson.lesson_type = 1` 且 `status = 1` 可见且 `deleted_at = 0`）；图文课时（`lesson_type = 2`）不计入完播率与学习时长类指标（**课程进度百分比除外**，其分母含图文课时，见 (7)）。

#### （2）学员完播率与平均完播率（`stat_teacher_daily.avg_complete_rate` / `stat_node_daily.avg_complete_rate`）

完播率为 2.1.1 定义的**累计状态型**指标，分子分母均落在日汇总表上，逐层直接相加：

```
【学员级，stat_student_daily】
finished_lesson_count(i) = 截至该统计日，该生 watch_status = 2 的视频课时数
should_lesson_count(i)   = 截至该统计日，该生的应学视频课时总数
                         = 经 org_resource_grant 授权给【该学员本人节点】的课程
                           （resource_type = 1、target_node_id = 该生 org_node.id、
                             统计日落在 valid_start ~ valid_end 内，valid_end 为空视为永久）
                           下，符合 (1) 统计范围的课时数
学员完播率(i)             = finished_lesson_count(i) ÷ should_lesson_count(i) × 100

【导师级，stat_teacher_daily】—— 分母范围 = 2.2「名下学员」
finished_lesson_count = Σ 名下学员 finished_lesson_count(i)
should_lesson_count   = Σ 名下学员 should_lesson_count(i)
avg_complete_rate     = finished_lesson_count ÷ should_lesson_count × 100

【节点级，stat_node_daily】—— 分母范围 = 2.2「节点子树内学员」（本表行即子树聚合）
finished_lesson_count = Σ 子树内学员 finished_lesson_count(i)
should_lesson_count   = Σ 子树内学员 should_lesson_count(i)
avg_complete_rate     = finished_lesson_count ÷ should_lesson_count × 100
```

- **区间取法（2.1.1 铁律）**：完播率是**累计状态量**，区间值 = **区间末日一行**的 `finished_lesson_count ÷ should_lesson_count`，**不得跨日 Σ**（同一门课时会被重复计入）。`avg_complete_rate` 列仅供趋势折线的**单日直读**。
- **口径说明**：本指标为"**先汇总分子分母、再相除**"（课时数加权）。理由：算术平均会让应学 5 个课时的学员与应学 200 个课时的学员等权，且与"分子分母各自汇总再相除"的原则不自洽。前端不得再用 `Σ学员比率 ÷ 人数` 复核本字段。
- **授权判定不回溯祖先链**（契约 §2.5 规则 4）：资源逐级显式下发，学员的应学课时只由授权给"该学员本人节点"的课程决定；其导师或上级管理员被授予但未再下发给该生的课程，**不计入该生分母**。
- **`stat_node_daily` 的父子行不可相加**（契约 §4）：父节点行**已包含**其全部后代的数据，`父行 + 子行` 会双计。同层**兄弟**节点的行互不重叠、可以相加，但其和**不等于**父行（差额为直挂父节点、不属于任何下级节点的学员）。跨节点汇总时只能取**最近公共祖先**的那一行。
- 结果 0~100，保留两位小数。**除零兜底**：`should_lesson_count = 0` 时比率记 0，前端展示为"—"，不得展示为 0%。
- 末日（今日）为 2.1 所述实时口径。

#### （3）作业按时提交率（`stat_teacher_daily.ontime_submit_rate` / `stat_node_daily.ontime_submit_rate`）

按时提交率为 2.1.1 定义的**当日流量型**指标，分子分母按自然日落在日汇总表上，区间值直接 `Σ分子 ÷ Σ分母`：

```
【学员级，stat_student_daily —— 结算时按"当日到期作业"计算】
当日到期作业集 = deadline 落在该统计日内、hw_homework.status IN (1已发布, 2已截止)、
                且 hw_homework_target.student_id = 该生 的作业
should_submit_count(i) = 该生当日到期作业份数（应交）
ontime_submit_count(i) = 其中 hw_answer_sheet.status IN (2,3) 且 is_late = 0
                        （submit_time ≤ deadline）的份数
late_submit_count(i)   = 其中已提交但 is_late = 1 的份数
                        （未交 = should_submit_count − ontime_submit_count − late_submit_count）

【导师级 / 节点级，stat_teacher_daily / stat_node_daily】
should_submit_count = Σ 范围内学员 should_submit_count(i)     （导师=名下学员；节点=子树内学员）
ontime_submit_count = Σ 范围内学员 ontime_submit_count(i)
ontime_submit_rate  = ontime_submit_count ÷ should_submit_count × 100   （仅当日直读）

【区间值（看板/大屏）】
区间按时提交率 = Σ(区间内逐日 ontime_submit_count) ÷ Σ(区间内逐日 should_submit_count) × 100
```

- **区间聚合直接读日汇总表**：由于分子分母已随结算落表，区间值只需对 `stat_teacher_daily` / `stat_node_daily` 的两列按 `stat_date` 范围求和后相除，**无需回 `hw_answer_sheet` / `hw_homework_target` 明细表实时聚合**。逐日 `ontime_submit_rate` 列仅供趋势折线的**单日直读**，**禁止**用它做区间平均（2.1.1 铁律）。
- **归属在结算时刻一次固化**：结算任务写 `stat_student_daily` 时，按当日的 `teacher_node_id` / `node_id` 快照归属该行；上卷时分子分母同行同源，天然对齐，不会出现"有提交无应交"。因此读侧**不需要**再按作业 `deadline` 回溯学员当时的归属。
- `hw_answer_sheet.teacher_node_id`（作答时刻快照）仍用于 4.2 单次作业分析等**按单份作业实时聚合**的场景；日汇总链路不依赖它。
- **除零兜底**：`should_submit_count = 0` 时比率记 0，前端展示为"—"（趋势图中当日无到期作业即为此情形，折线应断点而非落到 0）。注意 `Σ` 时这些 0/0 的日子对分子分母均贡献 0，不会污染区间值。
- 接口响应同时返回 `shouldSubmitCount`（应交人次）与 `ontimeSubmitCount`（按时提交人次），趋势数组的每个点亦返回该日的两个计数，便于前端独立复核区间值。

#### （4）高频错题（实时聚合，不落 `stat_` 表）

```
统计范围（导师维度）= hw_answer_detail.teacher_node_id = 该教师节点，且 submit_date 落在统计区间内
                     （submit_date 非空即等价于答卷 status ∈ {2,3}，无需回 hw_answer_sheet 判状态）
统计范围（节点维度）= hw_answer_detail.student_id ∈ 节点子树内学员集，其余条件同上

作答人数   = COUNT(DISTINCT student_id)，仅计 is_correct 非 NULL 的作答（待批改不计入分母）
错误人数   = COUNT(DISTINCT student_id)，其中 is_correct = 0（全错；半对 2 不计入错误）
错误率     = 错误人数 ÷ 作答人数 × 100
漏选人数   = COUNT(DISTINCT student_id)，其中 is_correct = 2（半对：多选漏选 / 填空部分正确）
漏选率     = 漏选人数 ÷ 作答人数 × 100
未掌握人数 = 错误人数 + 漏选人数（榜单入选与排序依据，不对外单独展示为指标）
```

> **三态口径（全局唯一定义，对齐契约 §5）**：同一分母（作答人数）下，`is_correct` 的三个取值互斥且完备，因此 **正确率 + 漏选率 + 错误率 = 100%**。
> 半对**不计入错误率**——多选漏选、填空部分正确属于"部分掌握"，与完全答错的教学含义不同，独立成"漏选率"一档呈现，便于导师区分"没学会"与"学得不牢"。
> 该口径同时适用于 4.1 高频错题榜与 4.2 单次作业分析，两处不得各自解释。
> 百分比按未舍入值满足上述恒等式，取两位小数后可能出现 ±0.01 的舍入偏差，前端**不得**以三率之和是否恰为 100.00 作为数据校验条件。

- 材料题（`question_type = 6` 父题）按**子题**（`qb_question.parent_id ≠ 0`）逐题统计，父题本身不参与。
- Top10 排序：**未掌握人数**（错误人数 + 漏选人数）降序 → 错误人数降序 → question_id 升序；题目摘要取 `qb_question.stem_preview`。

**执行路径（必须按此实现，否则看板首屏 2s 达不到）**：

导师维度直接查 `hw_answer_detail`，**不 join `hw_answer_sheet`**：

```sql
SELECT question_id,
       COUNT(DISTINCT student_id)                                      AS answered,
       COUNT(DISTINCT CASE WHEN is_correct = 0 THEN student_id END)    AS wrong,
       COUNT(DISTINCT CASE WHEN is_correct = 2 THEN student_id END)    AS partial
  FROM hw_answer_detail
 WHERE teacher_node_id = #{teacherNodeId}
   AND submit_date BETWEEN #{startDate} AND #{endDate}
   AND is_correct IS NOT NULL          -- 待批改不进分母
   AND deleted_at = 0
 GROUP BY question_id;
```

`idx_teacher_date_question(teacher_node_id, deleted_at, submit_date, question_id, is_correct, student_id)` 使本查询**全程走覆盖索引、不回表**（`EXPLAIN` 为 `Using index`）：两个等值列定位 → 范围裁剪日期 → 索引内完成分组与去重计数。`deleted_at` 必须在索引里，否则每行都要回表校验软删标记、覆盖失效。取到 Top10 后再按 `question_id` 回查 `qb_question.stem_preview` 补题面（10 行点查）。

`teacher_node_id` / `submit_date` / `student_id` 是本表的**冗余列**，在答卷提交时与 `hw_answer_sheet` 同源同时刻写入（契约 §4 / 02-数据库设计 §4.3.8）。**不要退回"先从答卷头捞 sheet_id 再 IN 查明细"的写法**——该表稳态 3600 万行，`idx_teacher_node_homework` 又不含 `submit_time`，那条路径会先拿到上万个 sheet_id 再去 IN，正是这三列要消除的东西。

节点维度把第一个条件换成 `student_id IN (子树内学员集)`，其余不变；子树学员集按契约 §2.4 的选路表取得，**不要内联 `FIND_IN_SET`**。
  排序用"未掌握人数"而非"错误人数"，是为避免一类盲区：**普遍漏选**的多选题（错误人数为 0、漏选人数极高）在只按错误人数排序时永远进不了榜，导师会误判该题已被全员掌握。
- **聚合值与下钻明细的范围不同**（重要，直接适用**契约 §2.6"数能算进去，人看不见"边界裁决表**）：
  - **聚合数值**（本榜单的 `answerStudentCount` / `wrongStudentCount` / `missStudentCount` 及两个比率）走 `hw_answer_sheet.teacher_node_id` **结算快照**，因此**包含已转出学员在该导师名下期间产生的作答**——否则导师历史业绩会随学员流动而回溯变化。响应中**不得返回任何已转出学员的身份信息**（姓名 / ID / 明细行）。
  - **个体明细下钻**（由榜单点开的"错误学员名单"）必须在快照条件之上**再叠加当前子树过滤**（契约 §2.4）：已转出学员**不出现在任何明细列表中**，其学员档案详情页返回 `404`（见 4.4）。
  - 因此名单人数可能小于榜单的 `wrongStudentCount`，**属预期行为**，前端不得据此判定数据异常。

#### （5）活跃学员（`stat_teacher_daily.active_student_count` / `stat_node_daily.active_student_count`）

```
stat_student_daily.is_active = 1  当且仅当  watch_seconds > 0 或 当日有提交答卷行为
                                （ontime_submit_count + late_submit_count > 0）

stat_teacher_daily.active_student_count = Σ 名下学员 is_active        （当日快照内去重）
stat_node_daily.active_student_count    = Σ 子树内学员 is_active      （本表行即子树聚合）
```

- **节点大屏的子树活跃数直接读 `stat_node_daily` 命中行**，无需展开子树求和（本表已是子树聚合）；反过来，**父行与子行不可相加**（父行已含子行，见 (2) 的同名说明）。
- **`active_student_count` 不可跨天求和**得到"区间活跃人数"：按天求和得到的是"活跃人日"。区间去重活跃人数须回 `stat_student_daily` 按 `student_id` 跨日 `COUNT(DISTINCT)`。本模块接口只返回**逐日**活跃数与**今日**活跃数，不返回区间活跃人数，即为规避此歧义。
- "今日活跃"（T 日）按 2.1 所述实时口径计算：当日产生**有效心跳**（通过间隔合理性校验并计入 `watched_duration`）或当日提交过答卷的去重学员数，归属按当前树结构判定。
- **今日实时活跃曲线**（4.3）按小时切片，每小时内部去重；**逐小时值不可相加**得到全天活跃数（同一学员可能横跨多个小时），全天值单独按天去重计算。

#### （6）累计学习时长（`stat_student_daily.watch_seconds`）

```
学员日学习时长（stat_student_daily.watch_seconds）
        = 该生当日经心跳有效校验计入的观看秒数增量

学员累计学习时长（学员档案口径，见 2.4）
        = Σ 该生全部课时的 vod_watch_progress.watched_duration
        （墙钟有效累计：复看已看片段同样计入，单次心跳最多计 min(实际间隔, 15) 秒，
          与该生逐日 watch_seconds 之和一致；**含转入当前导师之前的全部历史**）

导师/节点区间学习时长（看板与大屏口径）
        = Σ stat_student_daily.watch_seconds
          WHERE teacher_node_id = 该教师节点 / node_id ∈ 节点子树 AND stat_date 落在区间内
        （**只含该导师名下期间 / 该节点归属期间产生的时长**）
```

- 两个口径**刻意不同**，不得互相校验，理由见 2.4。

#### （7）课程进度百分比（学员档案用）

```
课程进度百分比 = 该课程下 watch_status = 2 的课时数（视频 + 图文）
              ÷ 该课程当前可见课时总数（lesson_type ∈ {1,2}，status = 1 且 deleted_at = 0）× 100
```

- **分母含图文课时**：与 03-课程与视频分册学生端"我的课程"的 `progressPercent` 及 PRD F4-3 公式为同一口径（图文课时首次成功访问即置 `watch_status = 2` 参与进度），保证学生端与学习档案进度数值一致。注意与 (1)(2) 的**完播率**（仅视频课时）为两个不同指标。
- **除零兜底**：可见课时总数为 0 时记 0，前端展示为"—"。

#### （8）错题掌握率（学员档案用）

```
错题总数   = hw_wrong_book 中该生记录数（UK student_id, question_id，同题多次做错仍为一条）
已掌握数   = master_status = 1 的记录数
掌握率     = 已掌握数 ÷ 错题总数 × 100 （错题总数为 0 时记 0，前端展示为"—"）
```

### 2.4 归属与结算口径（跨接口统一，对齐契约 §2.6）

**原则：历史归原导师，以自然日为结算单位。** 本模块所有接口必须遵循下表，不得各自解释。

| 规则 | 说明 |
| --- | --- |
| **历史归原导师** | 学员转导师后，其转出前已结算的 `stat_student_daily` 行仍带原导师的 `teacher_node_id` 快照，原导师的历史业绩曲线不会因学员流动而变动 |
| **已结算行永不重算** | `stat_student_daily` 一旦落库即不可回填改写；任务重跑对已结算日期为幂等空操作 |
| **转导师当日归新导师** | 转导师当日尚未结算，凌晨结算任务按**结算时刻**的归属计算，该日数据整日计入新导师。理由：与分母对齐——学员已不在原导师名下（不在其 `student_count` 内），数据若留在原导师会造成"有数据无学员"的错配 |
| **今日实时 vs 历史趋势** | "今日实时"（活跃数、区间末点）按**当前归属**计算；"历史趋势"读**结算快照**。**换绑当日两者短暂不一致，属预期行为**：新导师看板的今日实时已包含该学员，而该学员当日之前的趋势点仍在原导师名下；次日凌晨结算后归口一致 |
| **两个分离的口径** | **学员档案（看学生）**：新导师可查看该学员**转入前的完整学习历史**，否则无法督学 —— 累计时长、课程进度、成绩曲线、错题本一律按 `student_id` 维度取全量，不按 `teacher_node_id` 过滤。**导师看板/业绩（看导师）**：只统计该导师名下期间产生的数据，按结算快照上卷 |

> 因此，同一学员的"累计学习时长"在 4.4/4.5 学员档案中的数值，**必然大于等于**其在 4.1 导师看板区间统计中对当前导师的贡献值。这不是数据不一致，是两个口径。前端在档案页展示时应同时给出"累计（全程）"与"当前导师名下"两个数值以免误读（4.4 已提供 `totalWatchSeconds` 与 `watchSecondsUnderCurrentTeacher` 两个字段）。

### 2.5 数据权限在本模块的落地（对齐契约 §2.4）

全系统只有一条数据权限规则：**你能看到的数据 = 你所在节点的子树**。本模块的落地方式：

| 接口 | 统计范围的确定方式 |
| --- | --- |
| 4.1 导师看板 | `teacher` 角色：**无任何范围参数**，范围恒为"我的名下学员"（服务端由 `sys_user.node_id` 取本人教师节点）。`org_admin` 角色：**必须传 `teacherNodeId`**，且该节点须 `node_type = 2` 并落在调用者子树内 |
| 4.2 单次作业分析 | **访问权与统计范围分离**：范围 = 该作业分发对象 ∩ 调用者子树内学员，服务端强制计算，不信任前端传参 |
| 4.3 节点大屏 | `nodeId` 必须落在调用者子树内（含自身）；不传默认取调用者所在节点 |
| 4.4 学员档案 | 该学员节点必须落在调用者子树内，否则返回 `404`（不暴露存在性） |
| 4.5 我的档案 | 恒为本人，不接受任何 ID 参数 |
| 4.6 创建导出 | `bizParams.nodeId` / `bizParams.teacherNodeId` 均须落在调用者子树内，服务端二次校验 |

- **本模块统一的越权表现**（契约 §2.4 三分法）：**查询参数中显式传入**的 `nodeId` / `teacherNodeId` 落在本租户内但不在调用者子树内 → 返回 **`10107`**；**路径 `{id}` 上的对象**（如 `homeworkId`、`students/{id}`）不在可见范围 → 返回 **`404`**（不暴露存在性）；**跨租户或对象不存在** → 一律返回 `404`（不暴露存在性，契约 §2.1）。单个学员资源（4.4）因数据权限过滤后查不到，统一返回 `404`。
- 学员被移出某节点后，原上级**立即失去**对其个体明细（4.4 档案、错题名单、导出行）的访问权；其历史聚合数值仍留在原导师/原节点的快照统计中（2.4），二者不矛盾。

### 2.6 学生端可见性约束（对齐契约 §2.7，强制）

私域模式下**学生之间互不可见**。本模块面向学生端的接口只有 4.5 `GET /api/v1/stat/my/profile` 一个，其响应必须满足：

1. **不返回任何他人数据**：不含同伴名单、他人姓名、他人成绩、他人进度，一个字段都不允许。
2. **无排行榜**：不返回名次、百分位、超过百分之多少的同学等任何相对位置信息。
3. **无群体平均**：不返回导师/节点等任何群体的平均分、平均完播率、平均时长等聚合值，也不返回可反推群体规模的字段（如名下学员总数）。
4. **排行类与对比类功能仅存在于管理端**（4.1 高频错题榜、4.3 导师排行榜与下级节点对比），学生角色调用 4.1 / 4.3 / 4.4 一律返回 `403`。
5. 学生可见的仅限：本人课程与进度、本人作业与成绩、本人错题本、本人学习档案、本人所属导师姓名（其督学关系本身对学生公开）。

## 3. 业务错误码（4xxxx 数据中心段位）

以下为本模块业务错误码总表，各接口"相关错误码"引用本表，与《00-通用约定.md》§9.5 逐码一致。通用错误码：`401` 未登录、`403` 无权限（含数据权限拒绝）、`400` 参数校验失败；跨租户访问或资源不存在一律返回 `404`（不暴露存在性，契约 §2.1）。

| code | msg | 说明 |
| --- | --- | --- |
| 40001 | 导出任务生成失败 | 异步生成过程异常，任务 `status = 3`，失败原因见任务详情 `failReason` |
| 40002 | 导出参数错误 | `exportType` 不在 1/2 范围，或 `bizParams` 缺少该类型的必填字段 |
| 40003 | 导出任务不存在或非本人创建 | 导出任务仅创建人（`applicant_id`）可查 |
| 40004 | 相同参数的导出任务正在排队或生成中 | 防重复提交：同用户、同 `exportType`、同 `bizParams` 且 status IN (0,1) 时拒绝 |
| 40005 | 作业未发布，暂无统计数据 | 对 `status = 0` 草稿或 `status = 3` 已撤回的作业请求分析 |
| 40006 | 统计日期范围不合法 | `startDate > endDate`，或跨度超过最大允许的 90 天 |
| 40007 | 导出数据量超过上限 | 创建导出任务时预估行数超过 **5 万行**，拒绝创建并提示缩小节点/导师/时间范围分次导出（PRD F4-4 规则 1 / 边界 B49） |
| 40008 | 报表文件已过期清理 | 导出文件超过保留期（**7 天**，`sys_file` 逻辑删除）后再请求下载（PRD F4-4 规则 3） |

> **本模块未新增 4xxxx 错误码**，失败场景全部映射到既有码位或框架层状态码：
> - `teacherNodeId` / `nodeId` 是**查询参数中显式指定的目标**，落在本租户内但不在调用者子树内 → **`10107`**（契约 §2.4 三分法：「我选的目标」越界用 10107，提示重新选择；路径 `{id}` 上的对象越界才用 404）
> - `teacherNodeId` 指向的节点 `node_type ≠ 2`（非教师节点）、`nodeId` 指向学生节点、管理员调用 4.1 未传 `teacherNodeId` → `400`（参数值不合法，msg 中说明具体字段）
> - 节点/学员/作业不存在或跨租户 → `404`
> - 4.2 有效统计范围为空（调用者子树内不含该作业任何分发学员）→ `403`（理由见 4.2 实现提示）

## 4. 接口详情

### 4.1 导师看板

- **接口名**：导师看板
- **方法与路径**：`GET /api/v1/stat/teacher/dashboard`
- **权限**：
  - 允许角色：`teacher`（导师）、`org_admin`（管理员，任意层级）
  - **数据权限（契约 §2.4 子树规则）**：
    - `teacher`：统计范围**恒为"我的名下学员"**，即当前登录用户 `sys_user.node_id` 所指教师节点的直接子节点中的在读学员。**本接口不再有 `classId` 参数**；若 `teacher` 传入 `teacherNodeId` 且不等于本人教师节点，返回 `403`（教师节点下只能挂学生，其子树不含其他教师）。
    - `org_admin`：**必须传 `teacherNodeId`**，且该节点须满足 `node_type = 2` 且落在调用者子树内（`n.id = #{myNodeId} OR FIND_IN_SET(#{myNodeId}, n.ancestors)`）；不在子树内返回 `403`，节点不存在或跨租户返回 `404`，未传或节点类型不对返回 `400`。 <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
    - `student` 角色调用返回 `403`（契约 §2.7，学生端无群体聚合与排行）。
- **口径**：完播率取区间**末日**行的分子÷分母（累计状态型，2.3(2)），按时提交率对区间内逐日 `stat_teacher_daily` 的 **`Σontime_submit_count ÷ Σshould_submit_count`**（当日流量型，2.3(3)，无需回明细表），高频错题按 `hw_answer_detail.teacher_node_id` 冗余快照实时聚合（2.3(4)，与答卷头同源同时刻写入），趋势为逐日 rate 单日直读、末点（今日）为实时口径（2.1.1 / 2.4）。

| dateRange | int | 否 | 统计区间（最近 N 天，含今日），取值 `7` / `30`，默认 `7`。非法值返回 `400` |

| avgCompleteRate | number | 名下学员视频平均完播率（%），口径见 2.3(2)。**累计状态型**：取区间**末日**一行 `stat_teacher_daily` 的 `finished_lesson_count ÷ should_lesson_count`，即 `2039 ÷ 2600 × 100 = 78.42`；末日（今日）为实时口径 |
| finishedLessonCount / shouldLessonCount | int | 完播率的分子 / 分母（截至区间末日的累计课时数，2.1.1 铁律要求随比率一并返回）。**不可跨日求和**；`shouldLessonCount = 0` 时比率记 0，前端展示"—" |
| ontimeSubmitRate | number | 作业按时提交率（%），口径见 2.3(3)。**当日流量型**：对区间内逐日 `stat_teacher_daily` 的两列求和后相除 = `146 ÷ 168 × 100 = 86.90`，**不是**逐日 rate 的平均 |
| ontimeSubmitCount / shouldSubmitCount | int | 区间内按时提交人次 / 应交人次，等于 `ontimeSubmitRateTrend` 各点同名字段之和（示例：38+0+35+0+37+0+36 = 146；42+0+42+0+42+0+42 = 168）。应交人次为 0 时二者均为 0 且 `ontimeSubmitRate` 记 0（前端展示"—"） |
| todayActiveStudentCount | int | 今日活跃学员数（实时口径，见 2.3(5)），与 `activeTrend` 末点一致 |
| totalWatchSeconds | int | 区间内名下学员学习总秒数 = Σ `activeTrend[].watchSeconds`（示例：58420+62150+44030+25240+70510+67860+39210 = 367420），口径见 2.3(6) 导师区间口径 |
| topWrongQuestions | array | 高频错题 Top10（不足 10 条按实际返回），口径见 2.3(4)，排序：**未掌握人数（错误+漏选）降序 → 错误人数降序 → question_id 升序**。示例三题未掌握人数分别为 32 / 31 / 30，故按此序返回 |
| topWrongQuestions[].questionType | int | 题型：1单选 2多选 3判断 4填空 5简答 6材料题(父题)（材料题按子题统计，此处为子题题型） |
| topWrongQuestions[].answerStudentCount | int | 作答人数（`is_correct` 非 NULL 的去重学员数，待批改不计入分母） |
| topWrongQuestions[].wrongStudentCount / wrongRate | int / number | 全错人数（`is_correct = 0`）与错误率（%），**不含半对** |
| topWrongQuestions[].missStudentCount / missRate | int / number | 漏选人数（`is_correct = 2`：多选漏选 / 填空部分正确）与漏选率（%）。前端建议与错误率并列展示为双色堆叠条，二者**不可相加**解读为"错误率"。示例第三题错误率 0.00% 而漏选率 83.33%，正是排序采用"未掌握人数"要规避的盲区 |
| completeRateTrend | array | 名下学员平均完播率**逐日趋势折线**，点数 = `dateRange`（7/30），逐日**单日直读** `stat_teacher_daily.avg_complete_rate`（2.1.1 允许的唯一 rate 列用法）；末日（今日）为实时口径 |
| ontimeSubmitRateTrend | array | 作业按时提交率**逐日趋势折线**，点数 = `dateRange`，逐日**单日直读** `stat_teacher_daily.ontime_submit_rate`（当日到期作业，见 2.3(3)），并同时给出该日的 `ontimeSubmitCount` / `shouldSubmitCount`。**当日无到期作业时三者均为 0，前端应断点展示为"—"，不得连成谷底**；对这些点做 Σ 时分子分母同为 0，不污染区间值。**禁止**用本数组的 rate 求平均来复核 `ontimeSubmitRate`（2.1.1 铁律） |
| activeTrend | array | 近 7 日活跃趋势（**固定 7 个点，与 dateRange 无关**），逐日来源 `stat_teacher_daily.active_student_count`；末日（今日）为实时口径 |
| activeTrend[].watchSeconds | int | 该导师名下学员当日学习总秒数 = Σ `stat_student_daily.watch_seconds`（限 `teacher_node_id` = 本导师的行） |

> **换绑当日的预期不一致（2.4）**：若某学员在今日刚转入本导师名下，则 `todayActiveStudentCount` 与 `activeTrend` 末点已包含该生，而 `completeRateTrend` 的历史点（读结算快照）仍不含其转入前数据。**这是设计预期，不是缺陷**；次日凌晨结算后归口一致。前端可在末点加"实时"角标以示区分。

**相关错误码**：`400`（`dateRange` 非法值 / `org_admin` 未传 `teacherNodeId` / `teacherNodeId` 指向的节点 `node_type ≠ 2`）、`401`、`403`（`teacherNodeId` 不在调用者子树内 / 教师传入非本人节点 / 学生角色访问）、`404`（教师节点不存在、已删除或跨租户）。

### 4.2 单次作业分析

- **接口名**：单次作业分析
- **方法与路径**：`GET /api/v1/stat/teacher/homework/{homeworkId}/analysis`
- **权限**：
  - 允许角色：`teacher`、`org_admin`
  - **访问权（能不能打开）**：调用者须为该作业创建人（`hw_homework.create_by` 对应本人），**或**该作业的分发对象（`hw_homework_target.student_id`）中存在至少一名落在调用者子树内的学员；两者皆不满足返回 `403`。跨租户或作业不存在返回 `404`。
  - **统计范围（能看多少）—— 服务端强制收口，与访问权分离**：本接口的全部聚合指标只统计
    ```
    有效统计学员集 = hw_homework_target.student_id  ∩  调用者子树内的在读学员
                     （n.node_type = 3 AND (n.id = #{myNodeId} OR FIND_IN_SET(#{myNodeId}, n.ancestors))） <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
    ```
    该集合由服务端计算，**不信任前端任何传参**：
    - `teacher`：有效统计学员集 = 该作业分发对象 ∩ **其名下学员**。**即便该教师是作业创建人，也只能看到自己名下的学员**——创建人身份决定"能不能打开"，不决定"能看多少"。
    - `org_admin`：有效统计学员集 = 该作业分发对象 ∩ **其子树内全部学员**（含下级管理员、下级导师名下的学员）。
    - 传入可选参数 `teacherNodeId` 时，再与上述集合取交集；`teacherNodeId` 不在调用者子树内返回 `403`。
  - **设计原因**：作业以学员为粒度全量分发（`hw_homework_target.student_id`），同一份作业常横跨多位导师、多个节点。若按作业维度返回全局聚合，A 导师看到的 `avgScore`、`scoreDistribution`、`questionAnalysis` 会混入其他导师名下学员的数据——这不仅是越权，更会让导师**误判自己的督学效果**（均分可能主要由他人名下学员拉动）。
  - **不透露被排除的对象**：响应只给出 `scopeStudentCount`（本次统计覆盖的学员数）与 `scopeCoversAllTargets`（是否覆盖全部分发对象）两个标量，**不返回被排除学员的 ID、姓名、数量、所属导师或节点**，避免反向探测子树之外的组织结构与人员。

**请求参数**

| 参数 | 位置 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- | --- |
| homeworkId | path | string | 是 | 作业 ID（`hw_homework.id`） |
| teacherNodeId | query | string | 否 | 将统计范围进一步限定到某位导师的名下学员（`org_node.id`，`node_type = 2`）。不传则取"有效统计学员集"全部；传入不在调用者子树内的节点返回 `403`；节点类型不对返回 `400` |

```
GET /api/v1/stat/teacher/homework/1954120987654321153/analysis
Authorization: Bearer {accessToken}
```

### 4.3 机构/节点大屏总览

- **接口名**：机构/节点大屏总览
- **方法与路径**：`GET /api/v1/stat/node/overview`
- **权限**：
  - 允许角色：`org_admin`（任意层级的管理员，包括机构管理员与下级管理员）
  - **数据权限**：`nodeId` 必须落在调用者子树内（**含调用者所在节点自身**），判定条件 `n.id = #{myNodeId} OR FIND_IN_SET(#{myNodeId}, n.ancestors)`；不在子树内返回 `403`，节点不存在或跨租户返回 `404`。不传 `nodeId` 时默认取调用者所在节点（机构管理员即整个机构，下级管理员即其管辖分支）。 <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>

> **`stat_node_daily` 行的相加规则（契约 §4，实现必读）**
>
> 本表每行 = **该节点整棵子树**的聚合，因此：
> - **父行与子行不可相加**——父行已包含全部后代，相加即双计。跨节点汇总时只能取**最近公共祖先**的那一行。
> - **同层兄弟节点的行可以相加**（子树互不重叠），但其和**不等于**父行：示例中三个下级节点 `shouldLessonCount` 之和为 `18200 + 14700 + 10000 = 42900`，而本节点为 `43500`，差额 `600`（对应 `finishedLessonCount` 差额 `30372 − 30243 = 129`）来自**直挂本节点、不属于任何下级节点**的 20 名学员（如已归属管理员但尚未分配导师者）。`studentCount` 同理：`260 + 210 + 150 = 620 ≠ 640`。
> - 因此前端**不得**用 `childNodeComparison` 求和来校验本节点级 KPI，也不得据其差额提示"数据缺失"。

| teacherBottomRanking | array | **导师排行 Bottom 榜**：`rank = 1` 表示**最差**；按 `avgCompleteRate` 升序 → `ontimeSubmitRate` 升序 → `teacherNodeId` 升序，取 `rankLimit` 条（与 Top 榜同口径）。子树内导师总数不足 `2 × rankLimit` 时两榜可能重叠，前端按需去重展示 |
| teacherRanking[].nodePath | string | 该导师节点父级的名称路径，供管理员定位其组织位置 |
| todayActiveCurve | array | **今日实时活跃曲线**：0 点起逐小时的当日活跃学员数（实时口径 2.3(5) 按小时切片，每小时内部去重），**仅返回已过去与当前小时**（示例 `statTime` 为 15:30，故到 hour=15 为止）；前端每 60 秒刷新（PRD F4-2 规则 1）。**逐小时值不可相加**得到 `todayActiveStudentCount`（同一学员可能跨多个小时活跃），示例中小时峰值 132 与全天去重值 342 无加总关系 |

**相关错误码**：`400`（`trendDays` / `rankLimit` 非法值 / `nodeId` 指向学生节点）、`401`、`403`（`nodeId` 不在调用者子树内 / 教师或学生角色访问）、`404`（节点不存在、已删除或跨租户）。

### 4.4 学员学习档案（管理端）

- **接口名**：学员学习档案（管理端）
- **方法与路径**：`GET /api/v1/stat/students/{id}/profile`
- **权限**：
  - 允许角色：`teacher`、`org_admin`
  - **数据权限**：该学员的 `org_node` 节点必须落在调用者子树内（`n.id = #{myNodeId} OR FIND_IN_SET(#{myNodeId}, n.ancestors)`）。对导师而言即"我的名下学员"，对管理员而言即其子树内全部学员。不满足、学员不存在或跨租户**一律返回 `404`**（不暴露存在性）。学员被移出后原上级立即返回 `404`（契约 §2.4）。 <sup>⚠ 语义表达，执行写法见契约 §2.4 子树查询选路表</sup>
  - `student` 角色访问本接口返回 `403`（学生请使用 4.5）。

> **重要口径声明（契约 §2.6 学员档案口径，与导师看板不同）**
>
> 本接口按 **`student_id` 维度取全量历史**，**新导师可以查看该学员转入自己名下之前的完整学习历史**：累计学习时长、各课程进度、作业成绩曲线、错题总数与掌握率，全部不按 `teacher_node_id` 过滤。理由：不看完整历史无法开展督学。
>
> 这与 **4.1 导师看板只统计名下期间数据**（按 `stat_student_daily.teacher_node_id` 结算快照上卷）是**两个刻意分离的口径**：
> - **看学生 → 全量历史**（本接口）：学员档案连续，不因转导师而断档。
> - **看导师 → 名下期间**（4.1）：导师业绩只归属其实际督学期间。
>
> 因此本接口的 `totalWatchSeconds` 必然 **≥** 该学员对当前导师看板 `totalWatchSeconds` 的贡献；响应额外提供 `watchSecondsUnderCurrentTeacher` 与成绩曲线上的 `underCurrentTeacher` 标记，供前端并列展示，避免管理者把"全程累计"误当作"本导师业绩"。

### 4.6 创建导出任务

- **接口名**：创建导出任务
- **方法与路径**：`POST /api/v1/stat/exports`
- **权限**：
  - 允许角色：`teacher`、`org_admin`
  - **数据权限**：`bizParams.nodeId` 与 `bizParams.teacherNodeId` 均须落在申请人子树内（含自身），服务端**创建时校验一次、任务执行前再校验一次**（防止创建后被调岗导致越权导出）；不在子树内返回 `403`，跨租户或节点不存在返回 `404`。`teacher` 调用时两个参数均可省略，服务端默认锁定为其本人教师节点（即"我的名下学员"）。`student` 访问返回 `403`（契约 §2.7）。
- **说明**：导出为**异步任务**。创建成功即写入 `stat_export_task`（`status = 0` 排队），由后台任务生成 Excel 并上传至 `sys_file`，前端通过 4.8 轮询状态。两种报表的 Excel 列结构见第 5 节。
- **行数上限校验（PRD F4-4 规则 1 / 边界 B49）**：创建时服务端按 `bizParams` **预估导出行数**
  - `exportType = 1`：范围内在读学员数 × 命中课程数
  - `exportType = 2`：范围内在读学员数 × 区间内命中作业数

  预估超过 **5 万行**直接拒绝创建并返回 `40007`，提示缩小节点/导师/时间范围分次导出（避免生成中途 OOM）。
- **文件保留期**：生成的报表文件保留 **7 天**，到期由定时任务清理（`sys_file` 逻辑删除，PRD F4-4 规则 3）；过期后下载返回 `40008`，需重新创建导出任务。

**请求参数（Body，application/json）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| exportType | int | 是 | 导出类型：**1 学员学习进度**、**2 学员作业成绩**（对应 `stat_export_task.export_type`） |
| bizParams | object | 是 | 业务参数（原样存入 `stat_export_task.biz_params`），按 exportType 取值见下两表 |

**bizParams —— 范围参数（两种 exportType 共用）**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| nodeId | string | 否 | 统计根节点 ID，导出该节点**子树内**全部在读学员。不传默认取申请人所在节点；必须在申请人子树内 |
| teacherNodeId | string | 否 | 进一步限定为某位导师的**名下学员**（`node_type = 2`）。同时传 `nodeId` 时该导师节点必须落在 `nodeId` 子树内，否则 `403`；节点类型不对返回 `400` |

**bizParams —— exportType = 1（学员学习进度）追加参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| courseId | string | 否 | 课程 ID；不传则导出范围内学员的全部当前授权课程（学习进度为累计快照，无日期参数） |

**bizParams —— exportType = 2（学员作业成绩）追加参数**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| homeworkId | string | 否 | 作业 ID；传则仅导出该次作业 |
| startDate | string | 否 | 起始日期（`yyyy-MM-dd`），按作业 `deadline` 过滤；与 `endDate` 成对出现 |
| endDate | string | 否 | 截止日期（`yyyy-MM-dd`）；不传日期时默认最近 90 天，跨度上限 90 天，越界返回 `40006` |

## 5. 导出报表 Excel 列结构

两种报表均为 `.xlsx`（Excel 2007+）单 Sheet 文件；首行为表头，冻结首行；文件命名规则：`{报表名}_{范围名}_{yyyyMMddHHmmss}.xlsx`，其中 `{范围名}` 取 `teacherNodeId` 对应导师姓名（限定到导师时）或 `nodeId` 对应节点名称（否则）。生成完成后文件登记至 `sys_file`（`biz_type` 为报表导出），`stat_export_task.file_id` 指向该记录；文件保留 7 天后由定时任务清理（见 4.6 / 4.8，过期下载返回 `40008`）。

**列结构**：归属信息拆为 **"所属节点路径"** 与 **"导师"** 两列。

- **所属节点路径**：该学员**父节点**自租户根到自身的名称路径，用 ` / ` 分隔（由 `org_node.ancestors` 逐级取 `node_name` 拼接），如 `启明教育 / 东湖分校 / 初中部 / 王慧敏`。学员尚未分配导师时路径末段为其所属管理员节点名。
- **导师**：
  - **学习进度报表（exportType = 1）** 取学员**当前**导师姓名（`org_node` 父节点，`node_type = 2`）——学习进度是累计快照，只有"当前归属"一个口径；未分配导师时留空。
  - **作业成绩报表（exportType = 2）** 取 `hw_answer_sheet.teacher_node_id`（**作答时刻快照**）对应的导师姓名——对齐 2.4"历史归原导师"，保证导出的成绩行与导师业绩口径一致；无答卷记录（未提交）时回退取当前导师姓名，仍无则留空。

### 5.1 exportType = 1：学员学习进度报表

> **写出防护（强制）**：本节全部报表在生成 `.xlsx` 时，字符串单元格若以 `=` `+` `-` `@` `Tab` `CR` 开头，**必须前置单引号或显式设为文本格式**（见 00 §7.4）。姓名、学号、节点名等列源自用户输入，不转义会使每一份导出报表都成为公式注入的载体，受害面覆盖全部下载者。

Sheet 名：`学习进度`。**一行 = 一名学员 × 一门课程**（指定 `courseId` 时仅该课程），按所属节点路径升序 → 学号升序 → 课程名称升序。

| 列序 | 列名 | 数据来源与口径 |
| --- | --- | --- |
| A | 学号 | `org_student.student_no` |
| B | 姓名 | `sys_user.real_name` |
| C | **所属节点路径** | 学员父节点的名称路径（见上方说明） |
| D | **导师** | 学员**当前**导师姓名；未分配导师留空 |
| E | 课程名称 | `crs_course.course_name` |
| F | 应学课时数 | 该课程当前可见课时总数（**含图文**，口径 2.3(7) 分母） |
| G | 已完成课时数 | `vod_watch_progress.watch_status = 2` 计数（含图文课时） |
| H | 学习中课时数 | `watch_status = 1` 计数（图文课时不经过状态 1，仅视频产生） |
| I | 未开始课时数 | F − G − H |
| J | 课程进度(%) | G ÷ F × 100，保留两位小数（F = 0 时留空）；口径 2.3(7)（PRD F4-4 报表列"完播率"即此值，本表按课程进度口径命名以免与看板视频完播率混淆） |
| K | 累计观看时长(分钟) | Σ `watched_duration` ÷ 60，保留一位小数（图文课时 `watched_duration` 恒为 0，不产生时长） |
| L | 最近学习时间 | MAX(`vod_watch_progress.last_heartbeat_time`)，格式 `yyyy-MM-dd HH:mm:ss`，无记录留空 |

### 5.2 exportType = 2：学员作业成绩报表

Sheet 名：`作业成绩`。**一行 = 一名学员 × 一次作业**（指定 `homeworkId` 时仅该作业），按所属节点路径升序 → 学号升序 → 作业截止时间升序。

| 列序 | 列名 | 数据来源与口径 |
| --- | --- | --- |
| A | 学号 | `org_student.student_no` |
| B | 姓名 | `sys_user.real_name` |
| C | **所属节点路径** | 学员父节点的名称路径（见上方说明） |
| D | **导师** | `hw_answer_sheet.teacher_node_id`（**作答时刻快照**）对应导师姓名；未提交时回退取当前导师，仍无则留空 |
| E | 作业名称 | `hw_homework.homework_name` |
| F | 作业类型 | `homework_type`：1→"作业"，2→"考试" |
| G | 截止时间 | `hw_homework.deadline`，`yyyy-MM-dd HH:mm:ss` |
| H | 满分 | `hw_homework.total_score` |
| I | 客观题得分 | `hw_answer_sheet.objective_score`（未提交留空） |
| J | 主观题得分 | `hw_answer_sheet.subjective_score`（未批改留空） |
| K | 总得分 | `hw_answer_sheet.total_score`（仅 `status = 3` 已批改有值） |
| L | 得分率(%) | K ÷ H × 100，保留两位小数（K 为空时留空） |
| M | 答卷状态 | `hw_answer_sheet.status`：0→"未开始"，1→"作答中"，2→"已提交待批改"，3→"已批改"，4→"逾期未交"（无答卷记录按"未开始"） |
| N | 是否逾期 | `is_late`：0→"否"，1→"是"（未提交留空） |
