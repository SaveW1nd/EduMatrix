## 3. 请复核方重点看的六处判断

以下每一处都是**判断**而非机械改动，理由都写在代码注释里，但值得独立审一遍。

### 3.1 `encryptType` / `encrypt_type` 做成映射而不是换一个固定值

**背景**：03-03 §8.1 原文「固定 `1`」。第一版不加密后，最自然的改法是「那就固定 `0`」。

**判断**：两处都做成**按行翻译**（`PlayAuthConst.aliplayerEncryptTypeOf`、`VodPlayStream.resolvedEncryptType`）。

**理由**：存量视频与新视频**会长期混在一起**，写死任一值都会让另一半播不了，而那个表现是「视频打不开」，**与代码 bug 不可区分**。

**可证伪**：M46a/M46b、M48/M49 **各自从两个方向**变异，四条都有对应用例变红。

### 3.2 `template_group_id` 与 `encrypt_type` 分成两列

**判断**：不合并。前者是「我们**请求**了什么」（意图，上传即知），后者是「实际**产出**了什么」（观测，转码后才知道）。

**理由**：合成一列的话，**转码失败的视频（`status=3`）就没有可信的重转依据** —— 那时 `encrypt_type` 还只是占位值，而**正是那些行需要重转**。

**可证伪**：M52（重转改用当前配置）→ `retranscodeReusesOriginalTemplateGroup` 红，轨迹里能看到 `tpl=TPL-PLAIN`（正是会叠出第二套流的那个值）。

### 3.3 机构根收窄写在代码里，而不是 `sys_role_menu`

**这是对 F-110 / F-72 纪律的一次明知例外**，请重点审理由是否成立：

- 机构根管理员与下级管理员**共用同一个 `org_admin` 角色**，从角色上撤会把两者一起撤掉；
- 要用角色表达就得新建 `org_root_admin` 并改建人员的绑定逻辑 —— 那是**给一条结构性约束造一个身份**；
- 它的性质是「媒资这类资源只存在于机构根这一层」，与建树规则（02-数据库设计 §444「父节点 `node_type=0` → 子必须为 1」等）同类，**那一类判定本来就在代码里**。

**判定实现**：`节点 id == tenant_id` —— 契约 §2.1 / 02 §28 写死的两个 ID 例外之一，**一次比较，不查库、不遍历树、不看 `ancestors` 前缀**。注释里写明了**不要改成按 `parent_id == 0` 判**（那依赖树形状，而 `id == tenant_id` 是契约事实）。

**可证伪**：M53（`assertOrgRoot` 变空转）→ `mediaWriteIsOrgRootOnly` 红（`403` → `404`）。

### 3.4 加密组没配时**拒绝**而不是降级

`resolveTemplateGroup` 在 `encrypted=true` 而加密组为空时**抛错**。

**理由**：悄悄降级成不加密的表现是「**以为加密了其实没有**」——不报错、页面一切正常。与挑流那条「挑不到必须置 3、绝不可置 2」同一条纪律。

**可证伪**：M51 → `uploadWithEncryptionRejectedWhenNoEncryptedGroupConfigured` 红。

### 3.5 「恰好一路」守卫**保留**，并订正了一处不准确的前提

守卫不动。但**原先写的理由是错的**，已订正：

- ~~「两个模板组并存时 `GetPlayInfo` 会返回两路」~~ —— **不对**。模板组是**按视频**选的，「系统里有两个可选组」本身不会让任何一个视频出现两路。
- **真正会返回两路的**是「同一个视频被两个模板组各转过一次」，当前有一条可达路径：接口 33 重转用当前配置的组，切换配置后对老视频重转就会叠流。**已由 `template_group_id` 修掉**。

### 3.6 C14 检查器的前提被我打破，所以我改了检查器

**「DDL = 基线」这个前提，在第一个 `ALTER TABLE ADD COLUMN` 出现的那天就不成立** —— 本迁移是全库第一个。

不补的话唯一出路是「不把新列写进文档」，**而那正是 C14 存在要防的事**。

**边界**：只认 `ADD COLUMN`，**不认 `DROP` / `MODIFY`** —— 静默跟随会让「删了一列」查无实据。

## 6. 我自己发现并修正的错误（请复核方一并核实结论是否成立）

### 6.1 「第一版不加密不做水印」此前**全库零承载物**

### 6.2 F-113 的三处漏网（其中一处就在模块 12 的直接依据里）

- `03-03 §8.1` 的 `maxPosition` 行仍写「允许拖拽上限」「不解除禁快进」 —— 上一轮只改了 04 侧镜像，**漏了权威侧**；

### 6.3 「按课程选加密不成立、建议不做」是误读

需方要的是**上传时选**，与课程无关，完全成立。**建议已撤回**，功能已实现。

### 6.4 「两个模板并存会返回两路」这个前提是错的

见 §3.5。这一点让「自适应」比原先估的**便宜得多**（每个视频一个组，守卫 / 消费侧 / 播放侧全都不用动）。

### 6.5 04 §B 模块 12 规则 1 写「三步」，而权威侧是「五步」
