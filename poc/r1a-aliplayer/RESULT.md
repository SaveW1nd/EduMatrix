## 验过的两条技术路线

| | 路线 A（契约 §1 原选型） | 路线 B（本轮改测） |
| --- | --- | --- |
| 加密 | HLS 标准加密 AES-128 | 阿里云私有加密（`AliyunVoDEncryption`） |
| 播放器 | hls.js / DPlayer / xgplayer | Aliplayer 2.25.1 |
| 播放方式 | URL（m3u8） | VidAuth（`vid` + `playauth` + `encryptType:1`） |
| 密钥 | **自建** `/key` 接口 | 点播服务托管，无自建接口 |

转码产物已核实（`GetPlayInfo`）：`Format=m3u8`、`Encrypt=1`、`EncryptType=AliyunVoDEncryption`、单路 1280×720——满足契约 §1 挑选规则 `Format=="m3u8" && Encrypt==true`。

## 四项判定（Android XWEB）

| # | 验什么 | 路线 A（标准加密+hls.js） | 路线 B（私有加密+Aliplayer） |
| --- | --- | --- | --- |
| ① | 加密 HLS 能否播放 | **过**（`MANIFEST_PARSED`→`KEY_LOADED`→`FRAG_LOADED`，播满全片，零错误） | **过**（`player.ready`→`canplay`→52.23s 播完 `ended`，零错误） |
| ② | key 请求能否带住 URL 参数 | **过**（服务端 3 次收到 `query={"token":"TESTTOKEN123"}`、`hasToken=true`） | **不适用**（密钥由点播托管）。替代项 **PlayAuth 签发：过** |
| ③ | 水印 + MutationObserver（含全屏） | 篡改检测**过**；全屏**存疑**，见下 | **过**（全屏元素 `DIV#playerbox.prism-player`，水印在全屏子树内、框 978×440 铺满 977×440 屏幕，**人眼确认可见**） |
| ④ | 前跳能否拦住 | **过**（16 次拦截，`seeked 落点` 每次等于 `maxPosition`；**全屏下同样拦住**；后退与已看范围内跳转不误伤） | **人工确认通过，无日志佐证**，见下 |

## 两处必须如实标注的地方

**③ 路线 A 的"全屏失效"是疑似误判，不作为结论。**
2026-08-15 首次测 DPlayer 时记录为「全屏水印消失」。但当时水印是 190×12 的一行小字，漂移范围错用了 `stage` 尺寸（会被挤在左上角一小块），且红色虚线框与「H5 层」标签是之后才加的。同一台机器、同一内核下路线 B 全屏水印**可见**——说明 X5 并非一律把视频提到独立原生层压制 H5。路线 A 的全屏结论应在修好工具后重测，不能沿用。

**④ 路线 B 缺日志佐证。**
测试者口头确认"禁止前跳测了没问题"，但服务端日志三个会话均为 0 拦截（最后两个会话只有页面加载时的 `seeking → 0.10s`），推测为页面关闭时日志回传未成功。**路线 B 的 ④ 目前只有人工结论。** 路线 A 的 ④ 有完整日志佐证。

## 已可确定的两条

1. **契约 §1 的原选型没有被实测推翻。** 路线 A 在 Android XWEB 上 ①②④ 全部成立、③ 的篡改检测成立（全屏项待重测）。改用阿里云私有加密是产品侧决策，不是被 R1a 的实测结果逼出来的。
2. **路线 B 在 Android XWEB 上可用。** 阿里云控制台标注的「移动端浏览器支持有限」在这台机器上未成立。
