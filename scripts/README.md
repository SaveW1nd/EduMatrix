# 文档一致性检查

```bash
python3 scripts/check_consistency.py            # 全量
python3 scripts/check_consistency.py --only C1  # 只跑某一项
```

无依赖，纯标准库。退出码：有 ERROR 返回 1，否则 0（适合挂 CI / pre-commit）。

## 为什么需要它

这套文档 1.7 万行、分布在 11 个文件里，同一件事往往在契约 / PRD / DDL / API 分册各写一遍。
实际发生过的缺陷里，**至少一半属于"改了上游没传导到下游"或"看起来改对了但没验证"**——
人肉交叉核对既慢又不可靠，而这类错误恰恰是机械检查最擅长的。

下面每一项都对应一个**真实发生过**的缺陷，不是假想的规范。

## 一条反复出现的失败模式：同类缺陷的第 N 处

`node_type` 重编号这一类缺陷，**第 3 处比第 1 处难找得多**——不是因为它更隐蔽，而是因为前两处修完会产生"这类问题已经处理过了"的结案感，人工排查恰在此时最松懈。实际发生的序列：

| 轮次 | 形态 | 结果 |
| --- | --- | --- |
| 第 1 轮 | 「教师（`node_type=1`）」概念在前 | 修掉，补了 C9 |
| 第 2 轮 | 「由 `userType` 推导：1→2 管理员、2→3 教师…」带概念词的枚举串 | 修掉两行（400、554），**收工** |
| 第 3 轮 | 「决定新建节点的 `node_type`：1→2、2→3、3→4」**不含概念词的纯箭头映射** | 外部评审指出。它是**规范性参数说明而非示例**，按它实现导师永远分配不到学员 |
| 第 4 轮 | JSON 示例里 `userType=2` 配 `nodeType=3` | 同上，另有一棵"学生节点有 32 个子节点"的非法示例树 |

**教训：每补一条检查项，要同时问"这一类还有没有第 N 种形态"。** 箭头映射是第三种，JSON 示例是第四种——两者都不在最初 C9 覆盖的四种句式里。检查项的价值不在评审时报了多少错，而在改文档时拦住了多少次（本轮 C16 与 C14 就各拦下一次漏改）。

## 检查项

| 项 | 检查内容 | 对应的真实缺陷 |
| --- | --- | --- |
| **C1** | DDL 结构：定义行逗号、索引引用的列在本表存在、唯一索引末列为 `deleted_at` | 脚本替换整行时漏行尾逗号，连续发生三次，每次都靠起 MySQL 容器报语法错才发现；按索引名批量替换时误伤同名索引（`sys_user` / `qb_question` / `org_node` 都有 `idx_tenant_type_status`，列分别是 `user_type` / `question_type` / `node_type`），替换后索引引用了本表不存在的列 |
| **C2** | 枚举取值跨文档一致 | `org_perm_template.status` 在 DDL 写「0停用 1启用」、API 分册写「0启用 1停用」，方向相反且默认值随之取反——按 DDL 落库后新建模板在 API 语义下即为"停用" |
| **C3** | 错误码必须在 `00-通用约定 §9` 登记册中存在 | `10010` 与 `10207` 语义重复；`10003` 在 02 分册被改用为"手机号已占用"而登记册里是"用户名或密码错误"；PRD 引用了预留号段 `20012` |
| **C4** | API 声明的字段长度 ≤ DDL 的 `VARCHAR(n)` | `crs_course.description` 接口写"最长 2000"、DDL 是 `VARCHAR(1000)`——前端按 2000 校验，用户填 1500 字保存直接 500 |
| **C5** | 目录表接口数 = 正文接口数 = README 声明数 | README 写 244 个接口、实际 159 个（原数字是 grep 全文唯一 method+path 得来的，把正文提及的路径也算了进去） |
| **C6** | DDL 建表集合 = 契约第 4 节表清单，且文中出现的"N 张"与实际一致 | 契约标题写"36 张"而分前缀枚举实为 38 张；中途还出现过 DDL 只有 37 张的中间态 |
| **C7** | Markdown 健康度：JSON 块可解析、表格列数齐整、代码围栏配平 | 在表格单元格里写公式注入示例 `=cmd\|'/c ...'`，其中的竖线被当成列分隔符，把表格结构撑破 |
| **C8** | 禁用词：陈旧概念、已废弃表名、版本演进措辞、已废除的列名 | 去掉"机构/管理单元"节点类型后仍有 43 处残留——前一轮替换只覆盖了带"节点"后缀的写法，裸写的漏掉了 |
| **C9** | 中文概念 ↔ `node_type`/`user_type` 数值的绑定处处一致（四种句式：概念在前、编号在前、整串枚举、DDL 列注释） | `node_type` 从 `{1机构,2管理员,3教师,4学生}` 收敛为 `{0超管,1管理员,2教师,3学生}` 后，契约停用语义表把**教师写成 1**（与管理员撞号，按字面实现会导致停用一个教师就冻结他名下全部学员）、学生写成 2；DDL 有 3 处 `teacher_node_id` 注释仍写 `node_type=3`（新编号里 3 是学生）；PRD F1-3 整列旧编号；01 分册写着"`node_type` 由 `userType` 推导：1→2、2→3、3→4"而两者本应恒等 |
| **C10** | DDL 列的数据类型与注释语义相符（`BIGINT` 不得配「0否 1是」，`TINYINT` 不得自称时间戳） | `deleted_at` 从 `TINYINT(0/1)` 改为 `BIGINT` 毫秒时间戳后，22 张表的注释仍写「0否 1是」、23 张写了新语义，几乎对半开。按字面注释实现就是写 1，整个改造的收益完全落空 |
| **C11** | 正文「接口 N」指向本分册目录中真实存在的编号，且目录编号连续 | 删掉两个失效接口后 02 分册 48 个接口全部要重编号：正文 80 处「接口 N」交叉引用，外加 30 行错误码登记表用**不带"接口"前缀的裸编号列**记录触发接口——后者极易整块漏掉，且编号错了没有任何症状 |（并校验**跨册引用**：`00-通用约定` 没有接口目录，此前整份文件被 continue 跳过，里面的跨册引用**从未被校验过**——白名单那行指向「03-课程与视频接口 30」，而 30 是心跳上报、29 才是解密密钥。跨册引用一律要求带接口名，否则报 WARN——只校验编号范围抓不到"在范围内但指错"）
| **C12** | 承重论证的锚句必须逐字存在 | 全局替换 `is_deleted`→`deleted_at` 时把论证的**前提**也替换了：「若用 `deleted_at`，同一业务键最多容纳一条已删除行……时间戳方案下可容纳任意多条」——先说本方案有此缺陷、再说本方案解决了它，整段论证自毁。这类"改坏了但读起来通顺"的破坏，只能反过来断言"这句话必须在" |
| **C13** | 凡 `tenant_id` 带 `DEFAULT 0`（可承载平台级行）的表，必须在契约 §2.9 逐表定案 | `sys_role` 与 `sys_role_menu` 的内置角色行 `tenant_id=0`，而租户插件按 `AND tenant_id = ?` 注入 → 租户用户加载 `roles`/`perms` 命中 0 行 → **全员零权限、系统开箱不可用**。这是不报错的故障：接口返回 200、字段齐全，只是数组为空，极易被误判为"角色没配好" |
| **C14** | 每张表的列集合，DDL 与 02-数据库设计的字段表必须完全一致 | 给 DDL 补列时漏改文档字段表（或反之）。C10 只看类型与注释语义，看不出"少了一整列"；而 02-数据库设计正是实现方最常照着建表的文档。本项上线即抓出 3 处历史遗留：`crs_material.owner_node_id`、`stat_node_daily.watch_seconds`、`stat_teacher_daily` 的两列 |
| **C15** | 心跳请求体签名的字段集与字段序，契约 §6.4 / PRD F2-7 / 03-03 参数表三处逐字一致 | 契约称心跳为"最高频接口，签名固定"，正因固定，改动只在实现前便宜——而它已改过两次（补 `seeked` 解拖回复看被误判、补 `sessionId` 解多端并发永久归零）。每改一次要同步三个文件，漏一处直到联调才暴露 |
| **C16** | 心跳校验规则的编号，PRD F2-7 与 03-03 §8.3.1 一一对应；`reject_rule` 注释声明的取值都能在 §8.3.1 找到对应规则 | PRD F2-7 曾把"服务端拒绝规则"与"处理流程"混在一个列表里编号，与 §8.3.1 只有 2/6/7/8 四条碰巧对上。最危险的是 9 号——两边都是拒绝规则、都编号 9，一边"参数越界"一边"多端会话冲突"，处置动作完全相反。而 `vod_heartbeat_log.reject_rule` 已把规则编号**持久化进审计表**（按月分区留存数年），编号不一致会让运维读错历史日志且无法回溯修正 |
| **C17** | JSON 示例内部自洽：同对象内 `userType` 与 `nodeType` 相等、`nodeType=3` 的节点 `childCount=0`、`nodeType>=4` 一律报错 | `node_type` 重编号后，01 分册四处教师示例（`userType=2`）仍写 `nodeType=3`，02 分册示例树把管理员写成 2、教师写成 3、学生写成 4，且一个 `nodeType=3` 的节点带着 `childCount=32`（学生有 32 个子节点，是棵非法树）。**示例是实现方交叉验证时最信任的证据**——十余处互相印证的旧编号会让人越看越确信旧编号才对 |
| **C18** | 正文里写出的每个 `METHOD /api/v1/...` 都必须在某分册的接口目录中存在；比对按**逐段对齐**，目录侧是 `{xxx}` 则该段任意匹配 | `references/README.md:46` 曾在同一行里写着一个**已删除的端点**（`POST /api/v1/vod/callback/{provider}`，转码事件早已改为 XXL-Job 拉取 SMQ）和一个**少了 `/videos` 段的错路径**（`/vod/upload-token`）。两个都是人眼发现的——C5 只数接口总量、C11 只校验"接口 25"这类编号引用，**路径此前没有任何一条规则在看**。这是第一条跨"文档 ↔ 接口清单"的存在性检查 |

## 误报校准

检查器一旦开始喊狼来了就会被忽略，所以每项都做过收敛：

- **C3** 要求同行出现「返回 / 错误码 / code / 拒绝 / 失败」等语境词，避免把 `43500`
  这类算术示例、字节数、毫秒数误判为错误码
- **C4** 同名列可能分布在多张表（`description` 在 `crs_course` 是 2000、在
  `org_perm_template` 是 500），取**最宽者**比对，只有比所有候选都宽才算冲突
- **C2** 跳过 `status` / `biz_type` 这类天然按表而异的通用列名（媒资状态 ≠ 作业状态）
- **C18** 目录里是路径模板（`/org/nodes/{id}`）、正文示例里是具体值
  （`/org/nodes/1960000000000000010`）。整串集合比对会把 **87 条合法请求示例**判成死端点，
  第一次跑就喊 88 次狼来了，接着必然被人加一条"跳过整个 API 目录"的豁免，规则当场作废。
  改为逐段对齐后，雪花 ID 与 `tenant-configs/{configKey}` 这类字面量参数值一并消掉，
  **零豁免、零启发式，88 → 1**（那 1 条是 §7.2 说明改造理由时必须点名的已删除端点）。
  段数参与匹配是这条规则的牙齿：漏写 `/videos` 段会改变段数，直接落选

当前基线：**0 错误，0 警告**。

C8 的禁用词表里，个别位置需要"点名旧方案以说明为什么不用它"（契约 §2.2 论证 `is_deleted`
的缺陷、02-数据库设计 §7 的方案对照表），这些按**词 + 上下文**成对豁免，而不是整行放行。

C8 除了"当年那次缺陷的原文"（`org_class`、`DataScope 三档`），还登记了**已废弃概念的裸词**
（`DataScope` / `data_scope` / `班级`）。起因是 `references/README.md:13` 的
「数据权限（DataScope），对应"教师仅看自己班级"」在禁用词表下活了很久——表里登记的是表名
残留和那句话的原文，换个写法就穿过去了。裸词的代价是全库 13 行否定式表述（"不设 DataScope
分档"、"`sys_role` 无 `data_scope` 字段"，仅 `01-认证与系统.md` 就占 7 行）要豁免，逐条写
13 条且任一处改字就失效；改判上下文：**紧邻在前（10 字符内）的否定词**放行。否定式一次全过，
而新写的肯定式"支持 DataScope 分档"会被立刻抓到。

扫描范围里有 `references/README.md`（那两处残留正是因它长期在范围外才活下来的），但**故意不含
本文件**：上面这几段为了说清规则在防什么，逐字引用了大量废弃写法——本文件被扫等于让 C8/C9 报
一片纯误报，而那些引用正是本文件的内容本身。范围定义处（`check_consistency.py` 的 `MD_FILES`）
有同样一行注释，改的人两边都能看到。

C9 只认完整概念词，不做后缀匹配——"某位导师的**名下学员**（`node_type = 2`）"里的
注解属于导师而非学员，后缀匹配会误判成"学员写成了 2"。这类归属歧义机械上无法消解，
宁可漏一条也不制造假警报。

## 自检

改完脚本后可以注入已知缺陷验证它真的有效：

```bash
# 例：删掉某个列定义的行尾逗号、把索引改成引用不存在的列、
#     把某个 API 字段长度改成大于 DDL —— 三项应分别被 C1/C1/C4 抓到
python3 scripts/check_consistency.py
```

C9~C12 是在一轮节点类型重编号的回归复盘后补的。补完后把那一轮真实发生过的
8 条回归逐条注入副本验证，确认全部命中：

| 注入的回归 | 命中 |
| --- | --- |
| 契约停用语义表把教师写成 `node_type=1` | C9 |
| 正文引用了已删除的接口编号 | C11 |
| 契约 §4 表清单退回旧枚举 `1机构 2管理员 3教师 4学生` | C9 |
| DDL `teacher_node_id` 注释写 `node_type=3` | C9 |
| PRD 残留"管理单元"节点 | C8 |
