# 文档一致性检查

```bash
python3 scripts/check_consistency.py            # 全量
python3 scripts/check_consistency.py --only C1  # 只跑某一项
```

无依赖，纯标准库。退出码：有 ERROR 返回 1，否则 0（适合挂 CI / pre-commit）。

## 为什么需要它

这套文档 1.7 万行、分布在 11 个文件里，同一件事往往在契约 / PRD / DDL / API 分册各写一遍。
实际发生过的缺陷里，**至少一半属于"改了上游没传导到下游"或"看起来改对了但没验证"**——
人肉交叉核对既慢又不可靠，而这类错误恰恰是机械检查最擅长的。

下面每一项都对应一个**真实发生过**的缺陷，不是假想的规范。

## 一条反复出现的失败模式：同类缺陷的第 N 处

`node_type` 重编号这一类缺陷，**第 3 处比第 1 处难找得多**——不是因为它更隐蔽，而是因为前两处修完会产生"这类问题已经处理过了"的结案感，人工排查恰在此时最松懈。实际发生的序列：

| 轮次 | 形态 | 结果 |
| --- | --- | --- |
| 第 1 轮 | 「教师（`node_type=1`）」概念在前 | 修掉，补了 C9 |
| 第 2 轮 | 「由 `userType` 推导：1→2 管理员、2→3 教师…」带概念词的枚举串 | 修掉两行（400、554），**收工** |
| 第 3 轮 | 「决定新建节点的 `node_type`：1→2、2→3、3→4」**不含概念词的纯箭头映射** | 外部评审指出。它是**规范性参数说明而非示例**，按它实现导师永远分配不到学员 |
| 第 4 轮 | JSON 示例里 `userType=2` 配 `nodeType=3` | 同上，另有一棵"学生节点有 32 个子节点"的非法示例树 |

**教训：每补一条检查项，要同时问"这一类还有没有第 N 种形态"。** 箭头映射是第三种，JSON 示例是第四种——两者都不在最初 C9 覆盖的四种句式里。检查项的价值不在评审时报了多少错，而在改文档时拦住了多少次（本轮 C16 与 C14 就各拦下一次漏改）。

### 同一物种的第 5 轮：扫描范围 ≠ 覆盖

前四轮问的都是"这类缺陷还有没有别的形态"。第 5 轮换了个方向——**规则没漏，是规则没看见文件**：

`a64490a` 把 `docs/04-一期实施计划.md` 加进 `MD_FILES`，检查器报 **0 错 0 警**。逐条验证后，三条本该管住这份文档的规则里只有一条真的在看它：

| 规则 | 加进 `MD_FILES` 后的真实状态 | 成因 |
| --- | --- | --- |
| C18 | **真通过**，捕获 23 处端点引用并逐条比对目录 | 它本来就遍历 `MD_FILES` |
| C11 | **命中 0**：13 处跨册引用一处没看到 | `_XREF` 只认中文册名（`02-组织机构`），而该文档全篇用数字册号（`03-02 接口 37`） |
| C3 | **命中 0**：全文错误码一个没校验 | 它遍历的是 `API_FILES + [PRD]`，**根本不读 `MD_FILES`**，加不加进去都一样 |

**教训：把文件加进扫描列表之后，必须逐条验证每条规则是否真的触达了它——绿灯本身不是证据。**
验证方法不需要读代码：故意在新文件里注入一个必错的值（错误的接口编号、未登记的错误码、
不存在的端点路径），跑一次，看该规则是否报出来。报不出来就说明这条规则对这份文件是失效的，
而**失效的规则和通过的规则在输出里长得一模一样**——这正是它比前四轮更难发现的原因：
前四轮至少还有一处错误摆在文档里等人看见，这一轮连错误都不会被显示出来。

## 误报校准

检查器一旦开始喊狼来了就会被忽略，所以每项都做过收敛：

- **C3** 要求同行出现「返回 / 错误码 / code / 拒绝 / 失败」等语境词，避免把 `43500`
  这类算术示例、字节数、毫秒数误判为错误码
- **C4** 同名列可能分布在多张表（`description` 在 `crs_course` 是 2000、在
  `org_perm_template` 是 500），取**最宽者**比对，只有比所有候选都宽才算冲突
- **C2** 跳过 `status` / `biz_type` 这类天然按表而异的通用列名（媒资状态 ≠ 作业状态）
- **C18** 目录里是路径模板（`/org/nodes/{id}`）、正文示例里是具体值
  （`/org/nodes/1960000000000000010`）。整串集合比对会把 **87 条合法请求示例**判成死端点，
  第一次跑就喊 88 次狼来了，接着必然被人加一条"跳过整个 API 目录"的豁免，规则当场作废。
  改为逐段对齐后，雪花 ID 与 `tenant-configs/{configKey}` 这类字面量参数值一并消掉，
  **零豁免、零启发式，88 → 1**（那 1 条是 §7.2 说明改造理由时必须点名的已删除端点）。
  段数参与匹配是这条规则的牙齿：漏写 `/videos` 段会改变段数，直接落选。
  这条收敛换来一类有意的漏报，见「已知漏报」

当前基线：**0 错误，0 警告**。

C8 的禁用词表里，个别位置需要"点名旧方案以说明为什么不用它"（契约 §2.2 论证 `is_deleted`
的缺陷、02-数据库设计 §7 的方案对照表），这些按**词 + 上下文**成对豁免，而不是整行放行。

C8 除了"当年那次缺陷的原文"（`org_class`、`DataScope 三档`），还登记了**已废弃概念的裸词**
（`DataScope` / `data_scope` / `班级`）。起因是 `references/README.md:13` 的
「数据权限（DataScope），对应"教师仅看自己班级"」在禁用词表下活了很久——表里登记的是表名
残留和那句话的原文，换个写法就穿过去了。裸词的代价是全库 13 行否定式表述（"不设 DataScope
分档"、"`sys_role` 无 `data_scope` 字段"，仅 `01-认证与系统.md` 就占 7 行）要豁免，逐条写
13 条且任一处改字就失效；改判上下文：**紧邻在前（10 字符内）的否定词**放行。否定式一次全过，
而新写的肯定式"支持 DataScope 分档"会被立刻抓到。

扫描范围里有 `references/README.md`（那两处残留正是因它长期在范围外才活下来的），但**故意不含
本文件**：上面这几段为了说清规则在防什么，逐字引用了大量废弃写法——本文件被扫等于让 C8/C9 报
一片纯误报，而那些引用正是本文件的内容本身。范围定义处（`check_consistency.py` 的 `MD_FILES`）
有同样一行注释，改的人两边都能看到。

## 已知漏报（有意为之，不要"修"）

下面这些是**权衡后选择放过**的，不是 bug。写下来是因为它们看起来像 bug——下一个人
发现后很容易顺手加一条启发式把误报引回来，那笔账是亏的。

**C18：固定段打错、且错值恰好落在另一条同段数登记路径的 `{占位符}` 位置时不报。**

```
GET /api/v1/org/nodes/treee   ← 打错，但被 GET /api/v1/org/nodes/{id} 接住，静默通过
```

要抓它，必须判断"`treee` 这个值像不像一个 ID"——那是启发式（几位数字算 ID？带字母
算不算？`complete_rate_threshold` 这种字面量参数值怎么办？），而 C18 之所以能做到
零豁免、零误报，正是靠删掉了这类判断。引回来拦下的漏报远少于制造的误报。

暴露面是可以算清的，不是"应该很少"：全部 **159 条登记端点里只有 2 条**存在这个风险，
即固定段被同段数模板的占位符位置遮住——

| 端点 | 打错后被谁接住 |
| --- | --- |
| `GET /api/v1/org/nodes/tree` | `GET /api/v1/org/nodes/{id}` |
| `DELETE /api/v1/org/students/tags` | `DELETE /api/v1/org/students/{id}` |

且这两条的固定段（`tree` / `tags`）都是正文里高频出现的词，人眼容易发现。相比之下，
段数不同的错（漏写 `/videos` 段）与完全不存在的路径（已删除的端点）——也就是实际
发生过的那两类——C18 一条都不漏。

**C3：错误码必须与语境词同行、且写法要"像错误码"，两道门都过不了的引用不校验。**

C3 分两道门：① 同行须出现「返回 / 错误码 / 拒绝 / 失败 / code / → / 不可 / 不允许」之一；
② 该码本身要写成 `` `10107` `` / 「返回 10107」/ 表格首列 / 括号内码列表之一。两道门都是为
**六个 API 分册的行文习惯**调的，换一种文档体裁就会大面积失效。

实测 `docs/04-一期实施计划.md`（计划文档，错误码多写在表格单元格的职责描述里）：

| 口径 | 数值 |
| --- | --- |
| 全文引用的**已登记**错误码（去重） | 29 个 |
| C3 实际校验到的 | 18 个（**62%**） |
| 漏掉 | 11 个：`10008` `10009` `10012` `10107` `10203` `10205` `20001` `20003` `20008` `40002` `40008` |

漏掉的 11 个里，**只有 1 个**（`20001`）是栽在第 ① 道门（整行无语境词）；**9 个**栽在第 ② 道门——
行内有语境词，但码写成了**不带括号的斜杠枚举**，例如：

```
…改菜单绑定一律拒绝（契约 §2.9 末段）；10008 / 10009 / 10012 可复现
…置可见失败返回 **20008**（20003 仅用于上架与发凭证）
```

第 ② 道门的括号列表分支（`（10010 / 10207）`）本就是为这类形态加的，但只覆盖了带括号的写法。
最后 1 个是 `40002`，栽在「预留 / 号段」跳过规则上——那一行在讨论号段划分，跳过是对的。

**为什么不放宽**：第 ① 道门放宽会让六个分册里的数量、毫秒数、字节数被整片误判成错误码，
那个过滤器就是为此调的；第 ② 道门放宽（把裸斜杠枚举也纳入）虽然不会制造那类噪声，
但会把「`node_type` 1/2/3」「10s 心跳、20001/20002」这类混排数字拖进来，**需要先验证误报面才能动**。
在验证之前，**宁可漏这一类**，并把它记在这里——而不是让下一个人从"0 错 0 警"里推断计划文档已被校验过。

> 复现方式：去重口径 = 文中独立成 token 的五位数 ∩ 登记册；校验口径 = 跑一遍 C3 的两道门。
> 这两个数会随文档改动而变，**结论（第 ② 道门是主要漏点，不是第 ① 道）比数值更重要。**

同一物种的还有 **C9 只认完整概念词、不做后缀匹配**（见「误报校准」末段）：
"某位导师的**名下学员**（`node_type = 2`）"里的注解属于导师而非学员，后缀匹配会
误判成"学员写成了 2"。这类归属歧义机械上无法消解，同样宁可漏一条。

## 下限断言：让检查器能声明"我现在看不见了"

"先解析出一个集合、再拿它比对"的检查有一个共同的静默失效模式：**上游格式一改，
集合解析成空，比对无事可做，结果全绿**——它没报错，但它也没在看，而这两件事在
输出里长得一模一样。这类失效比漏报更危险：漏报只是少抓一条，静默失效是整条规则
下线且伪装成健康。

因此凡走"解析集合 → 比对"的检查都带一条下限断言：

| 项 | 断言 | 失效场景 |
| --- | --- | --- |
| **C11** | 02 / 03 / 04 三册必须解析出整数编号目录 | 目录表编号列或方法列格式漂移，`volume_tocs` 缺册后跨册引用走 `continue` 静默放行 |
| **C14** | 解析出的字段表小节数 ≥ DDL 表数的 80% | 小节标题层级或字段表格式一改，本项只剩一片 WARN（不影响退出码），看起来像"文档没写全"而不是"检查器瞎了" |
| **C18** | 目录路径数 ≥ 100 | 目录表格式一改，正则匹配到 0 条，C18 静默全绿 |

两条踩过的坑，写在这里免得重犯：

- **期望值不能从被守护的解析器反推。** C11 的断言最初写成"凡 `_TOC_ROW` 能匹配到
  行的分册都必须解析成功"——格式一坏，期望集合与实际集合同时归零，断言恒真。改为
  写死分册名（这是关于当前文档集的事实，新增分册时加一行）。
- **也不该拍一个数字当下限。** C11 曾写"应为 5 册"，但 01 与 05 用的是小节式编号
  （`| 1.1 |`、`| 4.1 |`），`_XREF` 的「接口 N」形态本就不适用，全库指向这两册的
  此类引用为 0——写死 5 会变成一条永久误报。

C6 不需要这条：它做的是**对称差**（契约列出但 DDL 没建 / DDL 建了但契约没列），
表清单解析成空时会立刻报出 41 条"DDL 建了但契约表清单未列"，不可能静默。

C9 只认完整概念词，不做后缀匹配——"某位导师的**名下学员**（`node_type = 2`）"里的
注解属于导师而非学员，后缀匹配会误判成"学员写成了 2"。这类归属歧义机械上无法消解，
宁可漏一条也不制造假警报。

## 自检

改完脚本后可以注入已知缺陷验证它真的有效：

```bash
# 例：删掉某个列定义的行尾逗号、把索引改成引用不存在的列、
#     把某个 API 字段长度改成大于 DDL —— 三项应分别被 C1/C1/C4 抓到
python3 scripts/check_consistency.py
```

C9~C12 是在一轮节点类型重编号的回归复盘后补的。补完后把那一轮真实发生过的
8 条回归逐条注入副本验证，确认全部命中：

| 注入的回归 | 命中 |
| --- | --- |
| 契约停用语义表把教师写成 `node_type=1` | C9 |
| 正文引用了已删除的接口编号 | C11 |
| 契约 §4 表清单退回旧枚举 `1机构 2管理员 3教师 4学生` | C9 |
| DDL `teacher_node_id` 注释写 `node_type=3` | C9 |
| PRD 残留"管理单元"节点 | C8 |

| `deleted_at` 注释退回「0否 1是」 | C10 |
| 移动节点的反面写法警示被删掉 | C12 |
| 契约 §2.9 漏登记一张有平台级行的表 | C13 |
